## 0. なぜ「共通」の文書が必要なのか（最重要）

**後継2EXP（EXP-OBS000005 / EXP-OBS000006）は、同一の選定/確認分割を使わなければならない。** 理由は次の算術的帰結である。

- EXP-OBS000006（ギャップ）は §6.2 G1-2 / G1-6 で**選定期間のリターン**を観測する（符号一致の確認）。
- したがって、もし EXP-OBS000006 の選定期間が EXP-OBS000005 の確認期間と重なっていれば、**EXP-OBS000006 を実行した時点で EXP-OBS000005 の確認期間は「未見」ではなくなる。**
- 逆も同様である。

> **⇒ 分割が一致していない2EXPを同一カレンダー上で走らせることは、どちらを先に実行しても他方の選定/確認分離を破壊する。** これは本PJが trading-app-v2 の8連敗から輸入した偽陽性対策の中核（PJ000002 §6）に対する直接の違反である。

**したがって本書は分割を1つに固定し、両 spec が参照により取り込む。** 加えて、両 spec を**同時に凍結**することで、どちらを先に実行しても他方の事前登録性が保たれる構造にする（§9 CX-1）。

## 2. 参照営業日カレンダー `T`（本書および両 spec 全体で唯一の正本）

- `T` := **契約範囲内で `/equities/bars/daily` に1件以上の行が存在する日付**を昇順に並べた列。**1始まりの添字**を用いる。
- これは `research/EXP-OBS000001/01-spec.md` §2.1.0 および `research/EXP-OBS000003/01-spec.md` §2.0 の定義と**同一の考え方**である（「候補全銘柄の観測日付の和集合」）。ただし本書では候補銘柄集合を**全上場銘柄**とする（§5 U-8 の生存バイアス対策のため）。
- **`T` は日付のリストであり、価格を一切参照しない。**
- 営業日の定義: **日足データにその銘柄の行が存在する日**。売買停止で行が存在しない日は、その銘柄については営業日として数えない（件数を記録）。

### 3.2 なぜ `2020-01-01` なのか（**判断根拠。リターンも `z` 分布もイベント件数の期間別比較も使っていない**）

4つの理由がすべて同じ境界を指す。

**(a) 検出力からの逆算（主たる理由。カウントのみを入力とする）**

- EXP-OBS000005（PEAD）の主検定 `IC_bar` の検出下限（MDE）は `1.645 × SD(IC_d) / √K` であり、`K` は「1日5件以上のイベントを持つ開示日の数」である。
- 凍結 spec の実測（`research/EXP-OBS000001/10-result/feasibility.json`、確認期間 2025-07-01〜2026-06-21 の231営業日）は **`K` = 27日／年**であった。
- EXP-OBS000005 §6 が要求する MDE ≤ 0.055 を満たすには `K ≳ 170〜190日` が必要（導出は同 spec §6.1）。⇒ **確認期間に約6.5〜7.0年が必要。**
- 10年の契約範囲から逆算すると、確認期間の開始は **2020年初頭**になる。2020-01-01 はその要求を満たす最も自然な暦上の境界である。
- **この逆算に使ったのは「27日/年」というカウントのみであり、リターンは1つも使っていない。** 27日/年は凍結 spec の DS-2 実測値であり、司令塔判断 D-9（データ拡張）の根拠そのものである。**すなわち本分割は、D-9 の決裁内容を数値に落としたものである。**

**(b) 株式決済サイクルの境界（配当落ち識別の単一規則化）**

- 日本株の株式決済は **2019-07-16 に T+3 → T+2 へ移行**した。配当落ち日の構成手続き（EXP-OBS000006 §3.1.1）は決済サイクルに依存する（§6 H10-1）。
- 確認期間を 2020-01 以降に置くことで、**合否判定に用いる期間の配当落ち識別が T+2 の単一規則で完結する。** T+3 期（2016-09〜2019-07）は選定期間（参照測定と `z*` 較正のみ）に収まる。

**(c) コスト前提の時代整合**

- 消費税率変更（2019-10-01・8%→10%）および委託手数料の自由化・無料化の進行により、**2019年以前の実効取引コストは本PJが仮置きしている往復 0.35%／0.45% より高い**と考えられる（§6 H10-4）。
- コストを全期間一定とする本設計は 2019年以前について**楽観側に偏る**が、その偏りは**選定期間（合否に使わない）に限局する**。

**(d) 自由度が構造的に存在しない**

- 境界は「2020-01-01 以降の最初の営業日」という**暦上の規則**である。複数の候補日を試して良い結果のものを採る、という余地が存在しない。
- 選定期間・確認期間のいずれについても、**前方リターン・`z` の分布・期間別のイベント発生率の比較を、境界の決定に一切使っていない。**

> **この開示が重要な理由**: 「カウントは見たがリターンは見ていない」という状態は、HARKing の観点では**成功基準を歪めない**。成功基準（G1・G2）はリターンの関数であり、カウントからは推定できない。一方でデータ十分性ゲート（DS）はカウントの関数であるため、**カウントを見てから DS を設計することは原理的に可能である。** そこで本書と両 spec は次の2つの規律を課す。
> 1. **DS 閾値は、緩める方向には一切動かさない。** 旧 spec より緩い DS 閾値を1つも置かない（§7 の対応表で全件検証可能にする）。
> 2. **DS 閾値は、検出力または経済的必要水準からの導出として書く。** 「実測がこの値だったから閾値をここに置く」という形の閾値を置かない。

## 5. ユニバース定義（**両EXPで共通。10年化にともなう改訂を含む**）

### 5.1 確定日（**年次再確定。10年化で新設**）

| 項目 | 定義 |
|---|---|
| **確定日集合 `U_dates`** | `{ T[61] }` ∪ `{ 各暦年 y の最初の営業日 : y ∈ [2017, T[|T|] の年] }`。ただし `T[61]` より前の日付は含めない |
| **適用規則** | イベント日 `D` に用いるユニバースは、`max{ d ∈ U_dates : d ≤ D }` で確定したものとする |
| 推定される確定日数 | **11点**（2016-12-15 近傍、2017-01-04 〜 2026-01-05 の各年初。**推定であり、B が `T` から機械的に求めて出力する**） |

> **なぜ年次再確定にしたか（凍結 spec からの意図的な改訂）**: 凍結 spec は検証期間が約1年であったため「期間の先頭で1回だけ確定し期中は固定」で足りた。**確認期間が約6.7年になると、1回確定のままでは (a) 上場廃止・規模区分変更を反映できず、(b) U-5 の株価帯（1,000〜3,500円）が年を追って無意味化する**（日本株の株価水準は 2016年と2026年で大きく異なる）。
> **この改訂は成功基準（G1・G2・DS）を1つも緩めない。** 確定手続き U-1〜U-7 は凍結 spec と一字一句同一であり、変わったのは「確定を何回行うか」だけである。かつ各確定は**確定日より厳密に過去の情報のみ**を使うため、先読みを一切導入しない。

### 5.2 確定手続き（**U-1〜U-7 は `research/EXP-OBS000001/01-spec.md` §5.4 をそのまま流用。U-8・U-9 は10年化で新設**）

| 手順 | 条件 | 使用フィールド |
|---|---|---|
| **U-1** | **規模区分が TOPIX500 相当**であること。すなわち `ScaleCat ∈ { "TOPIX Core30", "TOPIX Large70", "TOPIX Mid400" }` | `/equities/master?date=<確定日>` の `ScaleCat`（**実測で確定済みの値。`research/EXP-OBS000001/10-result/params.json` の `field_value_mapping_9_1`**） |
| **U-2** | **制度信用で買建て可能**であること。`Mrgn ∈ { "1"（信用）, "2"（貸借） }`。`"3"（その他）` を除外 | 同 `Mrgn` / `MrgnNm` |

### 6.1 配当落ち日の構成における決済サイクル分岐（H10-1 の具体化。EXP-OBS000006 §3.1.1 step 3 を置き換える）

`k := idx(b(R))`（`b(R)` は基準日 `R` 以下である `T` 上の最大の営業日）とする。**権利落ち日 `X` の集合を次のとおり決定する。**

```
if  date(b(R)) >= 2019-07-22 :   X = { T[k-1] }              # T+2 期（権利付最終日 = T[k-2]）
elif date(b(R)) <= 2019-07-12 :  X = { T[k-2] }              # T+3 期（権利付最終日 = T[k-3]）
else                          :  X = { T[k-1], T[k-2] }      # 移行帯（2019-07-16〜2019-07-19）: 両方を除外する
```

- **T+2 の算術**: 基準日 `R` に株主名簿に載るには受渡が `b(R)` までに完了する必要がある。`T+2` では約定日 `d` の受渡が `d` の2営業日後であるから `idx(d) + 2 ≤ k`、すなわち権利付最終日 `= T[k−2]`、その翌営業日である **`T[k−1]` が権利落ち日**である。
- **T+3 の算術**: 同様に `idx(d) + 3 ≤ k` より権利付最終日 `= T[k−3]`、**`T[k−2]` が権利落ち日**である。
- **移行帯（`b(R)` が 2019-07-16〜2019-07-19 にある場合）**: 権利付最終日となりうる約定日が移行の前後に跨るため、権利落ち日が一意に定まらない。**両方の候補日を除外する**（除外は保守側＝イベント集合を減らす方向であり、通す方向ではない）。該当する `(銘柄, 基準日)` の件数を記録する。移行帯に該当する暦日は10年間で4日以下である。
- **E-2B（暦ベース・一括除外）も同じ分岐に従う**: 各暦月 `m` の `T` 内での最終営業日を `L(m)`、`k_m := idx(L(m))` として、
  ```
  X(m) = { T[k_m - 1] }                 if date(L(m)) >= 2019-07-22
       = { T[k_m - 2] }                 if date(L(m)) <= 2019-07-12
       = { T[k_m - 1], T[k_m - 2] }     otherwise
  ```
- **本分岐は EXP-OBS000006 のみに適用される**（EXP-OBS000005 は配当落ちをシグナルに使わず、リターンは調整系列で計算するため配当落ちの段差を分離する必要がない）。ただし EXP-OBS000005 も `AdjFactor` が配当を調整しないことを前提に、**配当落ち日を跨ぐ保有が損益にどれだけ寄与したかを記述統計として出力する**（合否判定には使わない）。

## 7. データ十分性ゲート（DS）の共通原則と、旧 spec 閾値との対応

### 7.1 共通原則（**両EXPに適用**）

1. **DS ゲートはカウント・銘柄数・日数・欠損率のみを入力とし、リターンを一切参照せずに評価する。**
2. **DS ゲート未達のまま G1 以降を実行することを禁止する**（不可逆性。確認期間のリターンを一度でも見たら、その窓は永久に「未見」ではなくなる）。
3. **旧 spec より緩い閾値を1つも置かない。** 対応は §7.2 の表で全件検証できるようにする。
4. **閾値は「検出力」または「経済的必要水準」からの導出として書く。** 「実測がこの値だったから」という形の閾値を置かない。
5. MDE の式に入る**リターンの標準偏差は事前に固定した定数のみを使う**（`σ_R(5営業日) = 4.0%`）。実測の標準偏差は使わない（使えばリターンを見ることになる）。

## 9. 両EXPの同時凍結と交差汚染の防止（**本書で最も重要な規律**）

| # | 規律 | 内容 |
|---|---|---|
| **CX-1** | **両 spec を同時に凍結する** | `research/EXP-OBS000005/01-spec.md` と `research/EXP-OBS000006/01-spec.md` は**同一日（2026-09-15）に、確認期間の前方リターンが1件も観測されていない状態で**凍結された。したがって**どちらを先に実行しても、他方の事前登録性（回す前に基準が固定されていたこと）は保たれる** |
| **CX-2** | **凍結後の spec 変更は、リターンを直接見ていなくても K-4（HARKing）とみなす** | 一方の EXP が確認期間のリターンを1件でも観測した後は、**他方の spec の変更も禁止する**。同一カレンダーのリターンが観測された後の変更は、動機の純粋さにかかわらず「結果を見てから設計を変えた」ことと外形上区別できない |
| **CX-3** | **本書（10Y-COMMON）の変更は両EXPの再起票を要する** | 分割・ユニバース・カレンダー算術の変更は、両 spec の前提を同時に動かす。**変更が必要と判断した場合は本書を改訂せず、新規EXP番号で両方を再起票する。**<br>**【2026-09-15 追記・唯一の例外とその根拠】** 司令塔判断 **D-16**（U-6 の上限）の決裁にともなう §5.2 U-6 の改訂は、この規律の例外として実施した。**例外として許される理由は3点あり、すべて満たす場合に限る**: ① **D-16 は §10 に「決裁が出れば、リターン未観測のうちに限り spec 第2版として改訂してよい」と事前登録されていた**（事前登録された例外の行使であって、新しい裁量の行使ではない）／② **改訂時点で両EXPとも確認期間の前方リターンを1件も観測していない**（B実装チームは未起動）／③ **改訂を `U6_cap` のパラメータ化として行い、EXP-OBS000006 の数値を1つも変えていない**（同EXPの `U6_cap` は 175 のまま）。<br>**この3条件を満たさない変更は、今後も本書の改訂ではなく両EXPの再起票による。** |
| **CX-4** | **データ十分性ゲートの評価順序** | 両EXPの DS ゲートは**どちらもリターンを参照しない**ため、**両方の DS ゲートを先に評価してよい**（推奨: 先に両方の DS を評価し、どちらが G1 に進めるかを確定させてから G1 に着手する）。**G1 に進むのは DS 全合格の EXP のみである** |
| **CX-5** | **旧 EXP（OBS000001 / OBS000003）の確認期間は本EXP群の実行により未見性を失う** | 旧2EXPの確認期間（2025-07-01〜2026-06-21 ／ 2025-07-01〜2026-06-12）は、本書の確認期間（2020-01〜2026-09）に**完全に含まれる**。したがって本EXP群の G1 を実行した時点で、**旧2EXPは再開不能になる**。S はこれを「凍結」から「**終結（判定不能・後継EXPに置換）**」へ移すことを司令塔に具申する（§10 D-19）。**この置換は損失ではない**——旧2EXPは DS ゲートで停止しており、そのままでは永久に判定できなかった |

## 10. 司令塔判断を要する事項（本書で新たに生じたもの）

| # | 事項 | S の立場 |
|---|---|---|
| **D-16**<br>**✅ 決裁済み（2026-09-15・GO）**<br>**→ EXP-OBS000005 spec 第2版へ反映済み** | **EXP-OBS000005（PEAD）の U-6（175銘柄上限）を、U-1〜U-5 通過の全数（実測271銘柄相当）へ引き上げるか。** 引き上げると1開示日あたりのイベント数 `n_d` が約1.55倍になり、`SD(IC_d) ≈ 1/√(n_d−1)` 経由で **MDE が約 0.78倍（0.049 → 0.038）に改善**する。これは「現実的な単一会計ファクターの IC 帯（0.02〜0.05）」の中心に初めて届く水準である。<br>**ただし 175 は司令塔判断2（ユニバースは TOPIX500 から150〜200銘柄）の実装であり、引き上げは司令塔判断の変更にあたる。** | **S は 175 を凍結した**（司令塔判断を一存で動かさないため、かつ凍結 spec との比較可能性を最大化するため）。**引き上げを望む場合は、B が G1 を実行する前に決裁が必要**（実行後は確認期間の未見性が失われ、変更が K-4 になる）。**決裁が出れば、リターン未観測のうちに限り spec 第2版として改訂してよい**<br>**【2026-09-15・決裁と反映の記録】司令塔が GO を決裁。** 第1版 N-12 が事前登録していた2条件（①決裁が出ていること ②確認期間の前方リターンが未観測であること）を**両方とも満たした状態**で、S が `research/EXP-OBS000005/01-spec.md` を**第2版**へ改訂・凍結した（`U6_cap` = **271**）。<br>**反映にあたり、合否閾値は1つも緩めていない**（`G1-1`〜`G1-6`・`G2-1`〜`G2-6`・`DS-1`〜`DS-7` は第1版と同一。**特に DS-2b の 0.055 は据え置いた**——この閾値は `IC_econ` から導かれておりユニバース銘柄数に依存しないため、期待 MDE の改善は閾値を動かす根拠にならない）。<br>**むしろ2つのゲートを追加して厳格化した**: **G1-7**（`Va` 上位175銘柄に限定しても `IC_bar` の符号と上位デシルのグロス平均が正であること）・**G2-7**（往復コスト0.50%でも損益分岐を割らないこと）。**理由は、拡大が追加するのが `Va` 順位176〜271位＝相対的に低流動性の帯であり、一定コスト仮定が第1版より楽観側に偏るためである。**<br>**期待 MDE: 0.042〜0.049 → 0.033〜0.042。**<br>**EXP-OBS000006 は対象外**（`U6_cap` = 175 のまま）。ギャップEXPで同様の拡大を行うかは別途の司令塔判断を要する（同EXPは `z*` 較正という自由度を持つため、母集団の変更が較正を通じて合否に波及する。**S は現時点で拡大を推奨しない**）。 |
| **D-17** | **G2-4（最大DD ≤ 15.0%）をコロナ・ショックを含む6.7年の確認期間に同一閾値で適用してよいか。** 15.0% は PJ000001 §8.1 の運用停止水準そのものであり、期間長に依存しないリスク方針である。到達すれば §6.8 K-3 により**不採用**となる。 | **S は閾値を動かさない。** リスク方針の数値を検証の都合で緩めることはしない。ただし「コロナ期に運用停止水準へ到達したことをもって不採用とする」のがリスク方針の解釈として妥当かは S の職掌を超えるため、**了解を求める**。**了解が得られない場合も、S は spec を変更せず、C品質チームの判定文に事情を明記させる** |
