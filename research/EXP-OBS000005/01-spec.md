## 1. 仮説（1文）

**決算短信の開示によって更新される「会社自身の通期経常利益見通し」の変化量（＝会計サプライズ SUE）は、開示翌営業日始値から起算した5営業日の株価リターンを、日本株 TOPIX500 相当ユニバースにおいて、往復コスト0.35%控除後も正の期待値が残る程度に予測する。**

### 1.1 エッジ族の宣言

- 予測変数の生成過程: **会計データのみ**（会社予想・実績の経常利益と予想売上高）。価格・出来高・ボラティリティを**一切入力にしない**。
- したがって PJ000001 §4 C-3 が低事前確率とした「価格由来の特徴量から方向を予測する」族には属さない。
- **ただし出力形（イベント後の一方向継続を取る）は TSMOM と同型である。この区別が本質的でなかった場合、本 EXP も同じ天井に当たる。この可能性は spec 段階で排除できない。G1 の結果で判定する。**

### 1.2 事前確率の見立て

**中。ただし根拠は弱い。** 日本株 PEAD の学術的エビデンスについて、**一次文献は本 spec 作成時点でも直接確認できていない**（EXP-OBS000001 §1.2 と同じ状態）。**本 spec は「日本株 PEAD が文献で確認されている」ことを前提にしない。文献の存在を根拠に基準を緩めることはしない。**

## 2. 選定 / 確認プロトコル

### 2.0 参照営業日カレンダー `T`（本 spec 全体で唯一の正本）

- **`T` := ユニバース候補全銘柄の `/equities/bars/daily` の観測日付の和集合を、契約範囲 `[2016-09-15, 2026-09-14]` で切り取り、昇順に並べた列。1始まりの添字。**
- **`T` は日付のリストであり、価格を一切参照しない。**
- **実測値（`00-prescreen.md` §B-1）**: `T[1] = 2016-09-15`、`N = |T| = 2,441`、`T[N] = 2026-09-14`、`m = floor(N/2) = 1,220`、`T[m] = 2021-09-15`。
- **B実装チームは §9-1 の候補集合再構成後に `T` を再構成し、上記と一致することを確認する。一致しない場合は実験を回さず S に差し戻す**（N-3 / N-6）。**上表に合わせて実日付をハードコードしてはならない。**

#### 2.0.1 契約範囲のピン留め（**第2版で追加。訂正であって基準の変更ではない**）

**発見された事実（B実装チームの §9-1 実測）**: `/equities/bars/daily`（`code` 指定のみ・日付範囲パラメータなし）は**固定アーカイブを返さない。クエリ実行日から遡る約10年のローリング窓**を返す。

| 取得時期 | 返された窓 |
|---|---|
| 前セッション取得の旧候補511銘柄 | `2016-09-15` 〜 `2026-09-14` |
| §9-1 で新規追加した90銘柄（本日取得） | `2016-09-16` 〜 `2026-09-15`（**1日前進**） |

**本日 `2016-09-15` を明示指定すると HTTP 400（`Your subscription covers the following dates: 2016-09-16 ~`）＝ 恒久的に取得不能。**

**⇒ 初版 §2.0 の「観測日付の和集合」という定義は、取得日に依存して `N` が変動する（＝再現不能）という欠陥を持っていた。** 実際、切り取りを行わずに554銘柄を統合すると `N = 2,442` / `m = 1,221` / `D_conf = 2021-09-17` となり、事前登録値と1日ずれる。

**採る措置: 範囲 `[2016-09-15, 2026-09-14]` で切り取る（ピン留め）。**

**なぜこれが HARKing（K-4）に当たらないか**:

1. **この範囲は新しく選んだ値ではない。** `00-prescreen.md` §A-1 が、**10年データの件数測定を1回も行っていない時点**（コミット `b5080ee`）で既に「範囲: **2016-09-15 〜 2026-09-14**」と宣言していた。**第2版は、その凍結済みの宣言を `T` の定義側に書き写しただけである。**
2. **分割規則 `m = floor(N/2)` は変更していない。** 変更したのは `T` の定義の曖昧さであり、規則そのものではない。
3. **結果として事前登録値が<u>完全に再現される</u>。** ピン留め後の和集合は **`N = 2,441` / `T[1] = 2016-09-15` / `T[N] = 2026-09-14` / `m = 1,220`** であり、`00-prescreen.md` §B-1 と**1日も違わない**（S が実測して確認済み）。**「ゲートを通すために分割を動かした」という外形が成立しない**——動かしていないからである。
4. **前例との整合**: `research/ACTIVE.md` 0-20 は、EXP-OBS000001 §7 D項のエンドポイント誤りについて「**成功基準の変更ではなく実装指示の事実誤りの訂正**であるため HARKing には当たらない」と既に整理している。本件は同じ類型である。

**採らなかった代替案**:

| 案 | 却下理由 |
|---|---|
| 554銘柄を同一日に**全件再取得**し、新しい `T` を正とする | **致命的。既存キャッシュを上書きすると `2016-09-15` 以前の日が恒久的に失われる**（API から二度と取得できない）。加えて (a) 事前登録した分割点を**運用上の偶然（どの日に実行したか）で動かす**ことになり、「実行日を変えれば分割が変わる」という隠れた自由度を持ち込む。(b) 定義の時間依存性そのものは**まったく解消しない**（次回の再取得でまた1日ずれる） |
| 新規90銘柄を候補集合から外す | §9-1 が解消しようとしているサバイバーシップ・バイアスの是正そのものを無効化する。**本末転倒** |

**残る非対称性と、それが無害である理由（誤魔化さずに記録する）**:

- 新規取得90銘柄（うち89銘柄が該当）は `T[1] = 2016-09-15` の行を**持たない**。相異なるのは**この1日だけ**である（S が全601キャッシュを実測。`2016-09-15` を持つ銘柄489 / 持たない銘柄89）。
- **`T[1]` は U-4 の助走窓 `T[1]〜T[60]` の内部にあり、イベント日の範囲（PEAD は `T[61]` 以降）より前である。したがってイベントは1件も失われない。**
- 影響は当該銘柄の U-4 の `Va` 標本が **60個 → 59個**になることのみ。**§5 U-4 の既存規則「有効 `Va` が30個未満なら不通過」で決定的に処理される。新しい閾値を導入しない。**
- **この非対称性は §9-9 で銘柄ごとに件数を出力し、§2.4 B-8 として申し送る。**
- **将来さらに後の日に銘柄を追加取得した場合、その銘柄が欠く先頭日数は1日より増える。** 助走窓が60営業日あるため直ちに問題にはならないが、**U-4 の「30個未満は不通過」で機械的に落ちる**。**この場合も新しい閾値を作らず、既存規則に委ねる。**

### 2.2 窓長・ラグ・オフセットの算術的整合性（**T-8・trading-app-v2 EXP-OBS000037 の教訓**）

**「本数」と「対象範囲（終値の数・日付レンジ）」の対応関係を、実装者が再計算できる式として書く。導出済みの数値だけを散文で書かない。**

イベント日を `D = T[i]`（= `DiscDate`）とする。

| # | 用語 | 営業日の**本数** | 対象となる `T` の添字 | **参照する価格の個数** |
|---|---|---|---|---|
| W-1 | 選定期間の U-4 窓 | **60本** | `T[1]` 〜 `T[60]` | 銘柄あたり `Va` **60個**（欠測日はその銘柄の標本から除く。有効60個中30個未満なら U-4 不通過） |
| W-2 | 確認期間の U-4 窓 | **60本** | `T[m−59]` 〜 `T[m]` | 同上 |
| W-3 | エントリー日 `t_1` | **1本** | `T[i+1]` | 始値 `O(T[i+1])` **1個** |
| W-4 | **予測単位 `R_5`（H = 5営業日）** | **ホライズン5本** | `t_1 = T[i+1]` 〜 `t_5 = T[i+5]` | **`R_5 = C(T[i+5]) / O(T[i+1]) − 1`。始値1個＋終値1個＝価格2個。**<br>**※ これは隣接差分の連鎖ではないため「5本のリターン ⇒ 6個の終値」という対応にはならない。** 日次リターン系列を作る場合（デシル分析等の記述統計）に限り、`t_1`〜`t_5` の**5本の日次リターンは終値5個＋基準となる `O(t_1)` 1個＝価格6個**から作られる。**この2つを混同してはならない** |
| W-5 | 最大保有（10営業日）＋時間切れ決済 | **保有10本＋決済1本** | `t_1 = T[i+1]` 〜 `t_10 = T[i+10]`、決済は `t_11 = T[i+11]` の**始値** | 添字は `i+11` まで |
| W-6 | `SELL_BLOCKED` による持ち越し上限 | **＋5本** | 最悪で `T[i+16]` | 添字は `i+16` まで |
| W-7 | **⇒ 1イベントに必要な `T` の添字範囲** | — | **`i+1` 〜 `i+16`** | — |

- **したがってイベント日の添字 `i` は次を満たさなければならない**:
  - 確認期間: **`m+1 ≤ i ≤ N−16`**
  - 選定期間: **`61 ≤ i ≤ m−16`**
- **選定期間側にも `−16` の余白を置く。** 余白が無いと選定期間末尾のイベントの前方窓が確認期間の先頭に食い込み、「選定期間の測定」が確認期間の価格を観測してしまう。**EXP-OBS000001（選定末 2025-06-30／確認始 2025-07-01）はこの重なりを持っていた。本EXPは構造的に排除する。これは基準の緩和ではなく分離の強化である。**
- **イベント集合は G1・G2 で共通に定義する。** 上記の範囲は G1（`i+5` まで）と G2（`i+16` まで）の**両方**を満たすよう `i ≤ N−16` に統一しており、「測定ごとに異なるイベント集合を使う」ことを構造的に排除する。**前方窓が確保できないという理由でイベントを個別に除外する処理は発生しない**（範囲の定義自体が保証する）。万一発生した場合は実装の誤りであり、件数を記録して S に差し戻す。

### 2.3 本 EXP における「選定」の自由度はゼロである（最重要）

本 spec は SUE 定義・予測ホライズン・トレール4パラメータ・閾値・ユニバース条件・コスト前提の**すべてを回す前に数値で固定している**。**選定期間で選ぶパラメータは1つも存在しない。**

- 選定期間は「事前固定設計の参照測定」であり、チューニングの場ではない。
- **B実装チームは、選定期間の結果を見て spec のいかなる値も変更してはならない。** 変更が必要と判断した場合は**実装を止めて S に差し戻す**（§10）。
- 選定/確認の符号一致（§6.2 G1-2、§6.4 G2-3）は、この前提の下での再現性確認として要求する。

## 3. シグナル定義: SUE

**`research/EXP-OBS000001/01-spec.md` §3.1〜§3.5 を一字一句そのまま適用する。** 以下は実装者が参照なしで実装を誤らないための再掲であり、**原本との差異があれば原本が優先する**（差異を発見した場合は S に報告すること）。

### 3.1 単一の事前登録定義

| 記号 | 定義 | 取得元（すべて `/fins/summary`） |
|---|---|---|
| `A(t)` | 本開示時点の当期通期経常利益の会社見通し | 1Q/2Q/3Q 開示 → **`FOdP`** ／ 通期（FY）開示 → **`OdP`**（実績） |
| `B(t)` | 直前開示時点で示されていた**同一会計年度**の通期経常利益の会社予想 | 直前が 1Q/2Q/3Q または業績修正開示 → **`FOdP`** ／ 直前が前期のFY開示 → **`NxFOdP`** |
| `Scale(t)` | 直前開示時点の同一会計年度の通期予想売上高 | 同上 → **`FSales`** / **`NxFSales`** |

**`RawSUE(j, t) = ( A(t) − B(t) ) / Scale(t)`**

### 3.2 会計年度の一致判定

- `A(t)` の対象会計年度は本開示の `CurFYSt` / `CurFYEn` で特定する。
- 直前開示が 1Q/2Q/3Q/修正開示なら、その `CurFYSt` / `CurFYEn` が本開示の `CurFYSt` / `CurFYEn` と**完全一致**すること。
- 直前開示が FY開示なら、その `NxtFYSt` / `NxtFYEn` が本開示の `CurFYSt` / `CurFYEn` と**完全一致**すること。
- 一致する直前開示が存在しない場合、そのイベントは**除外**し、件数を記録する。

### 3.3 除外規則（すべて事前登録・件数を必ず記録）

1. `A(t)` / `B(t)` / `Scale(t)` のいずれかが null / 空文字 / 非数値 → 除外
2. `Scale(t)` ≤ 0 → 除外
3. 予測対象イベントは**四半期決算短信および通期決算短信の開示のみ**。業績修正開示・配当予想修正等は `B(t)` の探索対象にはなるが、**イベント（予測対象）にはしない**
4. 同一銘柄・同一 `DiscDate` に同種の開示が複数ある場合、`DiscTime` が最も遅い1件のみ。同一なら `DiscNo` が最大の1件

### 3.4 標準化・外れ値処理

- **主指標（IC）には追加の標準化を行わない**（Spearman は単調変換に不変）。
- **副指標（デシル）には先読みのないトレーリング分位 `SUEpct` を使う**（`DiscDate` が t より厳密に前の全イベントの経験分布・拡大窓）。参照イベント数が **200件未満**ならデシル分析からのみ除外する。
- **`RawSUE` の winsorize は行わない。リターンの winsorize も行わない。**
- **`RawSUE` の厳密なゼロ件数の比率を必ず出力すること。**

### 3.5 事前登録した感度分析（**合否判定に使ってはならない**）

| # | 軸 | 水準 |
|---|---|---|
| SA-1 | 利益項目 | `OdP`（**主**） / `OP` / `NP` |
| SA-2 | 予測ホライズン H | 3営業日 / **5営業日（主）** / 10営業日 |
| SA-3 | シグナル閾値 | 上位5% / **上位10%（主）** / 上位20% / 上位30% |
| SA-4 | 往復コスト | 0.25% / **0.35%（主）** / 0.50% |

**合否判定に用いる検定は §6.1 の主検定1本のみ**（`OdP` × H=5 × 上位10% × コスト0.35%）。**多重性の補正は不要。SA-1〜SA-4 は記述統計であり検定として解釈してはならない。**

## 4. 約定モデル

**`research/EXP-OBS000001/01-spec.md` §4.0〜§4.5 をそのまま適用する。** 要点の再掲:

### 4.1 値幅制限フラグの解釈（**唯一の判定式**）

```
BUY_BLOCKED(t)  = (Vo(t)==0) or (O(t) is null) or (UL(t)==1 and O(t)==H(t))
SELL_BLOCKED(t) = (Vo(t)==0) or (O(t) is null) or (LL(t)==1 and O(t)==L(t))
```

- `UL` / `LL` は**0/1 のフラグ**であり価格水準ではない。**JPX 制限値幅表からの上限/下限価格の自前再構成は禁止。**

### 4.2 エントリー

- **`t_1 = T[i+1]` の始値 `O(t_1)`** に固定する。`DiscTime` が場前・場中・場後のいずれでも同じ扱い（最も保守的な統一）。
- `BUY_BLOCKED(t_1)` が真なら**約定不能・そのイベントは見送る**（翌日以降の再エントリーをしない）。内訳を3分類（`Vo=0` / `O` が null / `UL=1 かつ O=H`）で記録。参考値として `UL=1 だが O<H` で約定したとみなした件数も記録。
- 約定価格 = `O(t_1) × (1 + 0.075%)`。

### 4.3 予測単位（G1）の前方リターン

- **`R_5 = C(T[i+5]) / O(T[i+1]) − 1`**（グロス。コスト・スリッページを一切引かない）。
- 約定不能イベントを除外した版と、`O(t_1)` を用いて仮想的に含めた版の**両方の `IC_bar` を出力する**（**主判定は除外版**）。

### 4.4 決済ルール（トレーリングストップ）

| # | パラメータ | 固定値 |
|---|---|---|
| 1 | 初期損切幅 | エントリー約定価格の **−3.0%** |
| 2 | トレール発動水準 | 終値ベースの含み益が **+4.0%** 以上に到達した日の**翌営業日から**有効 |
| 3 | 追随幅 | 発動後、`t_1` 以降の**日次終値**の最高値から **−2.0%** |
| 4 | 更新足と約定価格 | **日足終値のみ**で更新・抵触判定。抵触日の**翌営業日始値**で約定 |

- **日中高値・安値（`H` / `L`）はトレールの更新にも抵触判定にも使わない。**
- 決済時の約定価格 = `O(t_exit) × (1 − 0.075%)`。
- **最大保有10営業日**（`t_10` の終値時点で未決済なら `t_11 = T[i+11]` の始値で強制手仕舞い）。

### 4.5 決済できない場合（値幅制限の模擬）

- `SELL_BLOCKED(t_exit)` が真なら**約定できず持ち越し**。以降の各営業日で再評価し、偽となった最初の営業日の始値で約定する。その間の下落はすべて損失として計上する。
- **最大5営業日**持ち越しても約定できない場合、5営業日目の終値で強制的に評価損益を確定し「強制評価」として件数を記録する。
- **本ルールはすべての売り約定に一律に適用する**（初期損切・トレール抵触・最大保有超過・決算跨ぎ回避・サーキットブレーカー清算）。

**Sharpe の扱い**: 年率 Sharpe は**算出・報告するが G2 の合否判定には一切用いない**。報告時は必ず 95%信頼区間を併記する（**約5年観測のため標準誤差は概ね `√(1/5) ≈ 0.45`、信頼区間の幅は ±0.9 程度**）。**Sharpe の再現性判定は STEP3 フォワード較正へ送る。**

> **PJ000001 §5.2 との差異（申し送り）**: PJ000001 §5.2 の STEP2 KPI「確認期間でコスト控除後 Sharpe ≥ 0.5」を本EXPでは**合否ゲートに使わない**（EXP-OBS000001 §6.4 と同じ扱い）。代償として G1 側を厳しくしている（G1-3・G1-4・G1-5）。**この差異は C品質チームの検査対象とし、司令塔の了解事項として扱う。**

### 6.5 G2 で必ず出力する生データ

**`research/EXP-OBS000001/01-spec.md` §6.5 の P-1 〜 P-13 をそのまま要求する。欠けている場合、C品質チームは自動的に「差し戻し」とする。**

### 6.6 / 6.7 G3（低相関）・G4（限界寄与）

**本 EXP では判定不能**（スリーブ在庫がゼロ）。数値基準は PJ000001 §5.3 のまま据え置く（|ρ| < 0.3 ／ 合成 Sharpe +0.15 以上 **または** 最大DD −5pt 以下）。**本EXPでは測定しない**が、**確認期間の日次スリーブPnL系列を `pipeline.json` に保存する**（P-10）。
