## 2. 前提の分解 ——「1本の複合戦略」か「複数の独立EXP」か

### 2.1 判定: **分割する。束ねることは禁止する。**

司令塔が提示した5情報源を1つの戦略に束ねる設計は、**trading-app-v2 OBS000027（③LLMセンチメント層を②の上に足し算して不発。予測単位からして方向一致49.6%・p=0.83）と完全に同型**である。束ねた場合に何が起きるかは、罠の構造として以下のように確定している。

| 束ねた場合に起きること | なぜ起きるか |
|---|---|
| どの情報源が効いたか切り分け不能 | 5変数の合成スコアの寄与分解は、変数間に相関がある限り一意に定まらない |
| 無エッジの情報源を混ぜても「良さそう」に見える | 合成の重みを推定する自由度が増えるため、選定期間でのフィットは**必ず**改善する。増分がゼロでも見かけの成績は上がる |
| 不採用時に何も学べない | 「5つのどれかが悪かった」という結論は、次の実験の事前確率を1ミリも更新しない。**負の結果が資産にならない** |

本プロジェクトは現在**スリーブ在庫がゼロ**である。したがって「既存の何かの上に足し算する」設計は**物理的に不可能**であり、逆に言えば、**今なら全候補を強制的に単独検定の形に落とせる**。この構造上の幸運を使い切る。

### 2.2 分割の設計図

司令塔提示の5情報源を、**「単独で時間変動するシグナルを生成できるか」**という単一の基準で分類した結果が下表である。この基準は、束ね設計を排除するための最小十分条件である（単独で信号を出せないものは、必ず他の変数との掛け算を要求し、掛け算はすなわち足し算設計への入口になる）。

| 分類 | 該当 | 起票の扱い |
|---|---|---|
| **(A) 単独で時間変動シグナルを生成でき、データがある** | #4 オーバーナイト・ギャップ | **本EXPとして単独起票（GO）** |
| **(B) 単独で時間変動シグナルを生成できるが、データがない** | #2 適時開示テキスト（TDnetアドオン）<br>#5 板情報（そもそもAPIなし）<br>（参考）#3 のうち先物夜間セッション（Premium） | **保留またはKill**。データが解けた時点で単独EXPとして起票 |
| **(C) 単独では時間変動シグナルを生成できない（静的ラベル／低頻度状態変数）** | #1 業種区分 `S33`<br>#3 マクロ（金利・為替・短観） | **独立EXPとして起票しない**。中立化変数・リスク上限・レジーム監視として**他EXPの内部に吸収**する |

**(C) を独立EXPとして起票しないことが、本 prescreen の最も重要な設計判断である。** 静的ラベルや低頻度の状態変数を「シグナル入力」と呼んだ瞬間、それは必然的に「別の何かに掛ける／足す」設計になり、OBS000027 の罠に直行する。

## 4. 市場観点の評価（GO候補 #4 について）

> 以下は GO と判定した #4 のみを対象とする。却下・保留とした #1/#2/#3/#5 は §6 で個別に扱う。

### 4.1 想定するエッジの源泉

**需給／市場構造（マイクロストラクチャ）**。具体的には**寄付の板寄せ（単一価格オークション）における一時的な売り需給の偏りの解消**。

日本株の寄付は、前日大引け（15:30）から当日 9:00 までの**約17.5時間ぶんに蓄積された注文を、1回の板寄せで単一価格に清算する**。この清算価格は、蓄積された注文フローの偏り（個人の成行売り、投信の解約対応、信用の追証処分売り等）に押され、情報価値のない一時的な水準に振れうる。その振れが後日戻る、というのが本EXPの想定である。

### 4.2 エッジ族の分類 —— **価格由来の方向予測に該当する（重大）**

**該当する。** これを曖昧にしない。

司令塔のテーマ提示は「夜間取引は価格以外のインプット」という前提に立っているが、**この前提は誤りである**と判定する。オーバーナイト・ギャップ `ln(O_t / C_{t-1})` は、価格のみから算術的に導かれる量であり、生成過程は既存4戦略（MACD+RSI / BB+CCI / MAクロス+ADX / ATR+Stochastic）と**同一の族**に属する。PJ000001 §4 C-3 が事前確率「低」と宣告した族そのものである。

したがって **本EXPの事前確率は「低〜中」、内訳としては低寄りとする。** 「非価格情報だから有望」という理由づけは本EXPには一切使えない。

本EXPで非価格なのは、**特徴量ではなく条件分岐（決算開示の有無）**のみである。これは「日本株には非価格情報にエッジがあるのではないか」という本プロジェクトの賭け（STRATEGY-BRIEF §本プロジェクトの賭け）を**検証するものではない**。本EXPは賭けの検証ではなく、**追加コスト¥0で回せる、統計的検出力の高い価格由来の最後の一発**として位置づける。

### 4.3 なぜ日本株では結論が変わりうるのか（同型起票の必須条件）

trading-app-v2 の8連敗は**すべて暗号資産（24時間365日の連続取引）**の上で得られた結果である。本EXPが依拠する構造は、その市場には**概念として存在しない**。

| 日本株固有の構造 | 暗号資産での対応物 | 本EXPとの関係 |
|---|---|---|
| **1日17.5時間（週末は65.5時間）の取引停止** | **存在しない**（24/7連続） | ギャップという事象そのものが暗号資産には存在しない。OBS000018〜031 のどの実験も、この事象を測定対象にしていない |
| **寄付の板寄せ（単一価格オークション）** | **存在しない**（常時ザラバのみ） | 蓄積注文を1価格で清算する機構がないため、「オークション清算価格の一時的な歪み」という現象が発生しない |
| **値幅制限（ストップ高／安）** | **存在しない** | 極端ギャップの約定可能性を制度が制約する。`UL`/`LL` フィールドで明示的に判定可能 |
| **昼休み（11:30-12:30）による分断** | **存在しない** | 本EXPでは直接使わないが、日中の価格形成が連続でない点は共通の構造差 |
| **個人投資家比率の高さと信用取引の追証処分売り** | 構造は近いが、期日・追証の制度が異なる | 寄付に集中する強制的な売りフローの源泉 |

**重要な留保**: これらは「日本株では結論が変わりうる」ことの根拠にはなるが、「変わる」ことの根拠にはならない。**構造が違うから有望、という推論は成立しない。** 本EXPは、構造が違うので**測る価値がある**、という水準の主張しかしていない。

### 4.4 市場構造上の妥当性（単元株・値幅制限・信用規制・流動性）

| 観点 | 評価 | 詳細 |
|---|---|---|
| 単元株（100株） | 🔶 中程度の障害 | 目標建玉25万円に対し、株価1,000〜3,500円帯なら1単元10〜35万円。離散化誤差は許容範囲。OBS000001 spec §5.4 U-5 のユニバース定義をそのまま流用できる |
| 値幅制限 | 🔴 **本EXPの中核的リスク** | 大きな下方ギャップはストップ安に接する確率が高い。ストップ安比例配分では**買い注文は約定しやすい側**（売り手過多）だが、**特別気配による寄付の遅延**で「始値で買えた」という前提が崩れる。`UL`/`LL` による判定は必須。OBS000001 spec で確定済みの UL/LL 解釈規約（commit `d8a7f25`）を流用する |
| 信用規制 | 🟢 障害小 | **ロングオンリー**のため逆日歩・貸株規制の影響を受けない。増担保規制（委託保証金率引上げ）はギャップ銘柄で発動しうるため、spec で除外規則を定義する |

### 4.5 レジーム依存性の見立て

**依存性は高い、と見る。** 下方ギャップは市場全体の下落局面に集中する。したがって本EXPは「押し目買い」の一種として、**ベア相場では負け続け、ブル相場の調整局面で勝つ**という強いレジーム依存を持つ可能性が高い。

さらに深刻なのは**イベントのクラスタリング**である。市場急落日には8つの建玉枠すべてが同日の下方ギャップ銘柄で埋まりうる。これは「8つの独立な賭け」ではなく「市場ベータへの1本張り」への縮退であり、**OBS000029（N=2 は実質1本張りに縮退）が時間方向で再発する形**になる。spec で**同日エントリー上限**と**セクター上限**を数値で固定することを必須条件とする（§10 申し送り T-4）。

検証期間が **2024-06-21〜2026-06-21 の約2年間**しかないため、この2年が特定のレジームに偏っていた場合、結果はレジーム固有のものになる。**レジーム依存性は本EXPでは解消できない。** STEP3 フォワード較正での再現確認を必須とする（PJ000001 §4 C-4 最終決着と同じ扱い）。

### 4.6 資本制約下での実現可能性

| 項目 | 数値 |
|---|---|
| 運用資本 | 100万円（司令塔判断1） |
| レバレッジ / 建玉枠 | 2.0倍 / 200万円 |
| 1トレードの目標建玉 | 25万円 |
| 同時保有上限 | **8銘柄** |
| 想定保有期間 | 5営業日（spec で 3/5/10 を事前登録して比較） |

**これが EXP-OBS000002（却下）との決定的な違いである。** クロスセクショナル・ランキングは「上位デシル数十銘柄を同時に持ち続けて個別要因を相殺する」ことが作動原理であり、8枠（ユニバースの1.6%）では原理が成立しなかった。本EXPは**イベント駆動**であり、イベントは時間的に散らばって発生するため、8枠を逐次的に回して年215トレードを消化できる。**建玉枠がボトルネックにならない設計は、本プロジェクトの資本規模において構造的に価値がある。**

### 4.7 Kelly・破産確率のサニティ

| 項目 | 数値 |
|---|---|
| 1トレードの実効 f（建玉 ÷ 資本） | 25万 ÷ 100万 = **0.25** |
| 同時8枠フル時のグロス f | **2.0**（＝レバレッジ上限） |
| 1トレードあたり最大損失（初期損切 −4.0%） | 25万 × 4.0% = 1.0万円 = **資本の1.0%** |
| 8枠フル時の同時最大損失（相関1.0の最悪ケース） | **資本の8.0%** |
| サーキットブレーカー（PJ000001 §8.1） | DD 10% で新規停止、15% で全清算・打ち切り |
| 破産確率サニティ | 資本の1.0%/トレードは、8連敗しても −8%。CB（10%）に先に当たる設計であり、**単一トレードでの破産経路は存在しない** |
| フラクショナルKelly | 仮に勝率56%・損益比1.0なら Kelly f* = 0.12。実効 f=0.25 は **Kelly の約2倍**であり、**フルKelly超**。PJ000001 §8.2（フラクショナルKelly）に照らすと**過大** |

### 5.3 本プロジェクト内の不採用との照合 —— EXP-OBS000002（重要）

EXP-OBS000002（日本株クロスセクショナル価格ファクター）は 2026-09-13 に prescreen 段階で却下されている。**短期リバーサルは同EXPのスコープに含まれていた。** したがって本EXPは、**却下済み案件を形を変えて再提出しているのではないか**という疑義を正面から処理する義務がある。

| OBS000002 の却下根拠 | 本EXPへの当てはまり | 判定 |
|---|---|---|
| ① **コスト算術（決定打）**: 保有7営業日・往復0.35%・グロス2.0倍で年間コスト＝資本の24.5%。日本株の実測ファクター・スプレッドは約0.5%/年で **40〜50倍不足** | 🔴→🟡 **当てはまり方が異なる。これが唯一かつ最大の相違点** | OBS000002 は**常時フル投資のクロスセクショナル・ランキング**であり、コストは**建玉200万円全体の回転**に比例した。本EXPは**イベント駆動で建玉が断続的**であり、コストは**イベント件数**に比例する。年間コストは資本比 **24.2%（OBS000002 と同水準）**だが、**要求されるグロス・エッジの単位が違う**。OBS000002 は「年率0.5%のファクター・スプレッドから年24.5%を捻出せよ」という不可能な要求だったのに対し、本EXPは「選別した年215件の極端イベント1件あたりグロス0.45%を出せ」という要求であり、**必要倍率は40〜50倍ではなく、およそ2倍以内**（§8.4）。**この差が、同じコスト算術ルール（X-5）を適用しても結論が分かれる理由である** |
| ② 建玉可能数8（ユニバースの1.6%）でクロスセクショナルの作動原理が成立しない | ❌ 当てはまらない | §4.6 の通り、イベント駆動なので枠は足りる（必要215 < 上限392） |
| ③ 逆日歩で下位ランクのショートが組めず、ロングオンリーではファクターにならない | ❌ 当てはまらない | 本EXPは**最初からロングオンリーのイベント戦略**であり、ロング・ショートのスプレッドを取りにいく設計ではない。市場ベータを持つことは設計上の前提であり、**ベンチマークをロングオンリーに取る**（OBS000001 spec §5.2/§6.6 と同じ扱い） |
| ④ 日本固有エビデンスが逆方向（Fama-French 2012: 4地域中**日本のみモメンタム不在**、2025年東証研究も同旨） | 🟢 **むしろ順方向に働く** | 「日本にモメンタムがない」という所見は、**リバーサル側が相対的に優勢である**ことと矛盾しない（符号が逆）。ただしこれは**弱い傍証にすぎず、根拠として重く使わない**。FF2012 が測ったのは12ヶ月モメンタムであり、本EXPの1〜5日スケールとは別物である |

**判定**: 本EXPは OBS000002 の迂回起票ではない。**分岐点はコスト構造（常時フル投資 vs イベント駆動）1点であり、それを §8 で数値により明示した。** ただし C品質チームはこの主張を疑ってかかること——もし実装の結果、イベント件数が想定の215件/年を大きく超え（例: 年800件超）、実質的に常時フル投資に近づいた場合、**本EXPは OBS000002 と同じコスト構造に退化し、同じ理由で死ぬ**。したがって**イベント件数の上限を spec で事前に固定する**（§10 申し送り T-1）。

## 6. 却下・保留とした候補の個別評価

### 6.1 #1 業界（セクター）情報 —— 却下（独立EXPとして不成立）

**却下理由（本質的なもの）**: `S33` は**静的ラベル**であり、それ自体は時間変動しない。時間変動しない変数は、単独では時刻 t におけるシグナルを生成できない。したがってセクター情報を「シグナルの入力」とする設計は、**必ず「セクター × 何か」の形を取る**。そして掛ける相手は3通りしかない。

| 設計 | 判定 |
|---|---|
| セクター × 価格（セクター・ローテーション、セクター内相対モメンタム） | **EXP-OBS000002（却下済み）と同型**。加えてセクター単位に集約すると有効 N が33に落ち、175銘柄ユニバースでは1セクター平均5銘柄という極端に粗い推定になる。8枠の制約も同じく効く |
| セクター × 会計（セクター内 SUE ランキング） | **EXP-OBS000001（PEAD）に既に内包済み**。同 spec §6.3 が「セクター中立リターン」を副指標として要求している。新規EXPを起こす意味がない |
| セクター × 需給（業種別空売り比率等） | **データ取得不可**。J-Quants Standard 以上（¥3,300/月）が必要であり、重大論点 C-5 の管轄 |

**したがってセクター情報は「独立したエッジ源泉」ではなく「中立化・リスク分散のための制御変数」である**、というのが本 prescreen の判定である。実際、既に以下の形で本プロジェクトに組み込まれている。

- `EXP-OBS000001/01-spec.md` §5.3-7: セクター集中上限
- `EXP-OBS000001/01-spec.md` §6.3: セクター中立リターンによる副次検定
- `EXP-OBS000001/01-spec.md` §5.4 U-3: ユニバース構築時のセクター記録

本EXP（#4）でも同様に、§10 申し送り T-4 でセクター上限を要求する。**独立EXPとしては起票しない。**

### 6.2 #2 経営情報（適時開示テキスト）—— 保留。既存候補③に吸収し、新規EXPは起票しない

**保留理由（Kill ではなく保留とする根拠）**:

### 6.3 #3 マクロ経済状況 —— 却下（独立スリーブとして）

データは §3.3 の通り**無償で取得できる**（FRED＋日銀）。**却下理由はデータではなく、統計的検出力と設計にある。**

| 却下理由 | 詳細 |
|---|---|
| **① 時系列の有効 n が原理的に不足** | 検証期間は約2年。日銀短観は四半期公表なので**8観測**。金利・為替は日次だが自己相関が極めて強く、独立な「レジーム・エピソード」は2年でせいぜい5〜15回。これは**統計的に何も言えない**水準であり、どんな結果が出ても偶然と区別できない |
| **② ゲート設計は在庫ゼロでは成立しない** | 「マクロが○○のときだけスリーブを動かす」という設計は、ゲートされる対象（スリーブ）が必要。本プロジェクトの検証済みスリーブは**0本**。物理的に不可能 |
| **③ ゲート設計は OBS000018 と同型** | 仮にスリーブが1本できたとしても、「固定閾値でレジームを判定して on/off する」は **OBS000018（ERレジームゲート＝固定閾値は蜃気楼・非単調・パイプラインで無ゲート以下）** の完全な再演。かつ ① の低い n では非単調性チェックすら実施できない |
| **④ 横断設計に逃げると OBS000002 と同型化** | 有効 n を稼ぐために「銘柄ごとの為替ベータでランキングする」設計に逃げる経路があるが、為替ベータは**価格の回帰係数＝価格由来**であり、かつクロスセクショナル・ランキングなので **EXP-OBS000002（却下済み）のコスト算術がそのまま適用される** |
| **⑤ 足し算設計への強い引力** | マクロ変数は「他のシグナルに足す／掛ける」以外の使い道を持ちにくい。**OBS000027 の罠への最短経路**である |

**却下するが、以下は資産として記録する**（STRATEGY-BRIEF へ反映）:

> **マクロ変数は無償で取得できる**（FRED API: 無料・要APIキー登録／日銀 時系列統計データ検索サイト: 無料CSV・キー不要）。**用途をシグナル生成ではなく⑤リスク管理層のレジーム監視・サーキットブレーカーの補助入力に限定すれば、統計的検出力の問題を回避したまま価値を出せる可能性がある。** これは実験（EXP）ではなく実装（STEP4）の管轄であり、本 prescreen の対象外とする。

### 6.5 副産物 —— 決算発表予定日の前倒し／後ろ倒し（**保留を解除 → 却下。EXP-OBS000004 は起票しない**）

### 6.6 副産物 —— TDnetインデックス（本文なし）単体の使い道（**限定的。独立EXPとしては起票しない**）

§3.2 訂正1 により、`research/_snapshots/tdnet/` に**適時開示インデックスが40日分（9,361件）蓄積済み**であることが確定した。これ単体で何ができるかを正直に評価する。

| 使える情報 | 使えない情報 |
|---|---|
| 開示の**時刻**（分単位）・**銘柄**・**表題**（短文テキスト）・PDFリンク・XBRL有無・上場取引所 | 開示**本文**（数値・文言・トーン）。すなわち「何がどれだけ良かった／悪かったか」は一切分からない |

**考えられる用途と、その評価**:

| 用途 | 評価 |
|---|---|
| (a) **開示種別の分類**（表題の文字列照合で「業績予想の修正」「自己株式の取得」「TOB」等に振り分ける） | 🔶 **技術的には可能**。表題は定型文に近く、正規表現でも相当な精度が出る（実測40日で「業績予想の修正に関するお知らせ」が70件、「自己株式取得に係る事項の決定」が81件）。ただし**修正が上方か下方かは表題から分からない**ため、方向を持つシグナルにならない |
| (b) **開示の頻度・密度**（銘柄あたりの月次開示件数、その異常増加） | 🔴 **筋が悪い**。開示件数は企業規模・決算期・ETFか否かで決まる定数成分が支配的であり、時間変動成分は決算シーズンのカレンダー効果にほぼ吸収される。「異常に多い＝何か起きている」という仮説は、**方向を持たない**（好材料の連発と悪材料の連発を区別できない）。加えて **OBS000018（固定閾値レジームゲート＝蜃気楼）と同型**の閾値設計になる |
| (c) **開示の時刻**（15:00 以降の引け後開示、深夜開示など） | 🔶 EXP-OBS000003 の T-3（PEAD との事象排反）や T-7（未識別ニュースの混入率推定）の**補助情報としては有用**。ただし**直近38日分しかないため、2年のバックテストには使えない**。使えるのは STEP3 フォワード以降 |
| (d) **候補③（LLM単独）の代替** | ❌ **不可**。候補③が賭けているのは**本文の解釈**である。表題だけで LLM に解釈させる設計は、「業績予想の修正」という事実は取れても符号が取れないため、**情報量が構造的に不足する** |

**判定: TDnetインデックス単体では独立EXPを起票しない。**

理由は3点。① **方向（符号）を持つシグナルが作れない**——表題から上方修正か下方修正かが判別できず、シグナルの向きが決まらない。② **バックテスト用の履歴が38日分しかない**——保持期間の壁により過去へ遡れず、2年の検証窓に対して1/19の長さしかない。③ 方向が取れない以上、設計は必然的に「他の何かに掛ける／足す」形になり、**OBS000027 の罠への最短経路**になる（§2.3 の分類 (C) に該当する）。

**ただし蓄積は継続する。** 蓄積を止めると1年後の候補③解禁（§6.2 解消条件②）の道が閉じるため、`scripts/snapshot_tdnet.py` の日次実行は維持する。**蓄積の継続と、独立EXPを起票しないことは両立する。**

## 7. コスト前提（回す前に置く）

> **S戦略チームの自己ルール X-5（EXP-OBS000002 で確立）**: 「往復コスト × 年間往復回数 × グロス・エクスポージャ を prescreen 冒頭で算出し、損益分岐に必要なグロス・エッジを回す前に明示する」。本節はその履行である。

### 7.1 往復コストの内訳

本EXPは**寄付の板寄せで約定する**という、本プロジェクトの他EXPにない固有のコスト源を持つ。したがって**プロジェクト標準の往復0.35%をそのまま使わず、往復0.45% を本EXPの中心ケースとする**（標準より厳しく置く。緩める方向の変更ではない）。

| 項目 | 片道 | 往復 | 根拠 |
|---|---|---|---|
| スプレッド（呼値の半値） | 0.05% | **0.10%** | 株価1,000〜3,500円帯・呼値1円 → 1,000円で0.10%、3,500円で0.03%。保守側に 0.05%/片道 |
| スリッページ（**寄付の板寄せ**） | 0.10% | **0.20%** | 板寄せの成行は理論上は始値そのものだが、(a) 自分の注文が清算価格の形成に参加する、(b) ギャップ銘柄は板が薄い、(c) 特別気配で寄付が遅延する。**この項目が本EXPの最大の不確実性**。日足検証では検証不能（§4.4） |
| 委託手数料 | 0.05% | **0.10%** | 主要ネット証券の信用取引は約定代金に応じて無料〜0.05%程度。保守側 |
| 信用買方金利 | — | **0.05%** | 年2.8% × 7暦日（5営業日）÷ 365日 = 0.054% |
| 貸株料・逆日歩 | — | **0.00%** | **ロングオンリーのため発生しない**（OBS000002 却下根拠③の回避） |
| **合計** | | **0.45%** | |

**感度分析の必須レンジ**: spec では **0.35% / 0.45% / 0.60%** の3点で全指標を再計算することを要求する。0.60% は特別気配・板薄による最悪ケースを想定した水準である。

### 7.2 損益分岐勝率

決済はトレーリングストップ（司令塔判断3）のため固定利確幅が存在せず、テンプレートの式 `損切幅 ÷（利確幅＋損切幅）` をそのまま適用できない。**平均利確幅を仮に置いた上での必要勝率**として計算する。

初期損切 **−4.0%**、トレーリングによる平均利確 **+4.0%**（対称と仮定）、往復コスト **0.45%** とすると、

```
p × 4.0% − (1 − p) × 4.0% − 0.45% = 0
8.0% × p = 4.45%
p = 55.6%
```

**→ 必要勝率 55.6%**（コストなしなら50.0%）。コストが必要勝率を **5.6ポイント**押し上げている。

**これは spec で置く損切幅に強く依存する。** 損切を −2.0% に詰めると必要勝率は `(2.0 + 0.45) / 4.0 = 61.3%` に跳ね上がる。**下方ギャップ銘柄はボラティリティが高く、−2.0% の損切は即座に刈られる**ため、初期損切は最低でも −4.0%（当該銘柄の日次σの約2倍）を要する見込みである。spec で数値固定すること（§10 申し送り T-4）。

### 7.3 年間コスト（X-5 の算出）

| 前提 | 値 |
|---|---|
| 年間トレード数 | **215件**（§4.6。イベント頻度の想定値。spec で上限を固定する） |
| 1トレード建玉 | 25万円 |
| 年間売買代金（建玉ベース） | 215 × 25万 = **5,375万円** |
| 往復コスト | 0.45% |
| **年間コスト** | 5,375万 × 0.45% = **24.2万円 ＝ 資本比 24.2%/年** |

### 7.4 損益分岐に必要なグロス・エッジ（**本節が本 prescreen の核心**）

| 指標 | 必要水準 |
|---|---|
| **損益分岐（ネット期待値ゼロ）** | **1トレードあたり平均グロス・リターン ≥ 0.45%** |
| **North Star（Sharpe 1.0）到達に必要な水準** | **1トレードあたり平均グロス・リターン ≥ 0.85%** |

Sharpe 1.0 の逆算（事前登録する数値）:

```
1トレードのポジションP&Lのσ:
  5営業日の個別株リターンσ ≈ 日次2.0% × √5 = 4.47%
  資本に対するσ = 4.47% × f(0.25) = 1.12%
年間σ（トレード間の正相関＝急落日のクラスタリングを織り込んで割増）:
  独立仮定なら 1.12% × √215 = 16.4%
  クラスタリング補正（保守側に 1.3 倍） ≈ 21.3%
Sharpe 1.0 に必要な年間ネットリターン ≈ 21.3%
  = 21.3万円 ÷ 215トレード = 991円/トレード
  = 991円 ÷ 25万円 = 0.40%/トレード（ネット）
  → グロス = 0.40% + 0.45% = 0.85%/トレード
```

### 7.5 **1日保有版（寄付→引け）を回す前に却下する算術**

司令塔が言及した「学術的に報告例がある」オーバーナイト効果は、文献上は**同日の日中セッションで反転が完結する**ものとして報告されている。すなわち**保有期間1日未満**である。この版を本プロジェクトで実行した場合のコスト算術を示す。

| 前提 | 値 |
|---|---|
| 年間トレード数（8枠 × 245日を50%稼働） | **約980件/年** |
| 年間売買代金 | 980 × 25万 = **2億4,500万円** |
| 年間コスト（往復0.45%） | **110.3万円 ＝ 資本比 110.3%/年** |
| 必要グロス | **1トレードあたり 0.45%（＝1日で0.45%）** |
| 文献が報告する効果量の目安 | ロング・ショート・スプレッドで月3%前後 ≒ **日次0.15%（片側では約0.07%）** |
| **不足倍率** | **0.45% ÷ 0.07% ≈ 6.4倍** |

**→ 1日保有版は、回す前に期待値マイナスが確定する。** これは trading-app-v2 **OBS000031（短時間足高頻度化＝手数料ゼロのグロス段階で平均負）** および **EXP-OBS000002（コスト算術による却下）** の教訓が、そのまま日本株に適用された結果である。**§0.4 でスコープ外としたのはこの算術による。**

### 7.6 したがって本EXPが賭けているものの正体（正直な告白）

**本EXPは、文献が報告している効果そのものを検証するものではない。**

- 文献が報告するのは**日中で完結する反転**である
- 本プロジェクトのコスト構造は、その保有期間を**支払えない**（§7.5）
- ゆえに本EXPは、**「その反転の一部が数営業日にわたって残存している」という、文献の外挿**に賭けている

**これが本EXPの最大の弱点である。** 文献の存在は本EXPの根拠を**補強しない**。むしろ、文献が「日中で完結する」と報告していることは、**数営業日の残存に対しては弱い反証**ですらある。

**それでも GO とする理由は §8 に示す。事前確率は「低〜中（低寄り）」であり、この評価を結果を見てから引き上げることはしない。**

## 10. spec への申し送り（S自身がA設計官として引き取る）

| # | 論点 | 要求 |
|---|---|---|
| **T-1** | **イベント件数の上限を事前固定する** | 年間トレード数が想定215件を大きく超えると、コスト構造が OBS000002（常時フル投資）に退化し、同じ理由で死ぬ。**閾値 z を「年間イベント数が 150〜300件に収まる水準」として選定期間で1回だけ決め、確認期間では動かさない**。件数が範囲外なら S に差し戻す |
| **T-2** | **閾値の非単調性チェック（OBS000018 対策）** | 主指標は閾値ではなく **z の連続値に対する Spearman IC**。副指標として **z のデシル別平均リターンの単調性**を要求する。単調でなければ閾値は蜃気楼と判定し、統計的有意性にかかわらず不採用とする |

| **T-4** | **リスク集中の数値固定（OBS000029 の時間方向再発の防止）** | ① 同日新規エントリー上限（例: 3件）、② 同時保有上限（8ではなく**6以下**を推奨。§4.7 の f 過大への対応）、③ 同一 `S33` セクターの同時保有上限（例: 2件）、④ 初期損切幅（−4.0% を起点に、当該銘柄のATR連動とするか固定とするかを確定）、⑤ トレール発動水準・追随幅・更新足（司令塔判断3 の4点セット） |
| **T-5** | **寄付の約定モデルを保守側に固定する** | ① 始値約定に**片道0.10%のスリッページを必ず加算**（§7.1）。② `LL`（値幅制限下限）に始値が接している銘柄は**約定不能として除外**（`UL`/`LL` の解釈は commit `d8a7f25` の規約に従う）。③ 約定不能により見送った件数・内訳を**生データとして出力**（必須条件④相当）。④ **この約定モデルの妥当性は日足では検証できないことを spec に明記**し、STEP3フォワードでの実測を採用の必須条件とする |

| **T-7** | **「非決算」の定義の限界を spec に明記する** | 本EXPが除外できるのは**決算短信等（`/fins/summary` に載るもの）のみ**であり、業績修正・自己株買い・M&A 等の適時開示は**TDnetアドオン未契約のため識別できない**。未識別のニュース起因ギャップの混入は**反転を打ち消す方向（＝効果を過小評価する方向）**に働くと予想される。**ただしこれを「安全側だから問題ない」と扱わない**（trading-app-v2 EXP-OBS000037 の教訓）。混入率の推定値を生データとして出力し、C品質チームが独立に評価できるようにする |
