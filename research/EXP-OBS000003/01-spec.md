## 1. 仮説（1文）

**日本株 TOPIX500 相当ユニバースにおいて、寄付の板寄せで前日終値から自銘柄の平常ギャップ変動の数倍にあたる下方乖離をもって始まった銘柄のうち、決算短信等の開示に起因しないものは、その乖離の一部を続く5営業日で回復し、往復コスト0.45%を控除した後も正の期待値を残す。**

### 1.1 エッジ族の宣言（prescreen §4.2 の確定を引き継ぐ）

- 予測変数 `g = ln(O(D)/C(D−1))` は**価格のみから算術的に導かれる量**であり、**PJ000001 §4 C-3 が事前確率「低」と宣告した「価格由来の特徴量から方向を予測する」族に属する。**
- **本EXPは本プロジェクトの賭け（非価格情報に直交エッジがあるか）を検証するものではない。** 非価格なのは特徴量ではなく条件分岐（決算開示の有無）のみである。
- 「夜間取引＝非価格情報」という司令塔提示の前提は prescreen §4.2 で**誤りと判定済み**であり、本 spec はこの訂正を前提に書かれている。

### 1.2 事前確率の見立て

**低〜中（低寄り）**。prescreen §4.2 の判定をそのまま引き継ぐ。**結果を見てからこの評価を引き上げることはしない。**

日本株固有の構造（17.5時間の取引停止・寄付の板寄せ単一価格オークション・値幅制限・昼休みによる分断）は 8連敗の測定対象である24時間連続取引の暗号資産には**概念として存在しない**（prescreen §4.3）。ただしこれは「測る価値がある」ことの根拠であって、「有望である」ことの根拠ではない。

### 1.3 本EXPが賭けているものの正体（prescreen §7.6 の再掲・忘れないこと）

- 文献が報告するオーバーナイト反転は**日中セッションで完結する**ものであり、本プロジェクトのコスト構造はその保有期間を支払えない（prescreen §7.5: 1日保有版は必要グロス0.45%に対し効果量0.07%で**6.4倍不足**＝回す前に却下済み）。
- したがって本EXPは「**その反転の一部が数営業日にわたって残存している**」という文献の外挿に賭けている。
- **文献の存在は本EXPの根拠を補強しない。** 文献が「日中で完結する」と報告していることは、数営業日の残存に対してはむしろ弱い反証である。

### 2.2 「分割する」という判断の根拠（**リターンを一切見ずに、件数のみで行った**）

prescreen 申し送り T-9 は「確認期間だけで T-1 の件数条件を満たすならば分割を行う」と定めている。本 spec は以下の**件数のみの算術**により分割を選択した。

| 量 | 値 | 算出 |
|---|---|---|
| 参照営業日の総数 | 487本 | 実測（`feasibility.json`） |
| 年あたり営業日（本 spec で固定する年換算定数） | **245本/年** | 487 ÷ 2.0年 ≈ 243.5 を保守的に 245 と置く。**以降すべての年換算にこの定数のみを使う** |
| 選定期間のイベント日数 | **173本**（実測） | `T[68]` 〜 2025-06-30 の営業日 183本 − E-2B の一括除外 10本 |

| `z*` 較正の目標イベント件数（§3.6） | **215件/年** | prescreen §4.6 の想定値 |
| 確認期間の期待イベント件数 | 約 **194件** | 215 × 221 ÷ 245 |

- **第2版での改訂**: 第1版はイベント日数を 181本／245本と**推定**していたが、`T` の実測と、`σ_gap` 窓の改訂（開始 `T[62]` → `T[68]`）および E-2B の一括除外を反映して **173本／221本**に改めた。**選定期間の期待件数は 159件 → 152件へ減るが、T-1 の下限 150 を上回るため分割の判断は変わらない。** なお §3.6 の `z*` 較正は**年換算率** `N_ann = 件数 × 245 ÷ イベント日数` を目標215に合わせる手続きであるため、イベント日数の変化は較正によって自動的に吸収される（目標件数そのものは動かしていない）。

## 3. シグナル定義（回す前に数値で確定）

### 3.1 使用する価格（調整の規約）

- ギャップ・`σ_gap`・前方リターン・損益のすべてにおいて、**同一の調整規約で揃えた価格系列を使う。** 生値と調整値を混在させてはならない。
- 株式分割・併合を跨ぐ日の生値ギャップは**株価水準の人為的な段差**であり、これを「下方ギャップ」と誤認すると、**シグナルの最極端側が分割イベントで埋まる**。これは本EXPを構造的に破壊する。
- **B実装チームは §9-2 として、`/equities/bars/daily` の `AdjFactor` / `ExRT` / `Adj*` 系フィールドの正式名称・全ユニーク値・件数・調整の累積規約を実測して出力し、`params.json` に明記すること。** 意味が**一意に決まらない場合は推測で埋めず S に差し戻す**（N-8）。
- 調整規約が確定した上で、以下を**必ず実装する**（二重の安全網）:
  - **E-1（権利落ちの除外）**: `AdjFactor(D) ≠ 1`、または `ExRT` が `D` における権利落ち（分割・併合・権利付最終日翌日等）を示す場合、**その銘柄日 `D` をイベント候補およびプールから除外する**。除外件数を記録する。
  - **E-2（配当落ちの除外）**: `AdjFactor` は配当を調整しない（§9-2a で実測確定）。したがって**配当落ち日の下方段差は本EXPのシグナルに直接混入する。** 日本株の配当落ちは3月末・9月末に極端に集中するため、これは **OBS000029（実質1本張り）の時間方向再発**を直接引き起こす。本 spec は §3.1.1 の**決定的な構成手続き**により配当落ち日を識別し、**E-2A（銘柄別・厳密）と E-2B（暦ベース・一括）の和集合**を除外する

> **この扱いを「記録して先へ進む」にしなかった理由**: 配当落ちは(a)方向が常に下向き、(b)反転しない（理論価格の段差）、(c)暦上2日に極端に集中する、という3条件をすべて満たす。混入した場合の影響は「効果の希釈」ではなく「特定2日への集中と、そこでの確実な負け」であり、バイアスの向きが安全側ではない。EXP-OBS000037 の教訓（曖昧さを安全側と推測しない）を、ここで適用する。

> **「配当分だけ価格を補正して使う」（除外せず調整する）を採らなかった理由**: 理論上の落ち幅は配当全額だが、**実際の落ち幅は配当額の 100% ではない**（源泉徴収 20.315% を含む税制クライアンテレ効果により、実証的な落ち率は 0.7〜1.0 倍の範囲に入る）。補正を行えば「どの落ち率を使うか」という**新しい自由パラメータ**が生じ、かつ残差（≈ 0.15 × 平均配当利回り 1.39% ≈ **0.21%**）は**配当利回りと横断的に相関して残る**。これは `σ_gap` の典型値（約1.2%）の **0.17σ** に相当し、「高配当銘柄が下方ギャップを出して反転しない」という**本EXPが検出したいものと正反対の系統成分**を残す。**除外は規約であり自由度を持たないが、補正は自由度を持つ。** よって除外を採る。

#### 3.1.1 配当落ち日の決定的な構成手続き（§9-2b で検証する）

**識別の原理**: 日本株の配当の権利確定日（基準日）は**会計期間の期末日**であり、これは `/fins/summary` の `CurFYSt` / `CurFYEn` / `CurPerType` / `CurPerEn` から取得できる。実際に配当が支払われたか否かと金額は**実績配当**フィールド `Div1Q` / `Div2Q` / `Div3Q` / `DivFY` から取得できる。除権日そのもののフィールドは存在しないが、**基準日から権利落ち日への写像は 2019-07-16 以降の T+2 決済のもとで一意に決まる**（下記 step 3）。したがって「除権日フィールドが無い」ことは「配当落ちが識別できない」ことを意味しない。

| step | 手続き（**すべて決定的。推定・近似・当てはめを含まない**） |
|---|---|
| **1** | `/fins/summary` の各行について、`CurFYSt`（会計年度開始日）と `CurFYEn`（会計年度末日）を読む。いずれかが空の行は使わない（件数を記録） |
| **2** | 会計四半期末日を**暦月加算**で構成する: `Q1末 = CurFYSt + 3ヶ月 − 1日`、`Q2末 = CurFYSt + 6ヶ月 − 1日`、`Q3末 = CurFYSt + 9ヶ月 − 1日`、`FY末 = CurFYEn`。**暦月加算は日を保存し、月末超過のみクランプする**（例: `CurFYSt = 2023-08-21` ⇒ `Q2末 = 2024-02-21 − 1日 = 2024-02-20`）。基準日 `R` は**暦日**であって営業日ではない |
| **3** | 基準日 `R` を権利落ち日 `X` へ写す: `b(R) :=` **`T` の中で `R` 以下である最大の営業日**、`X :=` **`T` 上で `b(R)` の1営業日前**（＝ `T` の添字を1減じる。暦日で減じてはならない）。`T` に `R` 以下の営業日が無い場合、または `b(R) = T[1]` の場合は構成しない（件数を記録）<br>**根拠（T+2 決済の算術）**: 基準日 `R` に株主名簿に載るには受渡が `b(R)` までに完了する必要があり、`T+2` 決済のもとで権利付最終日 `= b(R) の2営業日前`、その翌営業日である `b(R) の1営業日前` が権利落ち日である |
| **4** | 各四半期の実績配当 `Div1Q` / `Div2Q` / `Div3Q` / `DivFY` を step 2 の対応する期末日に**フィールド名の四半期番号で**結びつける。**開示回の四半期ではなく、会計年度内の四半期に対応する**（例: 3Q短信が `Div2Q = 5.0` を報告する場合、それは中間期末を基準日とする配当である） |
| **5** | **`DPS > 0` のもののみ**を配当落ちとする。`0.0` の明示申告は「配当なし」として除外対象にしない（件数を記録）。同一 `(銘柄, 基準日)` に複数の申告値が現れた場合は**最大値**を採り、その発生件数を記録する |

- **E-2A（銘柄別・厳密）**: step 1〜5 で構成された銘柄日 `(j, X)` を、**イベント候補・プール `P`・`σ_gap` の窓のすべてから除外する。**
- **E-2B（暦ベース・一括）**: 各暦月 `m` について、`T` 内で月 `m` に属する最後の営業日を `L(m)`、その1営業日前を `X(m) := T[idx(L(m)) − 1]` とする。**`X(m)` を全銘柄共通で、イベント候補・プール `P`・`σ_gap` の窓のすべてから除外する。**

> **E-2B を E-2A に加えて置く理由（E-2A だけでは足りない）**: (a) **株主優待・新株予約権無償割当等、配当以外の権利落ち**が同一基準日に同居するが `Div*` には現れない、(b) **配当落ち日には銘柄横断の需給歪み**（配当再投資に伴う先物・現物のフロー、指数の配当落ち調整）が生じ、**配当を出さない銘柄にも及ぶ**ため銘柄別除外では取りこぼす、(c) `/fins/summary` のカバレッジが欠ける銘柄（実測 511 中 1 銘柄）を E-2A は救えない。**E-2B は「配当落ち日という日そのものを測定対象から外す」規約であり、E-2A は「非月末決算期の銘柄」を救う補完である**（実測: E-2A の 1,859 銘柄日のうち **12 件**が E-2B に覆われない＝ `2024-05-15` 期末・`2024-08-20` 期末などの非月末決算会社）。
> **E-2B の副作用（記録必須）**: `T` の末尾が暦月の途中で終わるため、最終月の `X(m)` は真の月末落ち日ではない。ただしこれは**イベント日範囲の上限 `T[481]` より後**にあり実害がない。B実装チームは該当件数を記録すること。

### 3.2 ギャップと正規化（**単一の事前登録定義。これ以外を合否判定に使わない**）

`D = T[i]` を**イベント日**（ギャップが観測される日）とする。

| 記号 | 定義 |
|---|---|
| `g(j,D)` | `ln( O(j, T[i]) / C(j, T[i−1]) )` — **銘柄 `j` の `D` におけるオーバーナイト・ギャップ（対数）** |
| `σ_gap(j,D)` | **有効ギャップちょうど60本**の**標本標準偏差（ddof=1）**（下記「`σ_gap` の窓」を参照） |
| **`z(j,D)`** | **`g(j,D) / σ_gap(j,D)`** — 下方ギャップでは負値 |
| **`S(j,D)`** | **`−z(j,D)`** — 下方ギャップの深さ。**大きいほど深い。** 予測単位の説明変数はこの `S` である |

**`σ_gap` の窓（第2版で改訂。改訂理由は §9-2b の実測にもとづく）**

- **有効ギャップ**とは、`g(j, T[m])` が算出可能（`O(j,T[m])` と `C(j,T[m−1])` がともに存在し正）であり、**かつ `T[m]` が `j` にとって E-1 / E-2A / E-2B の除外日でない**ギャップをいう。
- `σ_gap(j, D)`（`D = T[i]`）は、**`T[i−66]` 〜 `T[i−1]` の範囲にある有効ギャップのうち、新しい順にちょうど60本**を採り、その標本標準偏差（ddof=1）とする。
- **60本に満たない場合はイベント候補から除外する**（§3.4 C-2）。窓長の延長・短縮・「取得できた分での代用」を**禁止する**（N-8）。
- **遡り上限 66 を選んだ根拠（推測ではなく実測）**: 候補511銘柄・全銘柄日について、60本の有効ギャップを集めるのに必要な遡り営業日数 `K` の分布を実測したところ **最大 `K` = 65、`K ≤ 66` でカバー率 100.0000%（取りこぼし 0 件）** であった。66 は「余裕を見た値」ではなく、**実測された最大値 65 に 1 を足した上限**である。

> **なぜ第1版の「直前60本（隣接）」を改めたか（**測定にもとづく改訂であり、結果を見た緩和ではない**）**: 第1版は権利落ちギャップが `σ_gap` の窓に混入することを考慮していなかった。実測すると、**全銘柄日の 49.7% が窓内に権利落ちギャップを含み**、汚染ありの `σ` を除去後の `σ` で割った比の分布は **中央値 1.0033・p90 1.0838・p99 1.2725・最大 2.7873**（2% 超の膨張が 33.0%）であった。中央値では無視できるが、**裾では `σ` が最大 27%（p99）膨張し、`z` を同率だけ圧縮する。** 膨張量は配当利回りと相関するため、これは**高配当銘柄を系統的にイベント集合から押し出す**横断的な選択歪みであり、方向が安全側だと断定できない。**「中央値が小さいから無視してよい」と推測せず、実測して対処する**（N-6 を自分自身に適用）。

**仮説の符号**: `S` が大きいほど前方リターン `R_5` が大きい ⇒ **IC は正**。

**なぜ生の % ではなく `z` を主定義にするか**（C品質チームの検査用・回す前に確定した設計判断）:

1. ユニバースの株価帯は1,000〜3,500円（3.5倍幅）であり、銘柄ごとの日次ボラティリティも大きく異なる。**固定の % 閾値を使うと、イベント集合が系統的に高ボラ銘柄で埋まる。** それは「下方ギャップを取る戦略」ではなく「高ボラ銘柄のロング」であり、**OBS000029（実質1本張り）・OBS000030（ブレッド拡張はエッジ族の枯渇を救わない）と同型化する**。
2. `z` は「その銘柄の平常のギャップ変動に対して何倍か」という、銘柄間で比較可能な尺度を与える。
3. **`σ_gap` による正規化は、単一シグナル（ギャップ）のスケール変換であって、別のシグナルとの合成ではない。** したがって必須条件①／N-1 に抵触しない。ATR・ボリンジャーバンド等の**テクニカル指標は一切使わない**（N-1）。
4. 生の % 版（`g` をそのまま用いる版）は §6.3-7 で**記述統計としてのみ出力**する。**合否判定に使うことを禁止する**（N-10）。

### 3.5 PEAD（EXP-OBS000001）との事象排反性の証明（必須条件⑥）

- PEAD のイベントは `(j, DiscDate)` であり、そのエントリー日は `DiscDate` の翌営業日である。
- 本EXPのイベント日 `D` は、E-3 により `DiscDate ∈ [D−2, D+2]` なる銘柄日をすべて除外している。
- 仮に本EXPの `D` が PEAD のエントリー日と一致したとすると `DiscDate = D−1` であり、これは `[D−2, D+2]` に含まれるから E-3 で除外されている。**矛盾。**
- 同様に、PEAD のイベント日そのもの（`D = DiscDate`）も `[D−2, D+2]` に含まれるため除外されている。
- **∴ 本EXPのイベント集合と PEAD のイベント集合・エントリー日集合は排反である。** B実装チームは、E-3 による除外件数を**銘柄日ベースと `DiscDate` ベースの両方**で出力し、この排反性を実データ上で確認すること（§9-7）。

### 3.6 イベント閾値 `z*` の較正（T-1。**カウントのみを入力とする決定的手続き**）

1. 探索グリッドを**事前に固定する**: `z* ∈ { −1.50, −1.75, −2.00, −2.25, −2.50, −2.75, −3.00, −3.25, −3.50, −3.75, −4.00 }`（0.25刻み・11点）。**グリッドの追加・細分化を禁止する**（N-9）。
2. **選定期間のみ**について、各グリッド点の**候補イベント件数**（§3.4 の C-1〜C-4 と E-1〜E-6 をすべて適用した後の件数）を数える。
3. 年換算件数 `N_ann(z*) = 件数 × 245 ÷ (選定期間のイベント日数)`。**年換算定数は §2.2 で固定した 245 のみを使う。**
4. **`z*` = `|N_ann(z*) − 215|` を最小にするグリッド点。** 同値の場合はより極端側（より負）を採る。
5. `z*` を**凍結**する。確認期間・パイプライン・感度分析のすべてで同じ `z*` を使う。
6. **この手続きに前方リターンは一切入らない。** 入力は銘柄日の件数のみである。

### 3.7 「非決算」の定義の限界（T-7。**安全側だと扱わない**）

- 本EXPが除外できるのは **`/fins/summary` に載る開示（決算短信等）のみ**である。業績予想の修正・自己株式取得・M&A・上方/下方修正を伴わない適時開示は、**TDnetアドオン（¥11,000/月）未契約のため識別できない**（prescreen §3.2）。
- **混入率の条件付き推定は構造的に不可能である。** 理由を数値で示す:
  - 無償の TDnet インデックスの保持期間は約38日であり、自前スナップショットは **2026-08-06〜** しか存在しない。
  - J-Quants Free の日足は 12週遅延により **`T[487] = 2026-06-22`** で終わる。
  - **両者のカレンダーは1日も重複しない。** したがって「極端下方ギャップだった銘柄日に適時開示があったか」を結合して数えることは、本EXPの検証期間については**原理的にできない**。
- **B実装チームが代わりに出力すること**（§9-8。いずれも記述統計であり合否判定に使わない）:
  - (a) TDnet スナップショット（2026-08-06〜、9,361件）を用いた、**確認期間ユニバース175銘柄における非決算適時開示の無条件発生率**（銘柄日あたり）。これは混入率の**下限の目安**にはなるが、極端ギャップ日に条件付けた率ではない。
  - (b) E-3 によりイベント候補から除外された銘柄日の**割合**（＝極端下方ギャップのうち、決算短信で説明がつく割合）。これは「極端ギャップがどの程度ニュース駆動か」の**識別可能な部分**である。
- **バイアスの向きを断定しない。** 未識別ニュース起因のギャップは「反転しないので効果を希釈する（＝安全側）」と考えるのが自然だが、**ニュースへの過剰反応がむしろ強く反転する可能性を排除できない。** trading-app-v2 EXP-OBS000037 の教訓（曖昧さを「安全側だろう」と推測した結果、実際には安全側でなかった）に従い、**本 spec はバイアスの符号を決めない。** C品質チームはこの未確定性を判定文に明記すること。

## 4. 約定モデルの固定

### 4.0 値幅制限フラグ `UL` / `LL` の解釈と約定可否判定関数（**PEAD spec の規約をそのまま流用する**）

**本 spec は `UL` / `LL` を独自に再解釈しない。** `research/EXP-OBS000001/01-spec.md` **§4.0（§4.0.1 意味の確定／§4.0.2 論理的同値性／§4.0.3 パース規則／§4.0.4 判定関数）を本 spec の一部として参照により取り込む。** 要点のみ再掲する（差異があった場合は PEAD spec §4.0 が正）:

```
BUY_BLOCKED(t)  :=  (Vo(t) == 0) or (O(t) is null) or ( UL(t)==1 and O(t) == H(t) )
SELL_BLOCKED(t) :=  (Vo(t) == 0) or (O(t) is null) or ( LL(t)==1 and O(t) == L(t) )
```

- `UL` / `LL` は**価格水準ではなく 0/1 の文字列フラグ**である（`"1"` / `"0"`）。`UL(t)=1` ⇔ その日の高値が制限値幅上限に達した。`LL(t)=1` ⇔ その日の安値が制限値幅下限に達した。
- パース規則: `"1"` → 真、`"0"` / 空文字 / null → 偽。**それ以外の値が1件でも出現したら推測で埋めず S に差し戻す**（N-8）。欠損率が1%を超える場合も差し戻す。
- **JPX 制限値幅表から上限/下限価格を自前で再構成することを禁止する**（PEAD §4.0.4）。
- **方向の非対称性は意図的である**: 買いを阻むのは `UL`、売りを阻むのは `LL` である。**この非対称性を本EXPで反転・変更してはならない。**
- 既知の実測（`feasibility.json` の `9-1b`）: 全245,273行のうち `UL=1` が 185行（0.075%）、`LL=1` が 111行（0.045%）、欠損 0.0%。

> **T-5② との関係（重要・矛盾ではない）**: prescreen T-5② は「`LL` に始値が接している銘柄は約定不能として除外」と要求している。一方 PEAD §4.0.4 の規約では、ストップ安寄り付きは**買い注文を阻まない**（売り手過多のため買いは約定する）。本 spec は両者を次のように整理し、**どちらも歪めない**:
> - **約定可否そのもの**は §4.0.4 の2式のみで判定する（規約を変更しない）。
> - **その上で、本EXP固有の事前登録された追加除外**として、`LL(t_1)=1 かつ O(t_1)=L(t_1)` のイベントを**見送る**（§4.1 の E-8）。理由は約定可否ではなく、**(a) 始値が自由な市場清算価格ではない、(b) 特別気配による寄付遅延で「始値で買えた」という前提が検証不能**という測定上の理由である。
> - 両者を**別の項目として件数を分けて記録する**（§6.5 P-2 / P-2d）。

### 4.1 エントリー（**先読みを構造的に排除する**）

- **エントリーは `D` の翌営業日 `t_1 = T[i+1]` の始値 `O(t_1)` に固定する。**
- **`O(D)` でのエントリーを禁止する（N-4）。** `g(j,D)` は `O(D)` そのものから計算される量であり、`O(D)` で約定できると仮定することは「板寄せの清算価格を、その板寄せに注文を出す前に知っている」ことを意味する。**これは近似ではなく明確な先読みである。**
- 約定価格 = `O(t_1) × (1 + s)`、`s` = 買い片道スリッページ（中心ケース **0.100%**。§8.1）。
- 以下のいずれかに該当する場合は**約定不能として見送る**（翌日以降の再エントリーを行わない）。**件数と内訳を必ず分けて記録する**:
  - **E-7**: `BUY_BLOCKED(t_1)` が真（内訳3分類: `Vo(t_1)=0` / `O(t_1)` が null / `UL(t_1)=1 かつ O(t_1)=H(t_1)`）
  - **E-8**: `LL(t_1)=1 かつ O(t_1)=L(t_1)`（ストップ安寄り付き。§4.0 の但し書き）
  - **E-9**: §5.3 のリスク集中上限・単元離散化により建てられなかった（スロット競合。E-7/E-8 とは別カウント）
- 参考値として `UL(t_1)=1 だが O(t_1)<H(t_1)` で約定したとみなした件数、`LL(t_1)=1 だが O(t_1)>L(t_1)` で約定したとみなした件数も記録する（判定には使わない）。

**エントリーを `t_1` に置くことの代償（正直に記す）**: 文献が報告する反転の大部分は `D` の日中セッションで起きるとされる（prescreen §7.5）。`t_1` 始値エントリーは**その部分を構造的に捨てる**。すなわち本 spec の設計は文献の効果に対して**厳しい側に倒れている**。これは意図的であり、**この厳しさを理由にエントリー日を `D` に変更することを禁止する**（N-4。物理的に不可能であるため、そもそも代替設計ではない）。

### 4.2 予測単位（G1）の前方リターン

- **`R_5(j,D) = C(j, t_5) / O(j, t_1) − 1`**（**グロス**。コスト・スリッページを一切引かない）。`t_k = T[i+k]`。
- 前方窓が確保できないイベント（`i > 482`）は G1 から**除外**し、件数を記録する（§2.4）。
- `t_1` が取れないイベント（E-7 / E-8）は G1 から除外する。**ただし G1 は「取引可能性」ではなく「予測力」の検定であるため、除外した場合と `O(t_1)` を用いて仮想的に含めた場合の両方の `IC_bar` を出力すること**（主判定は除外版）。PEAD §4.2 と同じ扱い。
- **市場超過リターン**: `R_5^excess(j,D) = R_5(j,D) − (同一カレンダー窓 `t_1`〜`t_5` におけるユニバース全銘柄の等加重平均 `R_5`)`。TOPIX 日足が現行契約で取得不可（HTTP 403）であるため、ユニバース等加重平均を市場プロキシとする（PEAD §6.3 と同一）。
- **セクター中立リターン**: `R_5(j,D) − (同一 `S33` 業種のユニバース構成銘柄の等加重平均 `R_5` over 同一窓)`。**生データであり合否判定に使わない。**

> **注（回す前に確定しておく数学的事実）**: 同一イベント日 `D` に属する観測はすべて同一のカレンダー窓 `t_1`〜`t_5` を持つ（欠損営業日率 0.0% の実測による）。したがって市場プロキシの減算は**日内で定数**であり、**日内 Spearman 順位相関を変化させない。** §6.1 の `IC_bar` は `R_5` でも `R_5^excess` でも同値である。B実装チームは `R_5^excess` を用い、同値性を数値で確認して `prediction-unit.json` に出力すること（食い違ったら S に差し戻す）。

### 4.3 決済ルール（トレーリングストップ。PJ000001 C-1 決着／司令塔判断3 に準拠）

| 1 | **初期損切幅** | エントリー約定価格の **−4.0%（固定値）** | prescreen §7.2。**ATR連動にしない**（ATR はテクニカル指標であり必須条件①／N-1 に抵触する。加えて新しい乗数パラメータと第2のルックバック窓を導入し EXP-OBS000037 型の曖昧さを増やす）。prescreen §7.2 が「下方ギャップ銘柄は −2.0% では即座に刈られる」として −4.0% を要求した水準をそのまま採る |

### 4.4 決済できない場合（値幅制限の模擬）

- 手仕舞い日 `t_exit` について **`SELL_BLOCKED(t_exit)` が真の場合、約定できず持ち越し**とする。
- 持ち越し中は、その後の各営業日 `t` について `SELL_BLOCKED(t)` を同じ式で再評価し、偽となった最初の営業日の始値で約定する。その間の下落はすべて損失として計上する。
- **最大5営業日**持ち越しても約定できない場合、5営業日目の終値で強制的に評価損益を確定し、「強制評価」としてフラグを立てて件数を記録する。
- 本ルールは、初期損切・トレール抵触・最大保有超過（`t_6` 始値）・§7 D項の決算跨ぎ回避・§5.3-10 のサーキットブレーカー清算を含む、**すべての売り約定に一律に適用する。**
- 内訳を3分類で記録する（`Vo=0` / `O` が null / `LL=1 かつ O=L`）。参考値として `LL=1 だが O>L` で約定したとみなした件数も記録する。
- **`UL(t_exit)=1`（ストップ高）は売り約定を妨げない。**

- **`σ_gap` の窓について「取得できた分で代用する」「窓長を短縮する」「遡り上限 66 を延ばす」ことを禁止する。** 有効ギャップ60本ちょうどが `T[i−66]`〜`T[i−1]` の範囲に収まらない場合は**イベント候補から除外**する（§3.4 C-2）。窓長・上限の変更が必要と考えた場合は S に差し戻す（N-8）。
- **「60本」は常にギャップの本数を指し、営業日数でも価格点数でもない。** 採用した60本は隣接とは限らないため、**「60本のギャップ ⇔ 終値61個」という第1版の対応関係は第2版では成立しない**（隣接の場合にのみ成立した特殊ケースであった）。正しい対応は **60本 ⇔ 始値60個 ＋ 終値60個** である。**この対応関係を実装者が独自に読み替えてはならない**（T-8。EXP-OBS000037 で窓長が独自解釈された経路そのもの）。

### 4.6 寄付の約定モデルの妥当性は日足では検証できない（T-5④。**必ず明記して申し送る**）

- 本EXPは「板寄せの始値で、目標建玉25万円を、片道0.10%のスリッページで買える」という前提に全面的に依拠する。
- しかし **(a) 自分の成行注文は板寄せの清算価格の形成に参加する、(b) 極端ギャップ銘柄は板が薄い、(c) 特別気配により寄付が遅延する**という3点は、**日足データからは原理的に測定できない**（prescreen §4.4）。
- **したがって G1・G2 の合格は「日足上では成立する」ことしか意味しない。** 本EXPの採用可否に対し、**STEP3 フォワード較正における寄付約定の実測（想定約定価格と実約定価格の乖離分布）を必須条件とする。** C品質チームは、G1・G2 が合格した場合でも判定文にこの条件を明記すること。

### 6.1 G1 主検定（必須条件④・T-2）

#### 6.1.1 測定母集団

- **プール `P`**（連続値IC・デシル分析の母集団）: §3.4 の C-1〜C-3・E-1〜E-6 をすべて満たし、**`z ≤ −1.5`** を満たす銘柄日。**`−1.5` は回す前に固定した値であり、結果を見て動かさない**（N-9）。
- **イベント集合 `E`**（水準検定・パイプラインの母集団）: プールのうち **`z ≤ z*`**（§3.6 で較正・凍結）を満たすもの。`E ⊆ P` である。

> **なぜ母集団を2段にするか**: T-2 は「主指標は閾値ではなく `z` の連続値に対する Spearman IC」と要求する（OBS000018 対策）。一方で必須条件⑤は「実際に建てる集合のグロス平均 ≥ 0.45%」を要求する。前者は**プール全体での単調性**を、後者は**イベント集合での水準**を問うものであり、母集団が異なるのは設計上必然である。両者を同時に課すことで、「閾値を1点に決め打ちしたら偶然良かった」（OBS000018 の蜃気楼）と「単調ではあるが水準が経済的に足りない」の**両方を落とす**。

#### 6.1.2 主指標: イベント日内クロスセクション Spearman 順位相関の等加重平均（`IC_bar`）

1. 確認期間の各イベント日 `d` について、その日にプール観測を持つ銘柄群の **`S`（＝`−z`）と `R_5^excess`（§4.2）の Spearman 順位相関 `IC_d`** を算出する。タイは平均順位で処理する。
2. **1日あたりのプール観測数が5件未満の日は `IC_bar` の算出から除外**する（除外日数・除外観測数を記録）。残った日数が **`K`（＝DS-6 の計数対象と同一の量）**である。**両者が食い違う場合は S に差し戻す。**
3. **`IC_bar` = 対象日の `IC_d` の単純平均**（日を等加重。観測数の多い日に引っ張られないようにする）。
4. **有意性検定 = イベント日ブロック内 permutation**:
   - 帰無仮説: 「同一日の銘柄間で、`S` の順位は前方リターンの順位を説明しない」
   - 手続き: **同一イベント日ブロックの内部でのみ `S` をシャッフル**し（ブロック間の入れ替えは行わない）、`IC_bar` を再計算する。**10,000回**繰り返す。
   - 乱数シード: **20260914**（固定。変更禁止）
   - 片側 p 値 = ( 1 + #{ `IC_bar_perm` ≥ `IC_bar_obs` } ) / ( 1 + 10,000 )
   - **日内でのみ並べ替えることにより、同日の銘柄が共有するマクロ・市場全体の共通要因が p 値を過小評価させる問題を構造的に排除する**（本EXPは市場急落日にイベントが集中するため、この配慮は PEAD 以上に重要である）。

#### 6.1.3 水準検定（G1-3 の統計量。**p 値は報告するが合否ゲートにはしない**）

1. 確認期間の各イベント日 `d` について、その日のイベント集合 `E` の `R_5^excess` の**等加重平均** `M_d` を算出する。
2. **`M_bar` = 対象日の `M_d` の単純平均**（日を等加重）。対象日数は `K_event`（＝DS-5）。
3. **ラベル permutation**: 各イベント日 `d` について、その日に `t_1`〜`t_5` が確保できるユニバース銘柄の中から `k_d` 銘柄（＝その日の実イベント数）を**無作為抽出**して仮イベント集合とし、`M_bar` を再計算する。**10,000回**、シード **20260914**。
4. 片側 p 値を報告する。**この p 値は G1 の合否ゲートではない**（理由は §6.1.4 の検出力開示）。

#### 6.1.4 検出力の事前開示（MDE。**基準を緩める根拠にも結果を解釈し直す根拠にも使ってはならない**）

**(a) `IC_bar`（G1-1）**

- プールをユニバースの約6%（175銘柄 × 6% ≈ 10.5銘柄/日）と仮定し `n_d ≈ 10`。`SD(IC_d) ≈ 1/√(n_d − 1) ≈ 0.333`。
- 想定 `K ≈ 180日` ⇒ `SE(IC_bar) ≈ 0.333/√180 ≈ 0.0248` ⇒ **MDE ≈ 1.645 × 0.0248 ≈ 0.041**
- DS-6 の下限 `K = 100日` でも ⇒ `SE ≈ 0.0333` ⇒ **MDE ≈ 0.055**
- **PEAD の実測 MDE（0.11〜0.13）の半分以下であり、本EXPの検出力は本プロジェクトで最も高い**（prescreen §8.1-2）。**したがって本EXPが G1 未達となった場合、それは「検出力が足りない」ではなく「エッジが無い」証拠として `portfolio-ledger.md` に不採用で記録できる。** これは本EXPの主要な価値の1つである。

**(b) 水準 `M_bar`（G1-3 の統計量）**

- 1イベントあたり `R_5^excess` の標準偏差を **4.0%** と仮定（5営業日の個別株リターン σ ≈ 日次2.0%×√5 = 4.47% から市場成分を除いた概算）。
- 1日あたりイベント数 `k_d ≈ 2.5` ⇒ 日次平均の SD ≈ `4.0/√2.5 ≈ 2.53%`
- 想定 `K_event ≈ 120日` ⇒ `SE ≈ 2.53/√120 ≈ 0.231%` ⇒ **MDE ≈ 0.38%**
- DS-5 の下限 `K_event = 80日` ⇒ `SE ≈ 0.283%` ⇒ **MDE ≈ 0.47%**
- **⇒ ゲート下限では、検出可能な最小効果（0.47%）が経済的に必要な最小効果（0.45%）をわずかに上回る。** すなわち**損益分岐ぎりぎりのエッジは統計的に検出できない。** この限界を**回す前に受け入れる。**
- **この開示が G1-3 を「点推定の閾値」として設計した理由である。** 水準に有意性を要求すると、経済的に必要な水準と統計的に検出可能な水準がほぼ一致してしまい、ゲートが二重になって検出力をさらに削る。必須条件⑤が求めているのは「統計的に有意でも 0.45% 未満なら不採用」であって「0.45% 以上かつ有意」ではない。

- **B実装チームは実測の `K` / `K_event` / `n_d` / `k_d` / permutation 帰無分布の標準偏差を出力すること**（C品質チームが実測 MDE を再計算できるようにするため）。

| **G1-5** | プール内**デシル単調性**（§6.3） | **`S` のデシル番号とデシル平均 `R_5^excess` の Spearman 順位相関 `ρ_dec` ≥ +0.30** |
| **G1-6** | 選定期間のイベント集合 `E` の `R_5` グロス平均 | **> 0**（符号一致。水準は問わない） |
| **G1-7** | **単日依存性の除去**（第2版で新設）。確認期間から**イベント件数が最大の1日を丸ごと除いて** `IC_bar` と `R_5` グロス平均を再計算する | **`IC_bar` の符号が正のまま かつ `R_5` グロス平均が > 0**（水準・有意性は問わない） |

**G1-1 〜 G1-7 のいずれか1つでも未達なら G1 不合格とし、G2 以降は測定しない**（PJ000001 §5.3・N-12）。

> **G1-7 を必須にする理由（OBS000029 対策の核心・第2版で追加）**: 本EXPのイベントは市場全体のストレス日に構造的に集中する（S の実測では `z* = −2.5` で単日 `2025-04-07` が候補イベントの 10.7%、上位3日で 27%）。`IC_bar` の日等加重と §5.3 の1日2件上限は集中を**緩和**するが、**「合格が単一日の出来事に依存していないこと」を直接証明はしない。** G1-7 はそれを直接検定する。**除く日は「結果が悪くなる日」ではなく「イベント件数が最大の日」であり、リターンを見ずに一意に決まる**（HARKing の余地がない）。

> **G1-5 を必須にする理由（OBS000018 対策の核心）**: `S` が深いほどリターンが大きい、という単調性が無いのに `z*` という1点だけで水準が出ている場合、その閾値は**蜃気楼**である。prescreen T-2 はこれを「単調でなければ、統計的有意性にかかわらず不採用」と明記している。**本 spec はそれを G1-5 として数値でゲート化した。**

### 6.3 デシル分析・記述統計（必須出力）

1. **デシル**: プール `P` の観測を `S` の昇順で10分割し、各デシルの `R_5`（グロス）・`R_5^excess`・`R_5` セクター中立の**平均・中央値・件数・標準偏差**を出力する。`ρ_dec`（G1-5）を算出する。
2. **イベント日の集中度（OBS000029 診断）**: 1日あたりイベント数の度数分布、最大値、上位10日のイベント日と件数、**確認期間の総 `R_5` 合計に対する上位3イベント日の寄与率**。
3. **セクター分布**: イベントの `S33` 別件数と平均 `R_5^excess`。
4. **閾値スイープ（T-2・記述統計）**: `z ≤ −1.5 / −2.0 / −2.5 / −3.0 / −3.5` および `z*` の各閾値での件数・`R_5` グロス平均・`R_5^excess` 平均。**合否は `z*`（事前固定）のみで判定し、他の閾値の結果を合格根拠にしてはならない**（N-10）。
5. **レジーム別分解（要）**: 確認期間を四半期ごとに分けたリターン、および市場プロキシの当日リターンの符号別（市場下落日 / 上昇日）のリターン。**部分集合の好成績を全体の合格根拠にしてはならない**（OBS000038・N-10）。
6. **取引時間変更（B-5）の前後別**: 2024-11-05 より前 / 以後で、`g` と `σ_gap` の記述統計、イベント件数を分けて出力する。
7. **生の % 版（記述統計）**: `z` の代わりに `g` をそのまま用いた場合の閾値別件数・平均リターン。**合否判定に使うことを禁止**（N-10）。
8. **ホライズン SA**: H = 3 / 10 の `IC_bar`・デシル平均。**合否判定に使うことを禁止**（N-10）。
9. **ギャップの内訳（記述統計のみ・判定に使わない）**: イベント集合について、`C(D)/O(D) − 1`（`D` の日中セッションのリターン）と `O(t_1)/C(D) − 1`（`D` → `t_1` のギャップ）を出力する。**これは本 spec が構造的に捨てている部分の大きさを C品質チームが把握するための解剖情報であり、「`O(D)` でエントリーできていれば」という反実仮想を合否・採否の根拠にすることを明確に禁止する**（N-4・N-10）。

  - **選定期間の開始を `T[62]` としたのは、`σ_gap` の60本窓（終値61個・始値60個）と U-4 の60営業日窓が同時に要求する算術的帰結である**（§2.1・§4.5）。その代償として、契約2年で唯一のテール局面（2024年8月急落）が選定・確認のどちらの窓にも入らないことを B-1 として明記した。
  - **本 spec で prescreen から追加・厳格化した点**（いずれも緩める方向ではない）: ① **権利落ち・配当落ちの除外（E-1/E-2）を新設し、確定できない場合は実験を回さず差し戻す**ことを K-6 に規定（配当落ちは 3月末・9月末に集中し、方向が常に下向きで反転しないため、混入は安全側に働かない）、② **T-10 のコスト感度を G2-7 として合否ゲート化**（0.60% で損益分岐を割るなら中心ケース合格でも不合格）、③ **T-2 のデシル単調性を G1-5 として合否ゲート化**（`ρ_dec ≥ +0.30`）、④ **同一イベント日の新規建て上限を prescreen の例示 3件から 2件へ厳格化**（OBS000029 の時間方向再発の防止）、⑤ prescreen §7.2 の必要勝率 55.6% に**翌営業日始値約定ギャップ 0.30% を織り込んで 59.4% へ再計算**（§8.3）。
  - **司令塔判断事項 D-6（PEAD 確認窓との重複）・D-7（配当落ち識別が不能だった場合）**を新設した。
