## 1. 仮説（1文）

**週次の信用倍率変化（`ΔM_w(j) = LongVol_w(j)/ShrtVol_w(j) − LongVol_{w'}(j)/ShrtVol_{w'}(j)`）が正に大きい（信用買い残が信用売り残に対して相対的に積み上がった）銘柄ほど、公表から一定の遅延を置いた後の5営業日株価リターンは、日本株TOPIX500相当ユニバースにおいて、統計的に有意かつ経済的に意味のある大きさで負に偏る。**

### 1.1 エッジ族の宣言

- 予測変数の生成過程: **信用取引残高（`LongVol`・`ShrtVol`という株数）のみ**。価格・出来高・ボラティリティを一切入力にしない。
- したがってPJ000001 §4 C-3が低事前確率とした「価格由来の特徴量から方向を予測する」族には属さない。
- **ただしPEAD（EXP-OBS000005）と同様、本EXPも「イベント後の一方向的な継続」という出力形を取る点で、価格由来のトレンドフォロー戦略と表面上似た統計的挙動を示しうる。この区別が本質的でなかった場合、本EXPも同じ天井に当たる可能性がある。この可能性はspec段階では排除できず、G1の結果で判定する。**

### 1.2 事前確率の見立て

**低〜中。** PEAD・ギャップがいずれもG1でKillされ、本PJの非価格系スリーブ在庫がゼロに戻った状況下での3件目の非価格系候補である。制度信用の返済期限という制度構造は演繹的に筋が通っているが、**日本株における信用取引残高の方向予測力について、一次文献による確認は本spec作成時点で行っていない**。文献の不在・存在いずれをも根拠に基準を緩めたり厳しくしたりしない。

## 3. シグナル定義

### 4.2 値幅制限フラグの解釈（PEAD/ギャップと同一の判定式を再利用）


### 4.3 予測単位（G1）の前方リターン（**第2版で計算式を改訂。§4.3.1参照**）

**`R_5 = AdjC(T[k+9]) / AdjO(T[k+4]) − 1`**（グロス。コスト・スリッページを一切引かない）。**ポジションを取らない純粋な統計量であり、`BUY_BLOCKED`/`SELL_BLOCKED`による約定可否はG1には適用しない**（G1はPJ000001の定義どおり「手数料ゼロのグロス段階」の測定であり、執行可能性はG2で扱う）。

`AdjO`/`AdjC`は`data/raw/pead/bars_daily/{code}.json`に既存フィールドとして格納されている、J-Quantsが提供する分割・併合調整後の始値・終値である（第1版で使っていた生値`O`/`C`から変更）。**この変更は§9-9で検出された分割・併合汚染への対処であり、変更理由・妥当性の論証は§4.3.1に記録する。**

#### 4.3.1 なぜ`Adj`系列への変更が汚染除去として妥当か（§9-9への対応・回す前の判断）

**背景**: §9-9（B実装チーム実測）で、確認期間681件・選定期間624件の`(code, 週)`ペアの前方窓`[T[k+1], T[k+19]]`に`AdjFactor≠1`の行（分割・併合）が含まれることが判明した。生値`O`/`C`でこれらのペアの`R_5`を計算すると、分割・併合による機械的な価格の段差がそのままリターンに混入し、デシル平均を単独で支配しうる外れ値になる（EXP-OBS000005 §9-10と同型の懸念）。

**選ばなかった案（(a) 機械的除外）を採らなかった理由**: 汚染ペアをG1のサンプルから除外する案も検討したが、以下の理由で見送った。
1. **除外対象がリターンと無相関である保証がない。** 株式分割は一般に株価上昇後に実施される傾向が知られており（分割自体は`ΔM`から独立な決定だが、分割を行う銘柄・時期の選ばれ方は市場全体の値動きと無関係ではありうる）、「分割・併合が前方窓に入った銘柄週を除外する」という操作は、結果として`R_5`の分布と何らかの形で相関した部分集合を除去することになりかねない。これは客観的基準（分割の有無）による除外ではあるが、**除外後の残存サンプルの`R_5`分布が系統的に偏る可能性を否定できない**。
2. **サンプルを失う。** 選定624件・確認681件（全体の0.46〜0.52%）は少量だが、除外は`K_eff`（G1-1bゲート）にも波及しうる。

**選んだ案（(b) `Adj`系列への置換）を採る理由**:
1. **`AdjFactor=1`の行（全体の99.5%超）では`AdjO=O`・`AdjC=C`が数値的に完全一致する**（`data/raw/pead/bars_daily/13320.json`のサンプル行で確認済み: `AdjFactor=1.0`のとき`AdjO=O=435.0`・`AdjC=C=436.0`）。したがって**この変更は非汚染観測に一切影響を与えず、汚染観測のみを是正する**。除外とは異なり、選定・確認いずれのサンプル数も一切変化しない（DS-1〜DS-6・`K=250`・G1-1bの`K_eff`計算対象は不変）。
2. **窓の外側の分割・併合はリターン比の計算上、自動的に相殺される。** `AdjO`/`AdjC`は「現在時点の株数基準に揃えるための累積調整後」の値であり、`[T[k+4], T[k+9]]`の外側で起きた分割・併合（過去分・将来分いずれも）は分子・分母の両方に同じ累積係数として乗じられるため、比を取ると相殺される。実際に検証した: 銘柄24920（`AdjFactor=0.5`の分割が2016-12-28に発生）について、`AdjO`/`O`の比は分割前（2016-12-27時点）で4.0、分割直後（2016-12-29時点）で2.0であり、**分割前後で単独の値は変化するが、比率計算では窓内の分割のみが正味の影響を持つ**ことを数値的に確認した。窓の外側で起きた別の分割（同銘柄は2016-12-29〜2021-09-01の間にもう1回、比率が2.0→1.0になる分割を経験している）は、両端の日付に等しく乗じられるため相殺され、`R_5`の値を歪めない。**したがって将来（クエリ時点）に確定した調整係数を使うことは先読みバイアスにならない**——ここで問題になりうる「将来情報の混入」は、window内で発生した分割・併合という、まさにその5〜9営業日の保有期間中に実際に起きた事象の効果を正しく反映することであり、これはリターンの定義上必要な補正である。
3. **本PJで実測済みの信頼性**: `AdjFactor`/`ExRT`/`Adj*`系フィールドの整合性は、同一の生データキャッシュ（`data/raw/pead/bars_daily/`）に対しEXP-OBS000006 §9-2/§9-3で既に検証済みである（`AdjFactor≠1`の全387行が`is_split_merger_row()`で捕捉・`ExRT`との対応105/105一致・価格比`C(t)/C(t−1)÷AdjFactor`が105/105件で≒1.0）。本EXPの候補554銘柄はこの同一キャッシュの部分集合であり、新規にデータを取得し直すものではない。
4. **具体的な補正効果を実測で確認した**（S戦略チーム自身の検証。リターンとΔMの相関には一切触れていない）: 銘柄24920（2016-12-27→2016-12-29、分割を跨ぐ）について、生値では`C(T[k+9])/O(T[k+4])−1 = −49.41%`という機械的な外れ値になるが、`AdjC`/`AdjO`ベースでは`+1.18%`という妥当な値になる。

**B実装チームへの追加要求（§9-9bとして新設。下記§9参照）**: `Adj`系列を信頼する前に、本EXPの候補554銘柄の部分集合について、EXP-OBS000006 §9-3のV-6と同型の適合性検査（`AdjFactor≠1`の全行が`is_split_merger_row()`で捕捉されること等）を再実行し、0件の不整合であることを確認する。**もし不整合が1件でも見つかった場合は、その特定の`(code, week)`ペアに限り(a)の機械的除外を適用し、他は(b)のまま扱う**（部分的フォールバック。全体設計をやり直す必要はない）。

### 4.4 G2の約定モデル（**長短両建て。ショート脚は本PJで初めて必要になる規則**）

デシル1（`ΔM`最小＝将来上昇を予測）を**ロング**、デシル10（`ΔM`最大＝将来下落を予測）を**ショート**とする、市場中立の長短ポートフォリオ。

#### 4.4.1 ロング脚（デシル1）

| # | パラメータ | 固定値 |
|---|---|---|
| 1 | エントリー | `t_1=T[k+4]`の始値。`BUY_BLOCKED(t_1)`なら見送り |
| 2 | 初期損切幅 | エントリー価格の**−3.0%** |
| 3 | トレール発動水準 | 終値ベースの含み益が**+4.0%**以上に到達した日の翌営業日から有効 |
| 4 | 追随幅 | 発動後、日次終値の最高値から**−2.0%** |
| 5 | 決済判定 | `SELL_BLOCKED(t_exit)`なら約定不能・持ち越し（最大5営業日、超過時は5営業日目終値で強制評価） |
| 6 | 最大保有 | 10営業日（`t_10`終値時点で未決済なら`t_11`始値で強制手仕舞い） |

#### 4.4.2 ショート脚（デシル10・PJ本PJ初のショート約定モデル）

ロング脚のすべてのパラメータを**符号鏡像**で適用する。

| # | パラメータ | 固定値（ロング脚との対応） |
|---|---|---|
| 1 | エントリー（空売り建て） | `t_1=T[k+4]`の始値。**`SELL_BLOCKED(t_1)`なら見送り**（空売りは「売る」行為であり、ロングのエントリー〈買う〉ではなく決済〈売る〉と同じ値幅制限が適用される） |
| 2 | 初期損切幅 | エントリー価格の**+3.0%**（価格上昇＝ショートにとって不利） |
| 3 | トレール発動水準 | 終値ベースの含み益（価格下落）が**−4.0%**以上に到達した日の翌営業日から有効 |
| 4 | 追随幅 | 発動後、日次終値の**最安値**から**+2.0%**（価格が最安値から+2.0%戻したら手仕舞い） |
| 5 | 決済判定（買い戻し） | **`BUY_BLOCKED(t_exit)`なら約定不能・持ち越し**（買い戻すために「買う」行為であり、ロングのエントリーと同じ値幅制限が適用される。最大5営業日、超過時は5営業日目終値で強制評価） |
| 6 | 最大保有 | 10営業日（`t_10`終値時点で未決済なら`t_11`始値で強制買い戻し） |

**この鏡像対応（エントリー=SELL_BLOCKED判定・決済=BUY_BLOCKED判定）は、既存の`BUY_BLOCKED`/`SELL_BLOCKED`定義を「売買方向」ではなく「売り注文か買い注文か」で解釈することにより、新しい判定式を1つも追加せずに導出される。** ロングのエントリー（買い注文）とショートの決済（買い戻し注文）は同じ`BUY_BLOCKED`、ロングの決済（売り注文）とショートのエントリー（空売り注文）は同じ`SELL_BLOCKED`を使う。

### 4.5 決済できない場合（値幅制限の模擬。ロング・ショート共通の一般規則）

該当する`BLOCKED`条件が真なら約定できず持ち越し。以降の各営業日で再評価し、偽となった最初の営業日の始値で約定する。その間の含み損益はすべて損失として計上する。最大5営業日持ち越しても約定できない場合、5営業日目の終値で強制的に評価損益を確定し「強制評価」として件数を記録する。

### 4.6 分割・併合が前方窓に含まれるイベントの除外（**G2専用・第2版で新設**）

**G1（§4.3）とは異なり、G2は実際の約定価格（生値`O`/`H`/`L`/`C`）を使う執行シミュレーションであり、トレーリングストップ・損切幅・建玉サイジングはすべて日々の生値の水準（％乖離）に依存する。分割・併合が保有期間中に発生すると、株数・値幅制限・証拠金の実務上の扱いが本specの単純なモデルでは正しく再現できない**（例: 分割による見かけの−50%が損切トリガーを誤発火させる、単元株数の変更で実効ポジションサイズの計算が破綻する等）。したがって**G2では、既存の「決算跨ぎ制約」（§7 D項）と同じ設計思想を分割・併合にも拡張し、該当ペアを機械的に除外する**。

**除外規則（機械的・客観的基準のみ。結果を見て設計していない）**:

```
CorporateActionWindow(w, j) := { T[k+1], T[k+2], …, T[k+19] }  （k := idx_T(W[w])。19本の営業日、両端含む）
```

銘柄`j`・週`w`について、`CorporateActionWindow(w,j)`内のいずれかの日に`AdjFactor(j, ·) ≠ 1`の行が存在する場合、当該`(code, week)`ペアはG2のロング脚・ショート脚の対象から**除外**する（エントリーを見送る。`BUY_BLOCKED`/`SELL_BLOCKED`とは別カテゴリの新規区分`CORPORATE_ACTION_SKIPPED`として件数を記録する）。

- **窓の範囲は§9-9（改訂後）の検査窓と同一の`[T[k+1], T[k+19]]`とする**（`t_1=T[k+4]`からではなく`k+1`から。理由: エントリー直前の分割・併合も実務上の連続性を損なうため、安全側に広く取る）。
- **この除外により、G2の残存サンプルの前方窓には分割・併合が一切含まれなくなる。** したがって、除外後のG2実行では生値`O`/`H`/`L`/`C`をそのまま使ってよく、G2の約定モデル（§4.4）・トレーリングストップ・損益計算を`Adj`系列に置き換える必要はない（構造的に不要になる）。
- **除外件数（銘柄別・週別）は`feasibility.json`または`pipeline.json`に必ず記録する。** G2-5（実約定トレード数≥30件）・G2-6（約定不能率≤50%）の算出時、`CORPORATE_ACTION_SKIPPED`は分母（対象ペア数）に含めるが、既存の`BUY_BLOCKED`/`SELL_BLOCKED`とは区別してカウントする（原因の切り分けのため）。
- **除外率が§9-9の実測（選定0.46%・確認0.52%程度）から大きく乖離した場合（例: 候補集合再構成やユニバース条件の違いにより10倍以上に増える等）は、除外という設計選択の妥当性を再検討する必要があるためSに差し戻す**（機械的に決まる想定件数からの乖離は実装ミスの兆候であり、結果の良し悪しとは無関係の整合性チェックである）。

### 6.1 G1主検定

**主指標: 週内クロスセクションSpearman順位相関の等加重平均（`IC_bar`）**

1. 確認期間の各週`w`について、その週に有効`ΔM_w`を持つ銘柄群の`ΔM_w`と`R_5`の**Spearman順位相関`IC_w`**を算出する。タイは平均順位で処理する。
2. **1週あたりの有効銘柄数が5未満の週は`IC_bar`の算出から除外**する（除外週数・除外銘柄数を記録）。残った週数が`K`（DS-2/C7-1と同一の量）。
3. **`IC_bar` = 対象週の`IC_w`の単純平均**（週を等加重）。
4. **有意性検定 = 週内permutation**: 同一週ブロックの内部でのみ`ΔM_w`をシャッフルし`IC_bar`を再計算。**10,000回**。**乱数シード = 20260917**（固定・変更禁止）。**片側p値**（`IC_bar`が観測値以下に出た比率。**仮説は負の相関を予測するため、帰無分布より観測値が小さい側を検定する**）= `(1 + #{IC_bar_perm ≤ IC_bar_obs}) / (1 + 10,000)`。
5. **`K_eff`の算出（`00-prescreen.md` §6.1で規則を凍結済み）**: `IC_w`系列（週次時系列）のラグ1〜`L`自己相関`ρ_l`を算出し、`L = floor(4 × (K/100)^(2/9))`（Newey-West自動帯域幅）。`K_eff := K / (1 + 2×Σ_{l=1}^{L}(1−l/L)×ρ_l)`。
