## 1. 継承する凍結事項（**1文字も変更しない**）

### 1.1 符号仮説（EXP-OBS000007 §2.1 で回す前に固定済み・変更禁止）

> **`M`（信用倍率）が高い、または上昇するほど、将来の n 営業日リターンは負の方向に偏る。**

## 3. 分割規則（**測定の前に凍結**）

**`m_w := floor(N_w / 2)`**（EXP-OBS000005/006と同じ時系列50/50。理由も同一——自由度ゼロ・確認期間の最大化・選定期間で選ぶパラメータが存在しない・時系列順）。

### 3.1 前方窓の算術的整合性（**T-8・trading-app-v2 EXP-OBS000037の教訓を週次シグナルに適用**）

週次シグナルのイベント（＝週`w`の基準日 `W[w]`）を起点とする前方窓を、**「本数」と「対象となる`T`の添字」の対応関係を明記して**定義する。

| # | 用語 | 定義 | `T`上の添字（`W[w]`の`T`内位置を`k = idx_T(W[w])`とする） |
|---|---|---|---|
| P-1 | 公表可能日（PIT availability） | `W[w]` の**3営業日後**（§4.2で確定する理由付きバッファ） | `T[k+3]` |
| P-2 | エントリー日 `t_1` | 公表可能日の**翌営業日**（16:30頃の公表を跨いで初めて売買可能になる日）の始値 | `T[k+4]` |
| P-3 | 予測単位の前方リターン `R_H`（H=5営業日） | `t_1`〜`t_5`の**ホライズン5本**。`R_5 = C(T[k+9]) / O(T[k+4]) − 1`（始値1個＋終値1個＝価格2個。隣接差分の連鎖ではない） | `T[k+4]` 〜 `T[k+9]` |
| P-4 | 最大保有（G2のみ・10営業日）＋決済1本 | `t_1`〜`t_10`、決済は`t_11`の始値 | `T[k+4]` 〜 `T[k+14]` |
| P-5 | `SELL_BLOCKED`/`BUY_BLOCKED`（空売り・買戻し双方）による持ち越し上限 | ＋5本 | 最悪で `T[k+19]` |
| **P-6** | **⇒ 1週次イベントに必要な`T`の添字範囲** | — | **`k+3` 〜 `k+19`** |

- したがって週`w`が有効であるためには **`k + 19 ≤ N`**（`T`の終端を超えない）を満たす必要がある。選定/確認どちらの期間でも同じ余白を適用する（理由はEXP-OBS000005 §2.2と同一——期間末尾のイベントの前方窓が反対側の期間へ食い込むのを防ぐ）。
- **`k = idx_T(W[w])` は`W[w]`が`T`に存在することを前提とする。** `W[w]`（基準日）は東証の営業日であるため`T`に含まれるはずだが、**B実装チームは§9タスクとして全507週について`W[w] ∈ T`を検証し、含まれない週があれば件数を記録してS に差し戻す**（K-6相当）。

### 3.2 選定/確認の期間区分

| 区分 | シグナル週の範囲（`w`の範囲） | 役割 |
|---|---|---|
| 選定（参照） | `w = 1 〜 (m_w − b)` | 事前固定設計の参照測定。ここで何も選ばない |
| 確認（未見） | `w = (m_w + 1) 〜 (N_w − b)` | G1・G2の合否はこの期間のみで判定する |

- **バッファ`b`の決定方法（推測で埋めない）**: `b`は「週次シグナルの平均間隔（実測: 中央値7暦日≒5営業日）で前方窓（P-6: `k+19`添字ぶん≒19営業日≒約4週分）を吸収するのに必要な週数」として、**`b := ceil(19 / 5) = 4`** と算術的に導出する（19営業日 ÷ 週あたり平均5営業日の切り上げ）。これは新しい自由な数値ではなく、P-6で確定した`k+19`という前方窓の長さから機械的に導かれる。
- **B実装チームは§9タスクとして、この`b=4`が実際に全ての選定期間末尾・確認期間末尾のイベントについて重なりを排除できているかを`T`の実添字で検証する。** 週次間隔が想定（5営業日）より短い箇所（実測: 最小5暦日間隔＝約3〜4営業日のケースあり）が存在するため、**機械的な検証を必須とし、`b=4`で不足する場合は`b`を安全側に拡大したうえでS に差し戻す**（K-6。結果を見てから緩める方向の変更ではなく、安全側への機械的な拡大のみを許容する）。

## 4. シグナル定義

### 4.1 候補変数（EXP-OBS000007 §2.1 で固定済みの2候補）

| 記号 | 定義 |
|---|---|
| `M_w(j)` | 週`w`の銘柄`j`の信用倍率水準 = `LongVol_w(j) / ShrtVol_w(j)` |
| `ΔM_w(j)` | `M_w(j) − M_{w'}(j)`。`w'`は銘柄`j`自身の時系列で`w`の**直前の観測**（暦週が飛んでいても直前の実観測を使う。§4.3の異常ギャップ除外規則を適用した後の直前観測） |

### 4.2 主指標の確定（**本EXPで新規に確定する。回す前に固定し、以後変更しない**）

**主指標: `ΔM_w(j)`（週次変化）。`M_w(j)`（水準）は感度分析としてのみ算出し、合否判定には使わない。**

**理由（結果を見ずに言える理由のみ）**:

1. **符号仮説の経済メカニズムは「フロー」の概念である。** 「返済期限による将来の強制的な反対売買圧力」は、**新規に積み上がった**信用買い残が将来解消されなければならないという主張であり、これは水準そのものよりも**直近の変化**に対応する。ある銘柄が恒常的に高い`M`を持つこと（業種特性・投資家層の構成による構造的な差）は、このメカニズムが主張する「新しい情報」ではない。
2. **`M`（水準）は銘柄固有の持続的特性に強く支配される。** 信用取引が活発な銘柄群（値動きの軽い中小型株等）は恒常的に`M`が高く、この銘柄固有効果は週をまたいでほぼ一定であるため、`M`水準を週ごとにクロスセクションで検定すると**ほぼ同じ銘柄順位を繰り返し検定することになり**、実質的な独立情報が乏しい（§6.3で後述する自己相関の懸念に直結する）。**`ΔM`は銘柄固有の持続的水準を差分で除去する**ため、この懸念を緩和する。
3. **PEADのSUE設計との整合性。** PEAD（EXP-OBS000005）も「水準」ではなく「サプライズ（変化量）」を主指標としており（`RawSUE = A(t) − B(t)`）、本EXPの`ΔM`はこれと同じ設計思想（サプライズ・変化を検定する）である。

### 4.3 欠損・異常値の除外規則（**すべて事前登録・件数を必ず記録**）

| # | 規則 | 実測（0-27・件数のみ）|
|---|---|---|
| E-1 | `ShrtVol_w(j) = 0` の週は`M_w(j)`が定義不能。当該週の当該銘柄は**その週の観測から除外**（`ΔM`計算にも使えない） | 全270,081レコード中152件（**0.0563%**）が該当。極めて稀 |
| E-2 | `ΔM_w(j)`の算出に用いる直前観測`w'`について、`ShrtVol_{w'}(j) = 0`の場合も同様に除外 | 連続ペア269,527組中、両時点とも`ShrtVol≠0`は269,346組（**99.9328%**） |
| E-3 | **異常ギャップ除外**: 直前観測`w'`との暦日差が**21日を超える**場合、`ΔM`は「直前の実質的に連続した週次観測」とみなさず除外する（21日は実測の正常レンジ上限15日に対し安全側の丸め値として設定。**新しい閾値ではなく、実測分布の外側に安全マージンを取っただけ**） | 実測ギャップ日数分布: 5〜9日（97.19%・正常）／12〜16日（2.77%・年末年始等の週跳び）／21日超は**2件のみ**（0.0007%。819日・1862日。上場再開・長期休止等が疑われるが原因特定は範囲外） |
| E-4 | 同一銘柄・同一`Date`の重複レコード | **0件**（実測。重複除外規則は不要と判明したが、`params.json`には規則として明記し将来のデータ更新に備える） |

## 5. Point-in-Time 公表ラグ（**先読み防止の中核。EXP-OBS000007 0-26の実測を踏まえて確定**）

### 5.1 確定した事実（0-26実測の要約。詳細は `EXP-OBS000007/10-result/publication_lag_investigation.md`）

- 調査時点（2026-09-16）で有効な仕様下での公表ラグは**基準日から通常2営業日後**（金曜基準日→翌週火曜16:30頃公表）。J-Quants公式ドキュメント2ページ・JPX公式ページ・JPX公式通知PDF2件の計4情報源で確認済み。
- **祝日を挟んだ場合の後ろ倒し日数の網羅的実測は未実施**（定性的な規則「祝日等非営業日がある場合はその分後ろ倒し」の確認のみ）。
- **2026年9月28日に週次→毎営業日公表への仕様変更が予定**されている。0-25で取得済みの10年分データは**現行仕様（週次・2営業日ラグ）下のスナップショット**である。

### 5.2 本EXPが採用するPIT規則（**安全側に確定。推測で埋めない**）

**採用する規則: `AvailableDate(W[w]) := T[idx_T(W[w]) + 3]`（基準日の3営業日後。§3.1のP-1）。**

**なぜ「確認された2営業日後」ではなく「3営業日」を使うのか（安全側マージンの理由）**:

1. **`T`ベースの営業日カウントは、東証の休場日を自動的に吸収する。** JPX公式資料の「祝日等非営業日がある場合はその分後ろ倒し」という定性的規則は、**取引カレンダー`T`を使って「N営業日後」を数えれば、休場日をまたぐケースも機械的に正しく処理できる**（例: 月曜が祝日なら`T`はその日を含まないため、金曜の2営業日後は自動的に水曜になる）。この構造的な整合性は、実測で確認できた唯一の具体例（`2026-09-11`→`2026-09-15`＝2営業日後）と一致する。
2. **しかし「後ろ倒しの網羅的実測」は未実施であり、`T`ベースの営業日カウントだけでは吸収しきれない例外（JPX側の事務処理都合による追加の後ろ倒し。0-26 §1.5が記録した「システム移行に伴う例外運用」等）が存在しうることが分かっている。** これは**推測で「2営業日で足りるはず」と決めてよい状況ではない**（N-9）。
3. **したがって、確認済みの最小ラグ（2営業日）に対し、`+1`営業日の安全マージンを機械的に上乗せする。** これにより、先読み（実際にはまだ公表されていないデータを使ってしまうこと）の方向には**絶対に**倒れない。生じうる代償は「実際にはもう少し早く使えたはずのデータを1日分古いまま使う」というデータの**陳腐化**のみであり、これは先読みより安全な誤り方向である。
4. **本EXPでは`+1`営業日を新しい自由なパラメータとして導入したのではなく、「確認された下限値に対する固定の安全マージン」として1つだけ定める。** 感度分析として`+0`営業日（＝確認された2営業日そのまま）版も算出するが、**合否判定には使わない**（§9で後述）。

### 5.3 週次公表頻度の仕様変更（2026-09-28）への申し送り

**本EXPが使うデータ（`data/raw/margin_interest/`）はすべて2026-09-28より前の現行仕様（週次・2営業日ラグ）下で取得されたものであり、本EXPの設計・結果は現行仕様のみに基づく。** 新仕様（毎営業日公表）移行後は、公表ラグの構造自体が変わる（実質1営業日程度に短縮される見込み）ため、**本EXPの結果を新仕様下のデータへそのまま延長適用することはできない**。新仕様下での再検証は、移行後のデータが十分に蓄積してから**新規EXP**として起票する。

### 6.1 本EXPで新たに導入する検定力ゲート（**G1段階で評価。カウントのみでは評価できないため、DS-1〜DS-6とは別枠で§Aの時点で規則のみ確定する**）

**懸念（本EXP固有・新規）**: `ΔM`は`M`水準より持続性は低いと見込むが、それでも週をまたいである程度の自己相関を持ちうる。週次クロスセクションIC `IC_w`の系列が自己相関を持つ場合、単純平均`IC_bar`の標準誤差を「`K`個の独立観測」として計算すると、**実効的な独立情報量を過大評価し、有意性を偽陽性側に誤る**（K週あっても実質的に少数の「エピソード」しか無い可能性）。

**採用する対策（G1の主要有意性検定に追加するゲート。回す前に規則のみ確定。実際の値はリターンを含むG1測定でしか算出できないため、ここでは規則のみを凍結する）**:

1. **主有意性検定は、既存プロジェクトの標準手法（PEAD/ギャップと同型の週内ブロックpermutation。§7.2で定義）を维持する。** これは「週」を「日」に置き換えただけであり、既存の枠組みの拡張である。
2. **加えて、`IC_w`系列の自己相関を調整した実効週数`K_eff`を算出し、`K_eff ≥ 15`を新たなG1合格の必要条件とする（G1-1b）。** `K_eff`はNewey-West型の分散インフレ補正で算出する:

   ```
   K_eff := K / (1 + 2 × Σ_{l=1}^{L} (1 − l/L) × ρ_l)
   ```

   ここで`ρ_l`は`IC_w`系列のラグ`l`自己相関、`L`はNewey-West自動帯域幅 `L = floor(4 × (K/100)^(2/9))`（**手動で選ばない自動規則**）。
3. **`K_eff ≥ 15`の根拠**: `DS-2/C7-1`の生の閾値`30`の**半分**を要求する。「調整後も生の閾値の半分は残ること」を最低条件とすることで、自己相関による情報量の目減りが2倍を超える場合にのみ不合格とする、**保守性と実行可能性のバランスを取った丸めた値**。これは新しいアイデアを正当化するために事後に選んだ値ではなく、**既存のDS-2閾値から機械的に半分をとった**値である。
4. **`K_eff`はカウントのみでは算出できない**（`IC_w`の計算にリターンが必要）ため、DS-1〜DS-6とは異なり**G1測定の一部としてB実装チームが算出し、G1-1bとして§7.3のG1合格条件に組み込む**。

# §10 判定

## 10.1 判定: **条件付きGO**

§7の判定規則1に該当（DS-1〜DS-6の6項目すべてが合格）。**`01-spec.md`を起票する。**

**ただし、この条件付きGOはEXP-OBS000005/006と異なり、まだ「検出力の十分性」を保証するものではない。** DS-1〜DS-6は生の件数・構造ゲートに過ぎず、**本EXP固有の主要なリスク（`ΔM`の週次自己相関による実効サンプルサイズの目減り＝K_eff）はリターンを実際に測定するG1段階まで評価できない**。この点で、本EXPの条件付きGOは「回す価値がある」ことを意味するに留まり、「検出力が十分」を意味しない（PEAD/EXP-OBS000005の条件付きGOがMDE事前開示付きだったのと同様の限定性を持つ）。

## 10.5 ショート脚のコストモデルに関する新規の限界開示（**PEAD/ギャップには無かった論点**）

PEAD・ギャップは共にロングオンリーであり、日本株固有の模擬条件チェックリストの「H項（ショート時の貸株料・逆日歩・空売り規制銘柄の除外）」は「該当なし」として扱われてきた（EXP-OBS000005 §7 H項）。**本EXPの符号仮説は方向性を持つ（`ΔM`が高い銘柄は将来リターンが負＝ショート機会）ため、H項が初めて適用対象になる。**

- **貸株料**: 一般的な制度信用貸株料の代表的水準として**年率3.0%**を固定的に適用する（個別銘柄・日次の実際の料率データは本PJでは未取得）。
- **逆日歩（品貸料）はモデル化しない**（データ未取得）。逆日歩は空売りが集中する銘柄で大きく跳ね上がることが知られており、**本EXPのG2はショート脚のコストを過小評価する方向＝楽観側に偏っている**ことを明示する（PEAD C-5「信用規制模擬不能=楽観側に偏る」と同型の開示）。
- **空売り規制銘柄（直近安値からの下落率トリガー等）の除外フラグは本PJで未取得**のため適用しない。同じく楽観側の偏りとして開示する。
- **この限界を踏まえ、spec §7 H項は「近似あり」として明記し、G2の結果を解釈する際は貸株料・逆日歩コストが実際にはより高い可能性を必ず注記する。**
