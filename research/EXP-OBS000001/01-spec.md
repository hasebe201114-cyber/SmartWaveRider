## 1. 仮説（1文）

**決算短信の開示によって更新される「会社自身の通期経常利益見通し」の変化量（＝会計サプライズ SUE）は、開示翌営業日始値から起算した3〜10営業日の株価リターンを、日本株 TOPIX500 相当ユニバースにおいて、往復コスト0.35%控除後も正の期待値が残る程度に予測する。**

### 1.1 エッジ族の宣言

- 予測変数の生成過程: **会計データのみ**（会社予想・実績の経常利益と予想売上高）。価格・出来高・ボラティリティを**一切入力にしない**。
- したがって PJ000001 §4 C-3 が低事前確率とした「価格由来の特徴量から方向を予測する」族には属さない。
- ただし出力形（イベント後の一方向継続を取る）は TSMOM と同型である。この区別が本質的でなかった場合、本 EXP も同じ天井に当たる（prescreen §弱点4）。**この可能性は spec 段階で排除できない。G1 の結果で判定する。**

### 1.2 事前確率の見立て

**中**。ただし根拠は弱い。prescreen 要確認 R-5（日本株 PEAD の学術的エビデンス）は **spec 作成時点でも一次文献を直接確認できていない**。STRATEGY-BRIEF の「学術的に日本株でも報告のあるアノマリー」という記述の一次出典は未検証である。**本 spec は「日本株 PEAD が文献で確認されている」ことを前提にしない。** 文献の存在を根拠に基準を緩めることはしない。

### 2.2 本 EXP における「選定」の自由度はゼロである（最重要）

本 spec は SUE 定義・予測ホライズン・トレール4パラメータ・閾値・ユニバース条件・コスト前提の**すべてを回す前に数値で固定している**。したがって**選定期間で選ぶパラメータは1つも存在しない**。

- 選定期間は「事前固定設計の参照測定」であり、チューニングの場ではない。
- B実装チームは、選定期間の結果を見て spec のいかなる値も変更してはならない。変更が必要と判断した場合は**実装を止めて S に差し戻す**（§10）。
- 選定/確認の符号一致（§6.2 G1-2、§6.4 G2-3）は、この前提の下での再現性確認として要求する。

- **確認期間（2025-07-01〜2026-06-21）にはテール局面が含まれない。** prescreen §レジーム依存性が「部分的に改善」としたのは全期間についての記述であり、A案の時期分割では確認期間側のテール窓はゼロになる。**この空白は STEP3 フォワード較正でのみ補完できる。**

## 3. シグナル定義: SUE（S-1の確定）

### 3.1 単一の事前登録定義（これ以外を合否判定に使わない）

各イベント（＝ある銘柄 j のある決算短信開示 t）について、以下を定義する。使用フィールドはすべて `/fins/summary`。

| 記号 | 定義 | 取得元フィールド |
|---|---|---|
| `A(t)` | **本開示時点における当期通期経常利益の会社見通し** | 1Q/2Q/3Q 開示 → `FOdP`（当期通期予想）<br>通期（FY）開示 → `OdP`（当期通期**実績**。予想が実績に確定した情報更新として扱う） |
| `B(t)` | **直前開示時点で示されていた「同一会計年度」の通期経常利益の会社予想** | 同一銘柄・同一会計年度に対する通期経常利益予想を含む**直近の開示**（`DiscDate`, `DiscTime` の順で最大）の値。<br>直前が1Q/2Q/3Q開示または業績修正開示 → その開示の `FOdP`<br>直前が前期のFY開示 → その開示の `NxFOdP`（＝当期の通期予想） |
| `Scale(t)` | **直前開示時点の同一会計年度の通期予想売上高**（スケールフリー化の分母） | 直前が1Q/2Q/3Q開示または修正開示 → `FSales`<br>直前が前期のFY開示 → `NxFSales` |

**RawSUE(j, t) = ( A(t) − B(t) ) / Scale(t)**

単位は「通期予想売上高比の経常利益ポイント（会計マージンのポイント）」。

### 3.2 会計年度の一致判定（曖昧さを残さない）

- `A(t)` の対象会計年度は本開示の `CurFYSt` / `CurFYEn` で特定する。
- `B(t)` / `Scale(t)` を探すとき、直前開示が 1Q/2Q/3Q/修正開示なら、その開示の `CurFYSt` / `CurFYEn` が本開示の `CurFYSt` / `CurFYEn` と**完全一致**することを要求する。
- 直前開示が FY開示なら、その開示の `NxtFYSt` / `NxtFYEn` が本開示の `CurFYSt` / `CurFYEn` と**完全一致**することを要求する。
- 一致する直前開示が存在しない（＝データ窓の先頭でその銘柄の最初の開示）場合、そのイベントは**除外**し、除外件数を `prediction-unit.json` に記録する。

### 3.3 除外規則（すべて事前登録・件数を必ず記録）

以下はいずれも**リターンを見る前に**適用する。

1. `A(t)`、`B(t)`、`Scale(t)` のいずれかが null / 空文字 / 非数値 → 除外（「予想非開示」「未定」を含む）
2. `Scale(t)` ≤ 0 → 除外
3. 予測対象イベントは **四半期決算短信および通期決算短信の開示のみ**（`DocType` による）。業績修正開示・配当予想修正等は `B(t)` の探索対象にはなるが、**イベント（予測対象）にはしない**
4. `DocType` / `CurPerType` / `ScaleCat` / `MrgnNm` の取りうる値は未確認である。**B実装チームは実データから全ユニーク値と件数を先に出力し、本 spec の分類への対応付けを `params.json` に明記すること。対応付けが一意に決まらない場合は推測で埋めず S に差し戻す**（trading-app-v2 EXP-OBS000037 の教訓）
5. 同一銘柄・同一 `DiscDate` に同種の開示が複数ある場合（訂正等）、`DiscTime` が最も遅い1件のみを採用する。`DiscTime` が同一なら `DiscNo` が最大の1件

### 3.4 標準化

- **主指標（IC）には追加の標準化を行わない。** §6.1 の主検定は Spearman 順位相関であり、単調変換に不変であるため `RawSUE` をそのまま使う。
- **副指標（デシル）には、先読みのないトレーリング分位を使う**:
  - `SUEpct(j,t)` = ユニバース全銘柄の、**`DiscDate` が t より厳密に前**である全イベントの `RawSUE` の経験分布における、`RawSUE(j,t)` のパーセンタイル（拡大窓）。
  - 拡大窓の参照イベント数が **200件未満**の場合、そのイベントは**デシル分析からのみ除外**する（IC分析からは除外しない）。除外件数を記録する。
  - 同値（タイ）は平均順位で処理する。`RawSUE` がちょうど 0（＝予想改訂なし）のイベントが大量に発生することが想定されるため、**`RawSUE` の厳密なゼロ件数の比率を必ず出力すること**。

### 3.5 winsorize / 外れ値処理

- `RawSUE` の winsorize: **行わない**（主指標が順位相関のため不要）。
- リターンの winsorize: **行わない**（実際に発生する損益を歪めるため）。

## 4. 約定モデルの固定（S-2の確定）

### 4.0 値幅制限フラグ `UL` / `LL` の解釈と約定可否判定関数（2026-09-13 改訂で確定）

**本節は §4.1（エントリー）・§4.4（決済）・§7 B項が参照する唯一の正本である。約定可否に関する値幅制限の判定は、本節の2式以外の方法で行ってはならない。**

#### 4.0.1 実測により確定したフィールドの意味

- `/equities/bars/daily` の日足スキーマは `Date,Code,O,H,L,C,UL,LL,Vo,Va,AdjFactor,Adj*,MktCap,ExRT` であり、**その日の値幅制限の価格水準そのものを表すフィールドは存在しない。**
- `UL` / `LL` は**価格水準ではなく 0/1 のフラグ**である（文字列型で `"1"` / `"0"` が返る）。
- 意味の確定: **`UL(t)=1` ⇔ その日の高値 `H(t)` がその日の制限値幅上限の価格に達した。`LL(t)=1` ⇔ その日の安値 `L(t)` がその日の制限値幅下限の価格に達した。**
  - 根拠1（実測 `130A0` / 2024-08-05、`O=677, H=720, L=637, C=637, LL="1"`）: `L=637` を下限価格とすると、直前終値 `787`（基準値段 700円以上1000円未満 → 制限値幅 ±150円）からの下限 `787−150=637` と厳密に一致する。JPX 制限値幅表の下で `P−w(P)=637` を満たす基準値段は `P=787` のみであり、一意に整合する。
  - 根拠2（実測 `UL="1"` サンプル、`O=738, H=748, C=741`）: `H=748` を上限価格とすると、直前終値 `648`（基準値段 500円以上700円未満 → 制限値幅 ±100円）からの上限 `648+100=748` と厳密に一致する。`P+w(P)=748` を満たす基準値段も `P=648` のみで一意。
  - 根拠2は **`C≠H`** である。したがって「**終値**が制限に達したか」という解釈ではこのサンプルを説明できない。「**日中の高値／安値**が制限に達したか」と読むのが唯一整合する解釈である。
- **系（重要）**: `UL(t)=1` のとき、その日の制限値幅上限の価格は `H(t)` に等しい。`LL(t)=1` のとき、制限値幅下限の価格は `L(t)` に等しい。フラグが 0 の日は制限価格を復元できないが、**制限に達していない日は約定可否判定に一切影響しないため、復元する必要がない。**

#### 4.0.2 旧定義との論理的同値性（設計判断ではなく恒等式であること）

改訂前の spec は `O(t1) ≥ UL(t1)`（`UL` を上限価格とみなす数値比較）を条件としていた。§4.0.1 の意味の下で、次が**恒等的に成立する**（近似ではない）。

- `O(t) ≥ 上限価格(t)` ⟺ `UL(t)=1 かつ O(t) = H(t)`
  - （⇐）`UL(t)=1` なら `H(t)` が上限価格。`O(t)=H(t)` より `O(t)` は上限価格に等しく、`≥` を満たす。
  - （⇒）`O(t)` は上限価格を超えられないので `O(t) = 上限価格`。また `O(t) ≤ H(t) ≤ 上限価格` であるから `O(t)=H(t)=上限価格`。よって `UL(t)=1` かつ `O(t)=H(t)`。
- 同様に `O(t) ≤ 下限価格(t)` ⟺ `LL(t)=1 かつ O(t) = L(t)`

**したがって本改訂は約定モデルの厳しさを変更しない。** 改訂前の意図を、実在するフィールドだけで**厳密に**再構成したものである。B実装チームは「近似だから安全側に倒す」といった追加の解釈を加えてはならない（N-6）。

#### 4.0.3 パース規則（一意に確定。推測禁止）

- `UL` / `LL` の生の値を文字列化し前後空白を除去した `s` について: **`s == "1"` → 真。`s == "0"` または `s == ""` または値が null → 偽。それ以外の値が1件でも出現した場合、推測で埋めずに S へ差し戻す**（N-6）。
- B実装チームは §9-1b として **`UL` / `LL` の全ユニーク値と件数**を出力すること。
- `UL` / `LL` が null / 欠損である行の件数を出力する。**ユニバース×全期間の日足行数に対する欠損率が 1% を超える場合は S へ差し戻す**（模擬不能な範囲が無視できない大きさになるため）。
- 価格の同値比較（`O==H` / `O==L`）は、**同一日・同一スケールの値どうし**で行う（生値どうし、または調整値どうし。生値と `Adj*` を混在させない。同一日の中では調整係数が共通のため、どちらを使っても判定結果は変わらない）。
- 数値は `Decimal`（API 応答文字列から直接生成）で厳密比較する。やむを得ず `float` を使う場合の同値判定は `abs(x − y) ≤ 1e-6 × max(1.0, abs(y))` とする。

#### 4.0.4 約定可否の判定関数（この2式をそのままコードに落とすこと）

```
BUY_BLOCKED(t)  :=  (Vo(t) == 0) or (O(t) is null) or ( UL(t)==1 and O(t) == H(t) )
SELL_BLOCKED(t) :=  (Vo(t) == 0) or (O(t) is null) or ( LL(t)==1 and O(t) == L(t) )
```

- `UL(t)==1 and O(t)==H(t)` は「**寄り付き値がその日の制限値幅上限の価格に一致する**」ことを厳密に意味する。本 spec はこれを「ストップ高で寄り付き、寄り付きの買い注文が約定しない」とみなす。**寄らずのストップ高（比例配分）は `O=H=L=C=上限価格` となるため、同一条件で捕捉される。**
- **`UL(t)=1` だが `O(t) < H(t)` の日は約定不能にしない。** 寄り付きは上限未満であり、寄り付きの買いは約定する。日中に上限へ達した事実は、日足完結モデルでは約定に影響しない（根拠2の実測サンプルがこのケースに該当する）。売り側も対称に扱う。
- **方向の非対称性は意図的である。** 買い注文が約定しないのは需要超過（ストップ高）のときであり、売り注文が約定しないのは供給超過（ストップ安）のときである。**買いでストップ安、売りでストップ高は約定制約にしない**（そちらの方向では約定が容易になるため）。
- **JPX の制限値幅表を直前終値から自前で再構成して上限/下限価格を計算してはならない。** 値幅制限の拡大措置・新規上場銘柄・基準値段の特例など例外規定を再現できず、独自解釈の温床になる（§4.0.1 の根拠提示で用いた制限値幅表は、フラグの**意味を同定するための検証**にのみ使ったものであり、**実装には使わない**）。判定は §4.0.4 の2式のみで行う。
- 本節の `UL` / `LL` / `O` / `H` / `L` / `Vo` の利用は**約定可否の制約および損益計算**であり、予測変数 `SUE` の生成には一切入らない。必須条件②・N-2 に抵触しない（§10.3）。

### 4.1 エントリー

- 開示日を `t0`（= `DiscDate`）とする。
- **エントリーは `t0` の翌営業日 `t1` の始値 `O(t1)`** に固定する。`DiscTime` が場前・場中・場後のいずれであっても同じ扱いとする（最も保守的な統一。場前開示の機会を捨てる方向）。
- **`BUY_BLOCKED(t1)`（§4.0.4）が真の場合は約定不能**とし、**そのイベントは見送る（翌日以降の再エントリーを行わない）**。約定不能として件数を記録する。
  - 内訳を必ず3分類で記録する: (i) `Vo(t1) = 0`、(ii) `O(t1)` が null、(iii) `UL(t1)=1` かつ `O(t1)=H(t1)`（ストップ高寄り付き）。
  - 参考値として、**`UL(t1)=1` だが `O(t1) < H(t1)` であったため約定したとみなした件数**も併せて記録する（判定には使わない。C品質チームが約定可否の切り分けを検証するため）。
- 約定価格 = `O(t1) × (1 + 0.075%)`（買い片道スリッページ）。

### 4.2 予測単位（G1）の前方リターン

- **ホライズン H = 5営業日（主）**。
- **R_H(j) = C(t_H) / O(t_1) − 1**（グロス。コスト・スリッページを一切引かない）。
- `t_1` から `t_H` までの営業日が確保できないイベント（データ末尾近傍）は G1 から**除外**し、除外件数を記録する。
- `t_1` が取れないイベント（§4.1 の約定不能）も G1 から除外する。**ただし G1 は「取引可能性」ではなく「予測力」の検定であるため、約定不能イベントを除外した場合と、`O(t1)` を用いて仮想的に含めた場合の両方の `IC_bar` を出力すること**（主判定は除外版）。

### 4.3 決済ルール（トレーリングストップ。PJ000001 C-1 決着に準拠）

4パラメータをすべて数値固定する。

| # | パラメータ | 固定値 |
|---|---|---|
| 1 | 初期損切幅 | エントリー約定価格の **−3.0%** |
| 2 | トレール発動水準 | 終値ベースの含み益が **+4.0%** 以上に到達した日の**翌営業日から**有効化 |
| 3 | 追随幅 | 発動後、`t_1` 以降の**日次終値**の最高値から **−2.0%** |
| 4 | 更新足と約定価格 | **日足終値のみ**でストップ水準を更新し、**日足終値のみ**で抵触判定する。抵触した日の**翌営業日始値**で約定したとみなす |

- 日中高値・日中安値（`H` / `L`）は**トレールの更新にも抵触判定にも使わない**。日中の高値でトレール判定して当日中に約定できたとみなす楽観を構造的に排除するため（PJ000001 C-1 決着の警告への対応）。
- 初期損切も同じ扱い: `C(t) ≤` エントリー約定価格 × 0.97 なら、**翌営業日始値**で手仕舞い。
- 決済時の約定価格 = `O(t_exit) × (1 − 0.075%)`（売り片道スリッページ）。

### 4.4 決済できない場合（値幅制限の模擬）

- 手仕舞い日 `t_exit` について **`SELL_BLOCKED(t_exit)`（§4.0.4）が真の場合、約定できず持ち越し**とする。
- 持ち越し中は、**その後の各営業日 `t` について `SELL_BLOCKED(t)` を同じ式で再評価**し、偽となった最初の営業日の始値で約定する（約定価格は §4.3 の売り片道スリッページを適用）。その間の下落はすべて損失として計上する。
- **最大5営業日**持ち越しても約定できない場合、5営業日目の終値で強制的に評価損益を確定し、「強制評価」としてフラグを立てて件数を記録する。
- 本ルールは、§4.3 の初期損切・トレール抵触による決済、および §4.5 の最大保有期間超過による強制手仕舞い（`t_11` 始値）、§7 D項の未発表決算跨ぎ回避による手仕舞い、§5.3-10 のサーキットブレーカー清算を含む、**すべての売り約定に一律に適用する**。
- 内訳を必ず3分類で記録する: (i) `Vo(t_exit) = 0`、(ii) `O(t_exit)` が null、(iii) `LL(t_exit)=1` かつ `O(t_exit)=L(t_exit)`（ストップ安寄り付き）。
- 参考値として、**`LL(t_exit)=1` だが `O(t_exit) > L(t_exit)` であったため約定したとみなした件数**も併せて記録する（判定には使わない）。
- **`UL(t_exit)=1`（ストップ高）は売り約定を妨げない**（§4.0.4 の非対称性）。ストップ高の日の始値での売り約定は通常どおり成立させる。

### 4.5 保有期間の上限と、窓長の算術的整合性（trading-app-v2 EXP-OBS000037 の教訓）

**最大保有期間 = 10営業日**（PJ000001 §1 の「3〜10営業日保有」の上限）。`t_1` から数えて10本目の日足 `t_10` の終値時点で未決済なら、**`t_11` の始値**で強制手仕舞いする。

以下の対応関係を、実装前に必ず確認すること。**曖昧な箇所を独自解釈で埋めてはならない。**

| 用語 | 日足の本数 | 使う価格の点数 | 日付レンジ | 日次リターンの本数 |
|---|---|---|---|---|
| **予測単位 H=5営業日** | `t_1`〜`t_5` の **5本** | 始値1個 `O(t_1)` ＋ 終値5個 `C(t_1)`〜`C(t_5)` = **6点** | `t_1` 〜 `t_5` | `O(t_1)→C(t_1)`, `C(t_1)→C(t_2)`, …, `C(t_4)→C(t_5)` の **5本**（6点の隣接差分 = 6−1 = 5本 ✓） |
| **予測単位 H=3営業日**（SA-2） | `t_1`〜`t_3` の **3本** | 始値1個 ＋ 終値3個 = **4点** | `t_1` 〜 `t_3` | **3本**（4−1=3 ✓） |
| **予測単位 H=10営業日**（SA-2） | `t_1`〜`t_10` の **10本** | 始値1個 ＋ 終値10個 = **11点** | `t_1` 〜 `t_10` | **10本**（11−1=10 ✓） |
| **パイプライン最大保有** | `t_1`〜`t_10` の **10本**（保有判定に使う日足）＋ 強制決済日 `t_11` の始値 | 始値1個 `O(t_1)` ＋ 終値10個 `C(t_1)`〜`C(t_10)` ＋ 始値1個 `O(t_11)` = **12点** | エントリー `t_1`、最終決済 `t_11` | `O(t_1)→C(t_1)` から `C(t_9)→C(t_10)` まで **10本**、加えて `C(t_10)→O(t_11)` の決済ギャップ **1本** = 合計 **11本**（12−1=11 ✓） |
| **トレール最高値の参照範囲** | `t_1` 〜 抵触判定日 `t_k` | 終値のみ **k個**（`C(t_1)`〜`C(t_k)`） | `t_1` 〜 `t_k` | — |

- **「N営業日保有」は、`t_1` から数えて N本の日足を保有判定に使うことを意味する。** 決済約定はその翌営業日 `t_{N+1}` の始値である（＝価格点は N+2 個になる）。
- `t_0`（開示日）の日足は**一切使わない**。`C(t_0)` も `O(t_0)` も損益計算・シグナル計算に入れない。
- 営業日の定義: **日足データ（`/equities/bars/daily`）にその銘柄の行が存在する日**とする。売買停止で行が存在しない日は営業日として数えない（数えない場合の件数を記録）。

## 5. パイプライン統合の設計

### 5.1 シグナル（必須条件①・②の実装）

- ロング候補 = `SUEpct(j,t0)` が**上位10%（第10デシル）**のイベント。
- **テクニカル指標を一切参照しない。** MACD / RSI / ボリンジャーバンド / CCI / 移動平均 / ADX / ATR / Stochastic / モメンタム / 出来高指標のいずれも、エントリー・エグジット・フィルタ・サイジングの判断に用いない（`②` との合成は本 EXP のスコープ外。G1 合格後に別 EXP として起票する）。

### 6.1 G1 主検定（必須条件③）

**主指標: 開示日内クロスセクション Spearman 順位相関の等加重平均（`IC_bar`）**

1. 確認期間の各開示日 `d` について、その日にイベントを持つ銘柄群の `RawSUE` と `R_5`（§4.2）の **Spearman 順位相関 `IC_d`** を算出する。タイは平均順位で処理する。
2. **1日あたりのイベント数が5件未満の開示日は `IC_bar` の算出から除外**する（除外日数・除外イベント数を記録）。
3. **`IC_bar` = 対象日の `IC_d` の単純平均**（日を等加重。イベント数の多い日に引っ張られないようにする）。
4. **有意性検定 = 開示日ブロック内 permutation**:
   - 帰無仮説: 「同一開示日の銘柄間で、`RawSUE` の順位はリターンの順位を説明しない」
   - 手続き: **同一開示日ブロックの内部でのみ `RawSUE` をシャッフル**し（ブロック間の入れ替えは行わない）、`IC_bar` を再計算する。これを **10,000回**繰り返す。
   - 乱数シード: **20260913**（固定。変更禁止）
   - 片側 p 値 = ( 1 + #{ `IC_bar_perm` ≥ `IC_bar_obs` } ) / ( 1 + 10,000 )
   - **同日ブロック内でのみ並べ替えることにより、同日発表銘柄が共有するマクロ／セクター共通要因が p 値を過小評価させる問題を構造的に排除する。**

**検出力の事前開示（MDE）**

- 1日あたり平均イベント数を `n_d`、`IC_d` の標準偏差を概ね `1/√(n_d − 1)` とみなすと、`n_d ≈ 12` で `SD(IC_d) ≈ 0.30`。
- 確認期間の対象日数 `K ≈ 60` とすると `SE(IC_bar) ≈ 0.30 / √60 ≈ 0.039`。
- 片側5%の検出可能最小効果 **MDE(IC_bar) ≈ 1.645 × 0.039 ≈ 0.064**。
- **したがって本設計は `IC_bar` が概ね 0.065 以上でなければ検出できない。これより小さい真のエッジは検出できず G1 未達（＝Kill）となる。この限界を事前に受け入れる。**
- B実装チームは**実測の `K`・平均ブロックサイズ・permutation 帰無分布の標準偏差**を出力すること（C品質チームが実測 MDE を再計算できるようにするため）。

**【第3版で追記】上記 MDE 前提が実測で否定されていることの開示**

本節の MDE は `K ≈ 60`・`n_d ≈ 12` という**仮定**に基づいていた。2026-09-13 の実測（`feasibility.json`）はこの仮定を満たしていない。

| 量 | spec 初版の仮定 | 実測（確認期間） |
|---|---|---|
| `K`（`IC_d` を算出できる日数 ＝ DS-2 の実測値） | 約60日 | **27日** |
| 確認期間の有効イベント総数 | — | 341件（123開示日、1日あたり平均2.77件） |
| `n_d`（5件以上の日の平均ブロックサイズ） | 約12 | **未出力**（B実装チームは §9-4 で必ず出力すること）。341件・27日・「5件未満の日を除外」という制約から `n_d ∈ [5.0, 9.1]` の範囲に入る |
| 含意される MDE(`IC_bar`) | 約 **0.064** | `n_d=9.1` なら約 **0.11**、`n_d=7` なら約 **0.13** |

- **これは成功基準の変更ではない。** G1-1〜G1-5 の閾値（§6.2）は**一切変更していない**。本追記は「この設計が実際にはどこまで小さいエッジを検出できるか」の**正直な開示**であり、**基準を緩める根拠にも、結果を解釈し直す根拠にも使ってはならない**。
- **この開示が重要な理由**: 実測 MDE が 0.11〜0.13 であるということは、単一の会計系ファクターとして現実的な `IC` の水準（概ね 0.02〜0.05）を**構造的に検出できない**ことを意味する。この状態で G1 を回して不合格になった場合、それは「エッジが無い」証拠ではなく「検出力が足りない」証拠であり、`portfolio-ledger.md` に**不採用として記録してはならない**（§6.8 K-5 の「判定不能・保留」に該当する）。
- **DS-2 を27日から30日へ3日増やしても、MDE は約0.11から約0.10へしか改善しない。** すなわち DS-2 の3日不足は「あと3日あれば十分」という話ではなく、**閾値30日という前提自体が K≈60 の仮定の下で設定されたものであり、実データはその前提から大きく外れている**という事実の表面化である。この認識を司令塔判断（K-5）の材料として申し送る。

### 6.3 デシル分析（必須条件③(b)・OBS000018 / OBS000038 の教訓）

- `SUEpct`（§3.4）で確認期間のイベントを10デシルに分け、各デシルの `R_5` グロス平均・中央値・件数・標準偏差を出力する。
- **市場超過リターンの定義**: TOPIX 日足が現行契約で取得不可（HTTP 403）のため、**ユニバース全銘柄の等加重平均リターン**（同一カレンダー窓 `t_1`〜`t_H`）を市場プロキシとする。`R_5^excess(j) = R_5(j) − (ユニバース等加重平均 R_5 over 同一窓)`。
- **セクター中立リターン**も併せて出力する: `R_5(j) − (同一 `S33` 業種のユニバース構成銘柄の等加重平均 R_5 over 同一窓)`。これは生データであり、合否判定には使わない。
- 閾値非単調性チェック（SA-3）: 上位5% / 10% / 20% / 30% の各閾値での平均リターンを出力する。**合否は上位10%（事前固定）のみで判定し、他の閾値の結果を合格根拠にしてはならない。**
- レジーム別分解（**要**）: 確認期間を四半期ごとに分けたリターン、および決算シーズン別のリターンを出力する。**部分集合の好成績を全体の合格根拠にしてはならない**（trading-app-v2 OBS000038）。

**Sharpe の扱い**: 年率 Sharpe は**算出・報告するが、G2 の合否判定には一切用いない**。報告時は必ず 95% 信頼区間を併記すること（2年観測での年率 Sharpe 推定の標準誤差は概ね `√(1/2) ≈ 0.71` であり、信頼区間の幅は ±1.4 程度になる）。**Sharpe の再現性判定は STEP3 フォワード較正へ送る。**

> **PJ000001 §5.2 との差異（申し送り）**: PJ000001 §5.2 の STEP2 KPI は「確認期間でコスト控除後 Sharpe ≥ 0.5」としているが、本 EXP ではこれを**合否ゲートに使わない**。2年・年約50トレードの観測から Sharpe を有意に識別することが原理的に不可能であるため（prescreen §(c)）。代償として **G1 側を PJ000001 §5.3 より厳しくしている**（G1-3 のグロス下限、G1-4 の市場超過、G1-5 の単調性を追加）。この差異は C品質チームの検査対象とし、司令塔の了解事項として扱う。

### 8.3 損益分岐勝率の再計算（S-8）

> **警告（設計上の厳しさを正直に記す）**: 本パラメータでは、**トレール発動後すぐに戻された場合の利益が +1.35%(コスト後) しかなく、損失側の −3.65% に対して RR が 0.37 しかない。** この設計が成立するには、トレール発動後に平均して **+4%以上**まで伸びる必要がある（分岐勝率 52.1% 相当）か、勝率が大きく50%を超える必要がある。PEAD のドリフトは3〜10営業日で数%オーダーであり、これは**厳しい**。

### 10.3 許可される価格データの利用範囲（N-2 との混同を避けるための明示）

以下は**シグナルではなく取引可能性の制約・損益計算**であるため、価格データの使用を**明示的に許可**する。

- ユニバースの流動性フィルタ（売買代金 `Va` の中央値。§5.4 U-4）
- ユニバースの株価帯フィルタと単元数計算（`C`。§5.4 U-5、§5.3-3）
- 値幅制限による**約定可否**の判定（`UL` / `LL` フラグ、および同一日の `O` / `H` / `L` / `Vo`。§4.0.4・§7 B項）。**これは方向予測の入力ではなく取引可能性の制約であり、N-2 に抵触しない**
- 前方リターン・損益の計算（`O` / `C`。§4.2・§4.3）
- 市場プロキシ・セクター中立リターンの算出（§6.3）

**これらは予測変数（SUE）の生成には一切入らない。** 逆に、これら以外の用途で価格データを使うことは N-2 違反である。
