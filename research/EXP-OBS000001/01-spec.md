## 1. 仮説（1文）

**決算短信の開示によって更新される「会社自身の通期経常利益見通し」の変化量（＝会計サプライズ SUE）は、開示翌営業日始値から起算した3〜10営業日の株価リターンを、日本株 TOPIX500 相当ユニバースにおいて、往復コスト0.35%控除後も正の期待値が残る程度に予測する。**

### 1.1 エッジ族の宣言

- 予測変数の生成過程: **会計データのみ**（会社予想・実績の経常利益と予想売上高）。価格・出来高・ボラティリティを**一切入力にしない**。
- したがって PJ000001 §4 C-3 が低事前確率とした「価格由来の特徴量から方向を予測する」族には属さない。
- ただし出力形（イベント後の一方向継続を取る）は TSMOM と同型である。この区別が本質的でなかった場合、本 EXP も同じ天井に当たる（prescreen §弱点4）。**この可能性は spec 段階で排除できない。G1 の結果で判定する。**

### 1.2 事前確率の見立て

**中**。ただし根拠は弱い。prescreen 要確認 R-5（日本株 PEAD の学術的エビデンス）は **spec 作成時点でも一次文献を直接確認できていない**。STRATEGY-BRIEF の「学術的に日本株でも報告のあるアノマリー」という記述の一次出典は未検証である。**本 spec は「日本株 PEAD が文献で確認されている」ことを前提にしない。** 文献の存在を根拠に基準を緩めることはしない。

## 2. 選定 / 確認プロトコル（過学習の炙り出し）

### 2.1 主方式（A案・時期分割）

| 区分 | 期間（開示日 `DiscDate` ベース） | 役割 |
|---|---|---|
| **選定（参照）** | 2024-06-21 〜 2025-06-30 | 事前固定した設計が選定期間でどう見えるかを**記録するだけ**。ここで何かを選ぶことはしない |
| **確認（未見）** | 2025-07-01 〜 2026-06-21 | **G1・G2 の合否はこの期間のみで判定する** |

### 2.2 本 EXP における「選定」の自由度はゼロである（最重要）

本 spec は SUE 定義・予測ホライズン・トレール4パラメータ・閾値・ユニバース条件・コスト前提の**すべてを回す前に数値で固定している**。したがって**選定期間で選ぶパラメータは1つも存在しない**。

- 選定期間は「事前固定設計の参照測定」であり、チューニングの場ではない。
- B実装チームは、選定期間の結果を見て spec のいかなる値も変更してはならない。変更が必要と判断した場合は**実装を止めて S に差し戻す**（§10）。
- 選定/確認の符号一致（§6.2 G1-2、§6.4 G2-3）は、この前提の下での再現性確認として要求する。

### 2.3 測定範囲の空白（明示）

- **確認期間（2025-07-01〜2026-06-21）にはテール局面が含まれない。** 2024年8月上旬の急落は**選定期間側**に配置される。prescreen §レジーム依存性が「部分的に改善」としたのは全期間についての記述であり、A案の時期分割では確認期間側のテール窓はゼロになる。**この空白は STEP3 フォワード較正でのみ補完できる。**
- 確認期間に含まれる決算シーズンは約4回。**実質的に4シーズン分の共通要因しか観測していない。** 季節性・特定シーズンのマクロ環境に依存した結果である可能性を排除できない。
- 信用規制（日々公表銘柄・増担保規制）は現行契約でデータが取得できず（C-5・HTTP 403）、**模擬不能**。バックテストは規制発動がない前提＝**楽観側に偏る**（§7 F項）。

### 2.4 補助方式（B案・銘柄分割）

**確認期間で G1 に合格した場合にのみ**、追加確認として実施する。

- 分割方法: ユニバース銘柄を `Code` の昇順に並べ、**奇数番目群 / 偶数番目群**の2群に分ける（乱数を使わない決定的分割）。
- 全期間（2024-06-21〜2026-06-21）で両群それぞれの `IC_bar`（§6.1）を算出し、**符号が一致するか**を確認する。
- **B案の結果は合否判定に使わない。** 追加情報としてのみ `prediction-unit.json` に出力する。

## 3. シグナル定義: SUE（S-1の確定）

### 3.1 単一の事前登録定義（これ以外を合否判定に使わない）

各イベント（＝ある銘柄 j のある決算短信開示 t）について、以下を定義する。使用フィールドはすべて `/fins/summary`。

| 記号 | 定義 | 取得元フィールド |
|---|---|---|
| `A(t)` | **本開示時点における当期通期経常利益の会社見通し** | 1Q/2Q/3Q 開示 → `FOdP`（当期通期予想）<br>通期（FY）開示 → `OdP`（当期通期**実績**。予想が実績に確定した情報更新として扱う） |
| `B(t)` | **直前開示時点で示されていた「同一会計年度」の通期経常利益の会社予想** | 同一銘柄・同一会計年度に対する通期経常利益予想を含む**直近の開示**（`DiscDate`, `DiscTime` の順で最大）の値。<br>直前が1Q/2Q/3Q開示または業績修正開示 → その開示の `FOdP`<br>直前が前期のFY開示 → その開示の `NxFOdP`（＝当期の通期予想） |
| `Scale(t)` | **直前開示時点の同一会計年度の通期予想売上高**（スケールフリー化の分母） | 直前が1Q/2Q/3Q開示または修正開示 → `FSales`<br>直前が前期のFY開示 → `NxFSales` |

**RawSUE(j, t) = ( A(t) − B(t) ) / Scale(t)**

単位は「通期予想売上高比の経常利益ポイント（会計マージンのポイント）」。

### 3.2 会計年度の一致判定（曖昧さを残さない）

- `A(t)` の対象会計年度は本開示の `CurFYSt` / `CurFYEn` で特定する。
- `B(t)` / `Scale(t)` を探すとき、直前開示が 1Q/2Q/3Q/修正開示なら、その開示の `CurFYSt` / `CurFYEn` が本開示の `CurFYSt` / `CurFYEn` と**完全一致**することを要求する。
- 直前開示が FY開示なら、その開示の `NxtFYSt` / `NxtFYEn` が本開示の `CurFYSt` / `CurFYEn` と**完全一致**することを要求する。
- 一致する直前開示が存在しない（＝データ窓の先頭でその銘柄の最初の開示）場合、そのイベントは**除外**し、除外件数を `prediction-unit.json` に記録する。

### 3.3 除外規則（すべて事前登録・件数を必ず記録）

以下はいずれも**リターンを見る前に**適用する。

1. `A(t)`、`B(t)`、`Scale(t)` のいずれかが null / 空文字 / 非数値 → 除外（「予想非開示」「未定」を含む）
2. `Scale(t)` ≤ 0 → 除外
3. 予測対象イベントは **四半期決算短信および通期決算短信の開示のみ**（`DocType` による）。業績修正開示・配当予想修正等は `B(t)` の探索対象にはなるが、**イベント（予測対象）にはしない**
4. `DocType` / `CurPerType` / `ScaleCat` / `MrgnNm` の取りうる値は未確認である。**B実装チームは実データから全ユニーク値と件数を先に出力し、本 spec の分類への対応付けを `params.json` に明記すること。対応付けが一意に決まらない場合は推測で埋めず S に差し戻す**（trading-app-v2 EXP-OBS000037 の教訓）
5. 同一銘柄・同一 `DiscDate` に同種の開示が複数ある場合（訂正等）、`DiscTime` が最も遅い1件のみを採用する。`DiscTime` が同一なら `DiscNo` が最大の1件

### 3.4 標準化

- **主指標（IC）には追加の標準化を行わない。** §6.1 の主検定は Spearman 順位相関であり、単調変換に不変であるため `RawSUE` をそのまま使う。
- **副指標（デシル）には、先読みのないトレーリング分位を使う**:
  - `SUEpct(j,t)` = ユニバース全銘柄の、**`DiscDate` が t より厳密に前**である全イベントの `RawSUE` の経験分布における、`RawSUE(j,t)` のパーセンタイル（拡大窓）。
  - 拡大窓の参照イベント数が **200件未満**の場合、そのイベントは**デシル分析からのみ除外**する（IC分析からは除外しない）。除外件数を記録する。
  - 同値（タイ）は平均順位で処理する。`RawSUE` がちょうど 0（＝予想改訂なし）のイベントが大量に発生することが想定されるため、**`RawSUE` の厳密なゼロ件数の比率を必ず出力すること**。

### 3.5 winsorize / 外れ値処理

- `RawSUE` の winsorize: **行わない**（主指標が順位相関のため不要）。
- リターンの winsorize: **行わない**（実際に発生する損益を歪めるため）。

### 3.6 事前登録した感度分析（合否判定には使えない）

以下は**生データとして出力を必須**とするが、**G1・G2 の合否判定に使ってはならない**。これらのいずれかが良好であることを理由に本 EXP を合格にすることは禁止する。使いたい場合は**新規 EXP として起票**し、改めて確認期間を切り直す。

| # | 振る軸 | 水準 |
|---|---|---|
| SA-1 | 利益項目 | `OdP`（経常利益・**主**） / `OP`（営業利益） / `NP`（純利益） |
| SA-2 | 予測ホライズン H | 3営業日 / **5営業日（主）** / 10営業日 |
| SA-3 | シグナル閾値 | 上位5% / **上位10%（主）** / 上位20% / 上位30% |
| SA-4 | 往復コスト | 0.25% / **0.35%（主）** / 0.50% |

**多重検定の扱い**: 合否判定に用いる検定は **§6.1 の主検定1本のみ**である（主定義 `OdP` × H=5 × 上位10% × コスト0.35%）。したがって多重性の補正は不要。SA-1〜SA-4 は記述統計であり、検定として解釈してはならない。

## 4. 約定モデルの固定（S-2の確定）

### 4.1 エントリー

- 開示日を `t0`（= `DiscDate`）とする。
- **エントリーは `t0` の翌営業日 `t1` の始値 `O(t1)`** に固定する。`DiscTime` が場前・場中・場後のいずれであっても同じ扱いとする（最も保守的な統一。場前開示の機会を捨てる方向）。
- `t1` に売買が成立しなかった場合（`Vo(t1) = 0`）、または `O(t1) ≥ UL(t1)`（寄り付きがストップ高水準）の場合は**約定不能**とし、**そのイベントは見送る（翌日以降の再エントリーを行わない）**。約定不能として件数を記録する。
- 約定価格 = `O(t1) × (1 + 0.075%)`（買い片道スリッページ）。

### 4.2 予測単位（G1）の前方リターン

- **ホライズン H = 5営業日（主）**。
- **R_H(j) = C(t_H) / O(t_1) − 1**（グロス。コスト・スリッページを一切引かない）。
- `t_1` から `t_H` までの営業日が確保できないイベント（データ末尾近傍）は G1 から**除外**し、除外件数を記録する。
- `t_1` が取れないイベント（§4.1 の約定不能）も G1 から除外する。**ただし G1 は「取引可能性」ではなく「予測力」の検定であるため、約定不能イベントを除外した場合と、`O(t1)` を用いて仮想的に含めた場合の両方の `IC_bar` を出力すること**（主判定は除外版）。

### 4.3 決済ルール（トレーリングストップ。PJ000001 C-1 決着に準拠）

4パラメータをすべて数値固定する。

| # | パラメータ | 固定値 |
|---|---|---|
| 1 | 初期損切幅 | エントリー約定価格の **−3.0%** |
| 2 | トレール発動水準 | 終値ベースの含み益が **+4.0%** 以上に到達した日の**翌営業日から**有効化 |
| 3 | 追随幅 | 発動後、`t_1` 以降の**日次終値**の最高値から **−2.0%** |
| 4 | 更新足と約定価格 | **日足終値のみ**でストップ水準を更新し、**日足終値のみ**で抵触判定する。抵触した日の**翌営業日始値**で約定したとみなす |

- 日中高値・日中安値（`H` / `L`）は**トレールの更新にも抵触判定にも使わない**。日中の高値でトレール判定して当日中に約定できたとみなす楽観を構造的に排除するため（PJ000001 C-1 決着の警告への対応）。
- 初期損切も同じ扱い: `C(t) ≤` エントリー約定価格 × 0.97 なら、**翌営業日始値**で手仕舞い。
- 決済時の約定価格 = `O(t_exit) × (1 − 0.075%)`（売り片道スリッページ）。

### 4.4 決済できない場合（値幅制限の模擬）

- 手仕舞い日の `O(t_exit) ≤ LL(t_exit)`（寄り付きがストップ安水準）または `Vo(t_exit) = 0` の場合、**約定できず持ち越し**とする。
- 約定できる最初の営業日の始値まで持ち越し、その間の下落はすべて損失として計上する。
- **最大5営業日**持ち越しても約定できない場合、5営業日目の終値で強制的に評価損益を確定し、「強制評価」としてフラグを立てて件数を記録する。

### 4.5 保有期間の上限と、窓長の算術的整合性（trading-app-v2 EXP-OBS000037 の教訓）

**最大保有期間 = 10営業日**（PJ000001 §1 の「3〜10営業日保有」の上限）。`t_1` から数えて10本目の日足 `t_10` の終値時点で未決済なら、**`t_11` の始値**で強制手仕舞いする。

以下の対応関係を、実装前に必ず確認すること。**曖昧な箇所を独自解釈で埋めてはならない。**

| 用語 | 日足の本数 | 使う価格の点数 | 日付レンジ | 日次リターンの本数 |
|---|---|---|---|---|
| **予測単位 H=5営業日** | `t_1`〜`t_5` の **5本** | 始値1個 `O(t_1)` ＋ 終値5個 `C(t_1)`〜`C(t_5)` = **6点** | `t_1` 〜 `t_5` | `O(t_1)→C(t_1)`, `C(t_1)→C(t_2)`, …, `C(t_4)→C(t_5)` の **5本**（6点の隣接差分 = 6−1 = 5本 ✓） |
| **予測単位 H=3営業日**（SA-2） | `t_1`〜`t_3` の **3本** | 始値1個 ＋ 終値3個 = **4点** | `t_1` 〜 `t_3` | **3本**（4−1=3 ✓） |
| **予測単位 H=10営業日**（SA-2） | `t_1`〜`t_10` の **10本** | 始値1個 ＋ 終値10個 = **11点** | `t_1` 〜 `t_10` | **10本**（11−1=10 ✓） |

### 6.1 G1 主検定（必須条件③）

**主指標: 開示日内クロスセクション Spearman 順位相関の等加重平均（`IC_bar`）**

1. 確認期間の各開示日 `d` について、その日にイベントを持つ銘柄群の `RawSUE` と `R_5`（§4.2）の **Spearman 順位相関 `IC_d`** を算出する。タイは平均順位で処理する。
2. **1日あたりのイベント数が5件未満の開示日は `IC_bar` の算出から除外**する（除外日数・除外イベント数を記録）。
3. **`IC_bar` = 対象日の `IC_d` の単純平均**（日を等加重。イベント数の多い日に引っ張られないようにする）。
4. **有意性検定 = 開示日ブロック内 permutation**:
   - 帰無仮説: 「同一開示日の銘柄間で、`RawSUE` の順位はリターンの順位を説明しない」
   - 手続き: **同一開示日ブロックの内部でのみ `RawSUE` をシャッフル**し（ブロック間の入れ替えは行わない）、`IC_bar` を再計算する。これを **10,000回**繰り返す。
   - 乱数シード: **20260913**（固定。変更禁止）
   - 片側 p 値 = ( 1 + #{ `IC_bar_perm` ≥ `IC_bar_obs` } ) / ( 1 + 10,000 )
   - **同日ブロック内でのみ並べ替えることにより、同日発表銘柄が共有するマクロ／セクター共通要因が p 値を過小評価させる問題を構造的に排除する。**

**検出力の事前開示（MDE）**

- 1日あたり平均イベント数を `n_d`、`IC_d` の標準偏差を概ね `1/√(n_d − 1)` とみなすと、`n_d ≈ 12` で `SD(IC_d) ≈ 0.30`。
- 確認期間の対象日数 `K ≈ 60` とすると `SE(IC_bar) ≈ 0.30 / √60 ≈ 0.039`。
- 片側5%の検出可能最小効果 **MDE(IC_bar) ≈ 1.645 × 0.039 ≈ 0.064**。
- **したがって本設計は `IC_bar` が概ね 0.065 以上でなければ検出できない。これより小さい真のエッジは検出できず G1 未達（＝Kill）となる。この限界を事前に受け入れる。**
- B実装チームは**実測の `K`・平均ブロックサイズ・permutation 帰無分布の標準偏差**を出力すること（C品質チームが実測 MDE を再計算できるようにするため）。

### 6.3 デシル分析（必須条件③(b)・OBS000018 / OBS000038 の教訓）

- `SUEpct`（§3.4）で確認期間のイベントを10デシルに分け、各デシルの `R_5` グロス平均・中央値・件数・標準偏差を出力する。
- **市場超過リターンの定義**: TOPIX 日足が現行契約で取得不可（HTTP 403）のため、**ユニバース全銘柄の等加重平均リターン**（同一カレンダー窓 `t_1`〜`t_H`）を市場プロキシとする。`R_5^excess(j) = R_5(j) − (ユニバース等加重平均 R_5 over 同一窓)`。
- **セクター中立リターン**も併せて出力する: `R_5(j) − (同一 `S33` 業種のユニバース構成銘柄の等加重平均 R_5 over 同一窓)`。これは生データであり、合否判定には使わない。
- 閾値非単調性チェック（SA-3）: 上位5% / 10% / 20% / 30% の各閾値での平均リターンを出力する。**合否は上位10%（事前固定）のみで判定し、他の閾値の結果を合格根拠にしてはならない。**
- レジーム別分解（**要**）: 確認期間を四半期ごとに分けたリターン、および決算シーズン別のリターンを出力する。**部分集合の好成績を全体の合格根拠にしてはならない**（trading-app-v2 OBS000038）。

### 8.2 感度分析（必須出力・合否判定には使わない）

往復コスト **0.25% / 0.35%（主） / 0.50%** の3水準で §6.5 P-1 を出力する（SA-4）。**0.25% の結果が良いことを理由に合格にしてはならない。**

### 8.3 損益分岐勝率の再計算（S-8）

§4.3 で固定したトレール4パラメータ（初期損切 −3.0% / 発動 +4.0% / 追随 −2.0% / 日足終値判定・翌営業日始値約定）と往復コスト0.35%に基づく再計算。**翌営業日始値約定による約定ギャップを保守側に 0.30% 見込む。**

| ケース | 名目 | コスト後 |
|---|---|---|
| 損失側（トレール未発動で初期損切） | −3.0% | −3.0 − 0.35 − 0.30 = **−3.65%** |
| 利益側の**最小**（発動直後に追随幅まで戻す） | +4.0% − 2.0% = +2.0% | +2.0 − 0.35 − 0.30 = **+1.35%** |

2値近似での損益分岐勝率（利益側の平均値を振る）:

| 利益側の名目平均 | 利益側コスト後 | 損失側コスト後 | 損益分岐勝率 |
|---|---|---|---|
| +2.0%（最小・発動直後戻し） | +1.35% | −3.65% | **73.0%** |
| +4.0% | +3.35% | −3.65% | **52.1%** |
| +6.0% | +5.35% | −3.65% | **40.6%** |
| +8.0% | +7.35% | −3.65% | **33.2%** |

> **警告（設計上の厳しさを正直に記す）**: 本パラメータでは、**トレール発動後すぐに戻された場合の利益が +1.35%(コスト後) しかなく、損失側の −3.65% に対して RR が 0.37 しかない。** この設計が成立するには、トレール発動後に平均して **+4%以上**まで伸びる必要がある（分岐勝率 52.1% 相当）か、勝率が大きく50%を超える必要がある。PEAD のドリフトは3〜10営業日で数%オーダーであり、これは**厳しい**。
> **この厳しさを理由にパラメータを事後に変更することを禁止する。** B実装チームは §6.5 P-6（決済理由の内訳）・P-7（トレール発動率と発動後の平均到達最高含み益）を必ず出力し、C品質チームはこれらを使って「パラメータが構造的に不適合だったのか、エッジが不在だったのか」を切り分けること。
> なお時間切れ決済（最大保有10営業日）は上記2値近似に含まれない第3の帰結であり、実際の分岐勝率は上表とずれる。上表は**目安**であり、実測は P-1・P-6 で確認する。
