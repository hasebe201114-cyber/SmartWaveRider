## 0. 結論（先に書く）

### 0.1 三行で

1. **「会社業績予想データ」そのものは、J-Quants 以外に無償で取得できる。** 東証の 2 サイト（`www.release.tdnet.info` / `www2.jpx.co.jp`）から、`/fins/summary` の `FSales`・`FOdP`・`NxFSales`・`NxFOdP` と**同一の原本**（決算短信サマリー XBRL）が、**銘柄あたり約10年分**、ログインもAPIキーも不要でダウンロードできることを**実測で確認した**。
2. **しかしそれは DS-2 を解決しない。** DS-2 を縛っているのは会社予想データではなく **日足株価の履歴長（J-Quants 無料プランの約2年）** だからである。SUE だけ10年分あってもリターンが計算できず、U-4（直前60営業日の売買代金）も引けない。**本調査の最大の発見は「拘束条件を取り違えていた」という点である。**
3. **その結果、D-5 の選択肢③のコストが大幅に下方修正される。** 一次情報（`jpx-jquants.com`）を実測した結果、PEAD が必要とする `/fins/summary` は **Free を含む全プランに含まれており、TDnet アドオン（¥11,000/月）は不要**。履歴延伸に必要なのは**プラン自体の引き上げのみ**で、**Standard ¥3,300/月（10年）**、**Light ¥1,650/月（5年）**。従来 C-6 で前提していた **¥12,650/月（資本比15.2%/年）は、PEAD に関する限り誤った前提だった**。

### 0.2 判定

| 問い | 判定 |
|---|---|
| J-Quants 以外に「会社業績予想データ」の現実的な入手経路は存在するか | **存在する**（東証の無償2サイト。実測済み） |
| それは D-5 の課題（DS-2 不足・MDE 劣化）を解決するか | **解決しない**（拘束条件は株価履歴であり、会社予想データではない） |
| J-Quants 以外に「株価履歴＋会社予想」を**両方**揃える現実的な代替はあるか | **存在しない**（C-4 の決着が株価側にそのまま効く。§5 参照） |
| 追加費用¥0で本 EXP に貢献できるものはあるか | **ある**（STEP3 フォワードの SUE 入力。無料プランの12週遅延を回避できる。§6.1） |

## 1. 調査の枠組み — 「代替になる」の定義を先に固定する

C-4 と同様、**何をもって代替と認めるかを調査前に固定**した。以下 R-a〜R-f のすべてを満たさない限り「代替」とは呼ばない。1つでも欠ければ、その候補は spec `01-spec.md` §3.1 の `RawSUE` を計算できない。

| # | 要件 | 根拠（spec の該当箇所） |
|---|---|---|
| **R-a** | **会社自身の予想**であること。アナリスト予想・独自予想は不可 | §3.1 `A(t)`/`B(t)` は「会社見通し」「会社予想」と定義済み |
| **R-b** | **開示単位のレコード**であること（1開示＝1行、開示日・開示時刻つき）。**上書きされた過去の予想が残っている**こと | §3.1 `B(t)`＝「直前開示時点で示されていた予想」。最新スナップショットしか持たない情報源では原理的に計算不能 |
| **R-c** | 通期予想の**売上高**と**経常利益**（＝`FSales`/`FOdP`）、および FY開示における**翌期**予想（`NxFSales`/`NxFOdP`） | §3.1 の3記号すべて |
| **R-d** | **確認期間 2025-07-01〜2026-06-21 を含む履歴**。延伸するなら5〜10年 | §2.1・§6.0 |
| **R-e** | ユニバース全銘柄（175〜271）を**機械的に**取得でき、**規約上も許される**こと | §5.4・`CLAUDE.md` 最優先事項「本番運用できる信頼性」 |
| **R-f** | **同一期間の日足株価（四本値・売買代金）が揃う**こと | §3 の予測対象は D+1〜D+10 のリターン。U-4 は直前60営業日の売買代金 |

> **R-f を要件に含めたことが本調査の分水嶺である。** 司令塔の問いは「会社予想データの代替源」だったが、実験を成立させる単位は「会社予想 × 株価」のペアであり、**片方だけ延ばしても DS-2 は1日も増えない**。この点を §4 で数値化する。

## 3. 候補別の詳細（実測ログ）

### 3.1 金融庁 EDINET API（無償）— **業績予想は原理的に存在しない**

**到達性（実測）**

| エンドポイント | 結果 |
|---|---|
| `https://api.edinet-fsa.go.jp/api/v2/documents.json?date=2026-08-07&type=2` | HTTP 200、ボディ `{"StatusCode": 401, "message": "Access denied due to invalid subscription key.…"}` |
| 同上 `&Subscription-Key=dummy` | 同じ 401 ボディ |
| `https://disclosure.edinet-fsa.go.jp/api/v1/documents.json?…`（旧v1） | **HTTP 403**（v1 は廃止済み） |
| `https://api.edinet-fsa.go.jp/api/auth/index.aspx?mode=1`（キー発行） | Azure AD B2C（`fsaedinetauth.b2clogin.com`）のサインアップ画面へリダイレクト。**メールアドレス＋パスワードによるアカウント登録が必要** |

→ **APIキーは無償だが、司令塔本人のメール認証を伴う自己登録が必要**であり、本セッションからは取得できなかった。

**しかし、キーの有無は結論に影響しない。** EDINET の**中身**に業績予想が無いことを、キー無しで到達できる別経路から実測で確認した。

**実測1: EDINET に四半期報告書はもう存在しない。**
東証上場会社情報サービス（`www2.jpx.co.jp`、§3.4）の「法定開示情報（EDINET から取得した情報を表示しています）」欄を2銘柄で確認した。

- **トヨタ自動車（72030）** 直近1年: 有価証券報告書 1件（2026/06/10）、半期報告書 1件（2025/11/13）、**四半期報告書 0件**
- **栄電子（75670）** 直近2年: 有報 2件（2026/06/25・2025/06/30）、半期報告書 2件（2025/11/14・2024/11/14）、**四半期報告書 0件**

これは 2024-04-01 以後開始事業年度からの**四半期報告書の廃止**（金商法改正）による。したがって本 EXP の契約期間（2024-06-21〜2026-06-21）において、EDINET が提供する法定開示は**年2回（有報＋半期報告書）**にすぎず、決算短信の**年4回**に対して**イベント数が構造的に半減**する。DS-1（341件≥300）すら維持できない。

**実測2（傍証）: 第三者の EDINET 派生サービスが四半期データの更新を停止している。**
IR BANK のダウンロードページ（`https://irbank.net/download`）に以下の明記を確認した。

> 「四半期データは**四半期報告書の廃止に伴い、更新を終了しました**。」

**構造的事実（一次区分）**: 業績予想は**取引所規則にもとづく適時開示（TDnet）の事項**であって、金商法にもとづく法定開示（EDINET）の事項ではない。EDINET が「法定開示」、TDnet が「適時開示（業績予想およびその修正を含む）」という役割分担は、金融庁・JPX 双方の一次説明と一致する。

**判定**: **R-a（会社予想の存在）で失格。** 過去の議論の「法定開示であり適時開示の代替にならない」という整理は**正しかった**。今回それを、(a) 四半期報告書が実在しないこと、(b) 派生サービスが更新停止していること、の2点で実測により裏づけた。開示タイミングや粒度の違いではなく、**当該データ項目が EDINET に存在しない**。

### 3.2 TDnet 直接契約（J-Quants を介さない）— **法人向けで個人には開かれていない**

JPX の有料情報ページ（`www.jpx.co.jp/markets/paid-info-listing/tdnet/`）が掲げる4形態：

| 形態 | 内容 | 個人での契約可能性 |
|---|---|---|
| TDnet DBS サービス | インターネット経由、**5年分**の検索閲覧 | 法人向け |
| TDnet サーバ型 | **専用線**によるリアルタイム配信 | 事実上不可 |
| TDnet API サービス | インターネット経由、**5年分**をAPIで受信 | 法人向け |
| TDnet on Snowflake | Snowflake のデータ共有 | 法人向け |

いずれも料金は「要問合せ」で公開されておらず、個人が web 上で契約完結できる導線が存在しない。

**そして、これらを個人向けに再パッケージしたものが J-Quants の「TDnet/適時開示アドオン（¥11,000/月・5年）」である**（JPX ニュースリリース「個人向けデータ配信サービス J-Quants API 適時開示書類（TDnet）アドオン提供開始」）。つまり **「J-Quants を介さない TDnet 直接契約」は、個人にとっては J-Quants アドオンより安くも別条件でもなく、そもそも入口が無い。**

**判定**: **R-e で失格。** 司令塔の当初予想（個人・低資本での契約可能性は低い）は正しい。

> **なお §4 で述べるとおり、PEAD はそもそも TDnet アドオンを必要としない。**

### 3.3 東証 適時開示情報閲覧サービス（`www.release.tdnet.info`・無償）— **本文XBRLは無償で取れる。ただし38日**

**ACTIVE 0-18(a) の記述「取得できるのはインデックスのみで、テキスト本文（PDF/XBRL）は依然として TDnetアドオン（有償）が必要」は、実測の結果、誤りである。**

**実測1: インデックスに XBRL 列が存在する。**
`https://www.release.tdnet.info/inbs/I_list_001_20260807.html` を取得（HTTP 200）。ヘッダ行は

```
時刻 | コード | 会社名 | 表題 | XBRL | 上場取引所 | 更新履歴
```

であり、決算短信の行には次の形の**直リンク**が入っている。

```html
<td class="…kjXbrl"><a class="style002" href="081220260807515828.zip">XBRL</a></td>
```

**実測2: その zip は無償でダウンロードでき、必要なフィールドを含む。**
`https://www.release.tdnet.info/inbs/081220260807515828.zip`（栄電子 7567・2027年3月期第1四半期決算短信）を取得（HTTP 200、53,220 bytes）。中身は決算短信サマリー XBRL 一式。サマリー iXBRL から抽出した数値ファクト113件のうち、予想コンテキストのもの：

| 要素 | コンテキスト | scale | 値 | spec の記号 |
|---|---|---|---|---|
| `tse-ed-t:NetSales` | `CurrentYearDuration_ConsolidatedMember_ForecastMember` | 6 | 10,071 | **`FSales`** |
| `tse-ed-t:OrdinaryIncome` | `CurrentYearDuration_ConsolidatedMember_ForecastMember` | 6 | 351 | **`FOdP`** |
| `tse-ed-t:OperatingIncome` | 同上 | 6 | 333 | （`FOP`） |
| `tse-ed-t:ProfitAttributableToOwnersOfParent` | 同上 | 6 | 203 | （`FNP`） |

FY 決算短信（ＩＰＳＨＤ 4335・2026年6月期）でも `NextYearDuration_…` コンテキスト（＝`NxFSales`/`NxFOdP` に相当）の存在を確認した。

> **すなわち `/fins/summary` の `FOdP`・`NxFOdP`・`FSales`・`NxFSales` は、J-Quants が独自に作ったデータではなく、この無償 XBRL の再配信である。原本は無償で取れる。**

**実測3: 保持期間は 38日のローリング窓。**

| 日付 | `I_list_001_YYYYMMDD.html` |
|---|---|
| 2026-07-25 / 07-31 / 08-03 / **08-05** | **HTTP 404** |
| **2026-08-06** / 08-07 / 08-12 | HTTP 200 |

実行日 2026-09-13 に対し最古が 2026-08-06 ＝ **38日**。0-18 の実測（保持約38日）と完全に一致し、**これ以上遡れない**。

**実測4: 業績予想の修正開示には XBRL が付かないことが多い。**
2026-08-07 の全開示 499件のうち「業績予想…修正」を含む行は **25件**、そのうち XBRL zip が付いていたのは **4件（16.0%）** のみ。XBRL が付いた1件（`091220260804507876.zip`）は `tse-rvfc` タクソノミで前回予想（`PreviousMember`）と今回修正予想（`CurrentMember`）を持つが、**タグ付け品質が低い**（`NetIncomePerShare` の値に「今回修正予想(B)21,800」というラベル文字列が混入している実例を確認）。

→ これは spec §3.1 の `B(t)`（直前が業績修正開示の場合）に影響する**既知のデータ品質リスク**である。ただし **J-Quants も同じ XBRL を原本としているため、無償経路が劣るわけではない（パリティ）**。B実装チームは §9-5 の記述統計でこの欠落率を出力すること。

**判定**: R-a〜R-c・R-e は満たすが、**R-d（38日）で失格**。バックテストには使えない。**ただし §6.1 のとおり、STEP3 フォワードでは決定的に有用である。**

### 3.4 東証上場会社情報サービス（`www2.jpx.co.jp`・無償）— **約10年分の決算短信XBRLが無償で取れる**

本調査で新たに発見した経路。**ログイン・APIキー・費用のいずれも不要。**

**アクセス手順（実測・再現可能）**
1. `https://www2.jpx.co.jp/tseHpFront/JJK010010Action.do?Show=Show` でセッション取得
2. 同 action へ `eqMgrCd=<4桁コード>` を POST（銘柄検索）
3. `https://www2.jpx.co.jp/tseHpFront/JJK010030Action.do` へ `BaseJh` ＋ `mgrCd=<5桁コード>` を POST → 上場会社詳細

詳細ページには「基本情報 / **適時開示情報** / 縦覧書類・PR情報 / コーポレート・ガバナンス / 株価情報」のタブがあり、**適時開示情報タブは `[決算情報]` カテゴリに限定**されている（＝PEAD に必要な決算短信と業績予想修正だけが並ぶ、都合のよい形）。列は

```
開示日 | 表題 | XBRL | HTML | サマリー | 添付資料
```

**実測1: 履歴長**

| 銘柄 | 適時開示[決算情報]の全行数 | 決算短信の件数 | 最古 | 最新 | iXBRL リンクあり |
|---|---|---|---|---|---|
| トヨタ自動車 72030 | 507 | 46 | **2016/08/04** | 2026/08/04 | 42 |
| 栄電子 75670 | 201 | 71（決算短信＋業績予想修正） | **2016/08/09** | 2026/08/07 | — |

→ **約10年分**。検索結果のとおり「東証上場会社情報サービスでは過去10年分の適時開示資料が閲覧できる」という記載と整合する。

**実測2: 10年前の XBRL が実際にダウンロードでき、`FSales`/`FOdP` を含む。**
`https://www2.jpx.co.jp/disc/75670/081220160805469074_tse-qcedjpsm-75670-20160809375670-ixbrl.htm`（栄電子・**平成29年3月期 第1四半期決算短信〔日本基準〕**、開示日 2016-08-09）を取得（HTTP 200）。抽出：

| 要素 | コンテキスト | scale | 値 | spec の記号 |
|---|---|---|---|---|
| `tse-ed-t:NetSales` | `CurrentYearDuration_ConsolidatedMember_ForecastMember` | 6 | **5,801**（百万円） | **`FSales`** |
| `tse-ed-t:OrdinaryIncome` | `CurrentYearDuration_ConsolidatedMember_ForecastMember` | 6 | **222**（百万円） | **`FOdP`** |

**10年前の日本基準・中小型株の会社予想が、無償で、機械可読で、完全に取得できる。**

**実測3: 取得コストは小さい。**
175銘柄 × （セッション2リクエスト ＋ 詳細1リクエスト ＋ iXBRL 約42件）≒ **約8,000リクエスト / 約1GB**。1 req/sec の礼儀正しいレートでも数時間で完了する。**スクレイピング工数は障害ではない。**

**実測4: 業績予想の修正開示には XBRL 列が無い（PDFのみ）。**
栄電子 2026/08/07「2027年3月期第2四半期（中間期）および通期業績予想の修正に関するお知らせ」の行を生HTMLで確認したところ、`/disc/75670/140120260807515819.pdf` のみで XBRL/サマリー/添付資料の各セルは空。→ §3.3 実測4 と同じ制約。

**実測5: 規約（一次情報）**
`https://www.jpx.co.jp/term-of-use/index.html`（2026/07/29 更新）に以下の明記がある。

**判定**: **R-b で構造的に失格。** これは「証券会社ツール」というカテゴリ全体に効く論点である。

## 4. 本調査の核心 — **拘束条件は「会社予想データ」ではなく「日足株価の履歴長」である**

§3.4 で「10年分の会社予想が無償で取れる」ことを実測した。にもかかわらず **DS-2 は1日も増えない**。理由を数値で示す。

### 4.1 DS-2 は何で決まっているか

DS-2 ＝「**確認期間**の、1日あたり5件以上のイベントを持つ開示日の数」（spec §6.0、実測27日／閾値30日）。確認期間は 2025-07-01〜2026-06-21 の**約1年**であり、その長さを決めているのは **J-Quants 無料プランの日足株価が 2024-06-21 までしか遡れないこと**である（`PJ000001` §4 C-4 の実測）。

イベントが成立するには、開示日 `t` に対して

1. `A(t)`・`B(t)`・`Scale(t)`（＝会社予想。**無償で10年分ある**）
2. **D+1〜D+10 の日足終値**（リターン。無い）
3. **直前60営業日の売買代金**（U-4 のユニバース判定。無い）

の3つが**すべて**必要である。1 だけを延ばしても 2・3 が無ければイベントは1件も増えない。

### 4.2 MDE の算術（spec §6.1 の数値と整合することを確認済み）

spec §6.1 の開示値から、MDE は `K`（＝DS-2）に対して **MDE ∝ 1/√K** で動くことが確認できる。

| 検算 | 計算 | spec の記載値 |
|---|---|---|
| K=27 → K=30 | 0.11 ÷ √(30/27) = 0.104 | 「約0.10へしか改善しない」✓ |
| K=27 → K=135 | 0.11 ÷ √(135/27) = 0.0492 | 「K≈135 で MDE≒0.049」✓ |

確認期間の長さ 1年 = DS-2 27日 という実測比率（27日/年）を使うと：

| 履歴長 | 想定の選定/確認分割 | 確認期間 | 推定 `K` | 推定 MDE | 現実的IC 0.02〜0.05 を検出できるか |
|---|---|---|---|---|---|
| **2年（Free・現状）** | 0.75年 / 1.0年 | 1.0年 | **27** | **0.11〜0.13** | **できない** |
| 3年 | 1.5年 / 1.5年 | 1.5年 | 40 | 0.090 | できない |
| **5年（Light）** | 2.5年 / 2.5年 | 2.5年 | **68** | **≒0.070** | **できない** |
| **10年（Standard）** | 5.0年 / 5.0年 | 5.0年 | **135** | **≒0.049** | **上限値 0.05 にかろうじて届く** |
| 20年（Premium） | 10年 / 10年 | 10年 | 270 | ≒0.035 | 届く |

### 4.3 ここから導かれる3つの事実

1. **会社予想データの代替源を何本見つけても DS-2 は動かない。** §3.4 の発見は実験の拘束条件に触れていない。司令塔の問い「J-Quants 以外に取得方法はないか」への正直な答えは「**ある。しかしそれは問題を解いていない**」である。
2. **株価履歴を無償で延ばす道は C-4 で既に閉じている。** 楽天RSS（日足10年・ただし Excel 必須で不採用）、Yahoo Finance系（規約・非公式APIで不採用）。本調査でも `www2.jpx.co.jp` の「株価情報」タブを確認したが、取得できた詳細ページ HTML（205,539 bytes）に「始値」「高値」「安値」「終値」「出来高」の文字列は **いずれも0件**であり、**四本値の時系列は含まれていなかった**。C-4 の決着を覆す材料は見つからなかった。
3. **したがって D-5 の選択肢③（有料プランでの履歴延伸）に、無償の代替は存在しない。** ただし**必要な金額は従来の前提より一桁小さい**。次節。

## 7. 司令塔判断事項 D-5 への申し送り

本調査は D-5 の**材料**であり、S は採否を宣言しない（採否は C品質チームの職務、本番反映の GO は司令塔）。以下は S の**具申**である。

### 7.1 D-5 の選択肢は、本調査により次のように書き換わる

| 元の選択肢 | 本調査後の姿 |
|---|---|
| ①保留のまま凍結（¥0） | 変更なし。**PEAD は不採用ではなく「判定不能」のまま** |
| ②期間の切り直し | **K-4 HARKing。S は引き続き非推奨**（変更なし） |
| **③J-Quants 有料プランで履歴延伸** | **コストが ¥12,650/月 → Light ¥1,650/月（5年・MDE≒0.070）または Standard ¥3,300/月（10年・MDE≒0.049）に訂正。** Standard は **C-5（需給データ）も同時に解決**する。ただし **MDE 0.049 は現実的IC レンジの上端にかろうじて届くだけ**であり、課金は検出力を上げるがエッジを保証しない。**実行時は新規 EXP として事前登録し直すこと（N-9）** |
| ④U-6 の175上限の見直し | 変更なし（新規 EXP が必要） |
| **⑤（新規）J-Quants 以外の無償源** | **却下。§3.4 の10年分無償 XBRL は実在するが、R-f（株価同伴）を満たさず DS-2 を1日も増やさない**（§4） |

### 7.2 S の見解

- **③を採るなら Light ではなく Standard（¥3,300/月）を推す。** Light の MDE 0.070 は現実的 IC レンジ（0.02〜0.05）の**外側**にあり、**2万円/年を払って再び「判定不能」を買う**ことになる。Standard なら MDE 0.049 で少なくともレンジの上端に触れ、かつ C-5 が同時に解決して**需給スリーブという第2の非価格候補が復活する**（¥3,960/年の増分で得られる副次効果としては大きい）。
- **③と④（U-6 の271銘柄化）は併用できる。** 0-19 の記載（④単独で MDE 0.11→0.068）と③（K 5倍）を素朴に重ねると MDE は 0.03 前後となり、**初めて現実的 IC レンジの中心に届く**。ただし**両方とも新規 EXP の再起票が必要**であり、その spec は S が書く。
- **①（凍結）を採る場合でも、§6.1 の無償 TDnet XBRL 拡張は独立に進める価値がある**（費用¥0、STEP3 の実現可能性そのものを担保する）。

## 8. 再現手順

本調査の主要な実測は、以下で再現できる。

```bash
# (1) EDINET API v2 はキー無しでは 401
curl -s "https://api.edinet-fsa.go.jp/api/v2/documents.json?date=2026-08-07&type=2"
# => {"StatusCode": 401,"message": "Access denied due to invalid subscription key. ..."}

# (2) TDnet 無償インデックスの保持境界（実行日 2026-09-13 時点）
for d in 20260805 20260806; do
  curl -s -o /dev/null -w "$d -> %{http_code}\n" \
    "https://www.release.tdnet.info/inbs/I_list_001_$d.html"
done
# => 20260805 -> 404 / 20260806 -> 200   （38日）

# (3) TDnet 無償の決算短信サマリー XBRL（FSales / FOdP を含む）
curl -s -O "https://www.release.tdnet.info/inbs/081220260807515828.zip"

# (4) 東証上場会社情報サービスの 10年前の XBRL（栄電子 7567・2016-08-09 開示）
curl -s "https://www2.jpx.co.jp/disc/75670/081220160805469074_tse-qcedjpsm-75670-20160809375670-ixbrl.htm" \
  | grep -o 'tse-ed-t:OrdinaryIncome[^>]*CurrentYearDuration_ConsolidatedMember_ForecastMember'

# (5) kabu STATION API の全エンドポイント（財務・業績予想の口が無いこと）
curl -s "https://kabucom.github.io/kabusapi/reference/kabu_STATION_API.yaml" \
  | grep -E '^  /' 

# (6) J-Quants 料金の一次情報（Bot対策の 403 はブラウザ相当 UA で回避できる）
curl -sL -H "User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)" "https://jpx-jquants.com/"
```

東証上場会社情報サービスの銘柄別ページは、`JJK010010Action.do`（セッション）→ `eqMgrCd` POST（検索）→ `JJK010030Action.do` に `BaseJh` ＋ `mgrCd`（5桁）を POST、の3段で到達する（§3.4）。
