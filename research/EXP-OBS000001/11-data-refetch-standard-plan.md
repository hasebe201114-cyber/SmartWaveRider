## 新spec設計への申し送り（S戦略チーム向け）

- 生データは **2016-09-15〜2026-09-14 の約10年分**が揃った。ただし**旧spec（PEAD第3版・ギャップ第3版）の選定/確認期間の基準日は本作業では一切変更していない**（N-9準拠。frozen specをそのまま延伸することはできないため）。
- 新しい選定/確認分割の設計は、この10年分の生データ在庫から**リターンを見る前に**数値基準を固定したうえで、新規EXP番号（EXP-OBS000005/000006等）として起票すること。
- `/equities/master` のスナップショットは旧spec基準日（選定期間確定日・確認期間確定日）のものしか無い。新specで選定/確認の区切りを変える場合、**その基準日時点の `/equities/master` を追加取得する必要がある**（本作業のスコープ外）。
- C-5（需給データ: 投資部門別売買状況・信用残・空売り比率）もStandardプランで解禁されている可能性があるが、本作業では確認していない（`research/ACTIVE.md` 0-14 参照）。

## 訂正: 実体はローリング窓である（2026-09-15追記。上記「背景」節の記述を訂正する）

**上記「背景」節は「`/fins/summary`の契約可能期間の境界: 2016-09-15〜2026-09-14」を固定された境界として記述しているが、これは誤りである。** 正しくは、**`/equities/bars/daily`・`/fins/summary`・`/fins/earnings-date` の3エンドポイントすべてが、クエリ実行日から遡る約10年の「ローリング窓」を返す**（固定された契約開始日を持つ静的アーカイブではない）。

### 発見の経緯

EXP-OBS000005/EXP-OBS000006の§9-1実行中（2026-09-15）、旧511銘柄キャッシュ（本文書に記載の作業で取得。実質的な取得日は2026-09-14）に対し、新たに90銘柄を追加取得したところ、**同じ`/equities/bars/daily`（コード指定のみ）が返す日付範囲が1日前進していた**（旧: 2016-09-15〜2026-09-14 → 新: 2016-09-16〜2026-09-15）。

### 実測で確認した事実（2026-09-15時点）

| エンドポイント | 明示的に `date=2016-09-15` を指定した結果 | 明示的に `date=2016-09-16` を指定した結果 |
|---|---|---|
| `/equities/bars/daily` | HTTP 400: `Your subscription covers the following dates: 2016-09-16 ~` | HTTP 200 |
| `/fins/summary` | HTTP 400（同上メッセージ） | HTTP 200（実データ7件） |
| `/fins/earnings-date` | HTTP 400（同上メッセージ） | HTTP 200（実データ33件） |

**3エンドポイントすべてで同一の境界日・同一のエラーメッセージ**が確認できた。すなわち **`2016-09-15` は2026-09-15時点で既にAPI側から恒久的に取得不能**であり、これは1エンドポイント固有の挙動ではなく、Standardプランのデータ提供方式そのものがローリング窓であることを意味する。

### 本文書「背景」節・「取得結果」表への影響

- 「背景」節の「契約可能期間の境界: 2016-09-15〜2026-09-14」という記述は、**2026-09-14時点でのローリング窓の位置**であり、固定された契約上の境界ではない。**日が経過するごとに境界は1日ずつ後ろへ移動する。**
- 「取得結果」表に記載の各キャッシュ（`fins_summary_all.jsonl`・`bars_daily/`・`earnings_date/`）は、**取得を実行した日（実質的に2026-09-14）のローリング窓のスナップショット**であり、複製不能な一点物である。翌日以降に同じ範囲を再取得することはできない（`2016-09-15`は永久に失われる）。
- **既存キャッシュ自体の正当性は損なわれていない**（取得した時点では窓内にあった正規のデータである）。問題は「今後キャッシュを上書き・再取得すると、当時取得できた最古日が失われる」という不可逆性の方である。

### 実務上の帰結（EXP-OBS000005/000006 spec第2版 §2.0.1・§9-0 で正式に対処済み）

1. **既存キャッシュを `--force` 等で上書き・再取得・削除してはならない。** 上書きした瞬間に失われた最古日は二度と取得できない。
2. **`T`（参照営業日カレンダー）は「観測日付の和集合」ではなく、契約範囲 `[2016-09-15, 2026-09-14]` で明示的に切り取って（ピン留めして）構成する必要がある。** 切り取らないと、取得日が異なる銘柄を混在させた時点で `N` が不安定になる（実測: 混在させると `N=2,442`、ピン留め後は `N=2,441` で prescreen 凍結値と一致）。
3. **Standardプラン解約後は、いかなる銘柄についても10年分を二度と取得できなくなる。** 解約前に必要な全データの取得とバックアップ（`data/raw/` 全体）を完了しておく必要がある。

詳細な論証は `research/EXP-OBS000005/01-spec.md` §2.0.1 および `research/EXP-OBS000006/01-spec.md` §2.0.1 を参照。
