# EXP-OBS000007 - 方向判定要素の候補洗い出し（prescreenレベルの目利き）

> 担当: S戦略チーム（chief-strategist。A設計官兼務）
> `research/_templates/prescreen.template.md` の項目に準拠しつつ、複数候補を横並びで評価する形式（EXP-OBS000003 と同型）を採る。

## 0. 位置づけ（重要）

**本メモは prescreen レベルの目利きで止める。いかなる候補についても spec 起票（実装着手）は行わない。** 司令塔の次の判断（どの候補を spec 化するか、複数並行するか）を待つ。

司令塔提案の要約: 「PEAD（EXP-OBS000005）・ギャップ（EXP-OBS000006）は、どちらも『いつ動くか・どれだけ動くか』（マグニチュード・タイミング）と『どちらに動くか』（方向）を同じシグナルに込めていた。この2つを分離し、方向は別の要素から判断してはどうか」。

**オーケストレータの一次評価（本メモが前提とする留保）**: 今回の2実験の死因は「方向が分からなかった」ことではなく「シグナルと将来リターンの関係自体が不安定・見せかけだった」ことである（PEAD: 確認期間で有意・選定期間で符号反転＝関係の不安定性そのもの。ギャップ: G1-1/G1-4/G1-5/G1-6/G1-7が不合格で、唯一の合格条件G1-3も単一日依存の見かけの合格）。**したがって「方向判定要素を切り出す」こと自体は、今回2件を殺した死因を直接治療しない。** 本メモはこの留保を前提として、それでも着想として筋のある複合戦略（方向要素×マグニチュード/タイミング要素）の**方向側候補**を洗い出すにとどめる。マグニチュード/タイミング側の再設計（PEAD/ギャップをそのまま再利用できるか、それとも新規の検出器が要るか）は本メモのスコープ外であり、別途 S が判断する。

## 1. 束ねない原則の再確認（EXP-OBS000003 §2.1 を踏襲）

複数候補を1本の複合戦略として一度に評価・起票しない。理由は EXP-OBS000003 で確立済み: 束ねると (a) 寄与分解が一意に定まらず、(b) 合成重みの自由度により無エッジでも選定期のフィットは**必ず**改善し、(c) 不採用時に事前確率が更新されない＝**負の結果が資産にならない**。本メモは候補を個別に評価し、GO/却下/保留を候補ごとに判定する。

#### §2.1 候補1の実機確認結果と判定（2026-09-16・B実装チーム0-24報告を受けたS戦略チームの判断）

**実測結果（`research/EXP-OBS000007/10-result/margin_interest_probe.md`）**: `/markets/margin-interest`はStandardプラン下でHTTP 200。`code`指定で銘柄別（トヨタ72030で508件）、`date`のみでも市場横断（2026-09-11でn=4259件）。フィールドは`Date, Code, ShrtVol, LongVol, ShrtNegVol, LongNegVol, ShrtStdVol, LongStdVol, IssType`。**頻度は週次**（508件中7日間隔が460件で最多）。取得可能期間は**2016-09-16〜2026-09-11**（他エンドポイントと同型の10年ローリング窓）。候補ユニバース554銘柄からの決定的サンプル15件は**15/15件でヒット**（母集団554件全件は未確認）。

**判定: 条件付きGO**。当初の解消条件（実機確認でHTTP 200かつ銘柄別粒度と判明すること）はいずれも満たされた。ユニバースは既にPEAD U-1〜U-5（流動性・信用取引可否等）を通過済みの554銘柄であり、「信用取引可否」は既にフィルタ済みのため、信用取引残高データが存在しない銘柄が母集団に紛れ込む可能性は構造的に低いと見積もる（15/15のサンプルヒット率もこれと整合）。**ただし母集団554件全件のヒット率確認は、次段階（spec起票時のDS-1相当ゲート設計）で正式に実施すること**。

**方向の符号仮説（回す前に固定。K-4回避のため、次段階のspecでもここから変更しない）**:

- 変数の候補: 週次信用倍率 `M_t = LongVol_t / ShrtVol_t`、またはその週次変化 `ΔM_t = M_t − M_{t-1}`。どちらを主指標とするかは spec 段階で確定するが、**符号の向きはここで固定する**。
- **固定する符号**: `M`（信用倍率）が高い、または上昇するほど、将来の n 営業日リターンは**負**の方向に偏る、と仮説を固定する。
- **根拠（結果を見ずに演繹できる、取引制度そのものからの理由）**: 制度信用取引の返済期限（一般に6か月以内）により、信用買い残（`LongVol`）の積み上がりは「将来必ず反対売買（売り）をしなければならない」という**強制的な将来の売り圧力**を意味する（「戻り待ちの売り」）。逆に信用売り残（`ShrtVol`）の積み上がりは将来の買い戻し（踏み上げ）圧力を意味し、将来リターンにポジティブに働く。**この論理は返済期限という制度構造から演繹されるものであり、過去の値動きパターンから逆算したものではない**ため K-4（HARKing）に該当しない。日本の制度信用が米国のfree margin debt（明確な返済期限を持たない）と異なるという構造的差異が、「なぜ日本株で機能しうるか」の根拠になる（PEAD/ギャップのprescreenが要求した「日本株固有の構造的差異の明示」と同じ形式の説明）。
- **反対の解釈への対処**: 「信用買い残の急増＝強気な投資家の増加を示すポジティブなシグナル」という逆の解釈も文献上存在することを認識しているが、**本メモでは制度的な返済圧力の論理を主仮説として固定する**。将来この仮説が誤りだと判明した場合、それは**符号の見直しではなく候補1のKillとして扱う**。符号を反転させて再挑戦することは HARKing として禁止する。

**週次頻度がPEAD/ギャップ型（日次）マグニチュード/タイミング検出器との掛け合わせに与える影響（design原則5の具体化・新規の必須確認事項）**:

1. **【最重要・未解決】Point-in-time公表ラグが未確認**: レスポンスには基準日を示す`Date`のみが含まれ、**公表日（いつ市場に開示されたか）を示すフィールドが存在しない**（実機確認で確認済み）。東証の実務慣行では信用取引残高は基準日から数営業日後に公表される。**この公表ラグを実測・確定しないまま先読みなしにG1検定を組むことはできない**（姉妹PJ EXP-OBS000037の窓算術の教訓、および EXP-OBS000003 の配当落ち日 point-in-time 構成と同型の注意点）。**spec起票の前提条件として、公表ラグの実測をB実装チームへの先行タスクに含めることを推奨する**
2. **観測単位の粒度不一致**: PEAD/ギャップ型は日次イベント、信用倍率は週次更新。同一週内に複数のイベントが発生した場合、それらは同一の方向シグナル値を共有する＝疑似的なクラスタリングが生じうる（C-7の日次ブロック統計問題が週次でも再発しうる）。spec段階で「週次ブロック統計」の要否を検討すること
3. **鮮度の劣化**: イベント発生時点で参照できる直近の信用倍率は、公表ラグ次第で最大2週間近く古い値になりうる。方向要素単独のG1検定でも、「イベント日のT-1時点で入手可能だった最新の公表値のみを使う」という設計が必須

**次のステップの位置づけ**: **候補1は単独G1検証へ進める段階に昇格したが、複合戦略全体のspec起票ではなく、まず「信用倍率単独の方向予測力」を検定する新規specをS（A設計官兼務）が起票することを推奨する**（design原則1）。この新規specでG1相当（方向一致率・IC・permutation p値、選定/確認分割）に合格して初めて、PEAD/ギャップ型の検出器（ただし design原則3 により「方向予知は死んだが値動きの大きさ・タイミング予知は未検定」の区別のもとで再設計されたもの）との固定ルール合成を検討する。**この2段階を1つのspecに縮約しない**（合成重みの自由度を混入させないため）。

**契約の時限性を踏まえた緊急の推奨事項**: J-Quants Standard契約は「1ヶ月以内完了・月末解約」の運用であり、**spec設計・G1測定の完了を待たず、候補ユニバース（554銘柄、または271銘柄）の信用取引残高10年分の生データを今すぐ一括取得し`data/raw/`へ永続化することを強く推奨する**（PEAD/ギャップの10年データ再取得＝0-23実行計画と同じ考え方）。生データさえ確保できれば、契約解約後もspec設計・G1測定は生データに対して進められる。**これは司令塔への提案であり、S単独では実行を指示しない**（B実装チームの起動は司令塔／オーケストレータの判断）。

### 候補5: セクター/市場全体のトレンド（マクロレジーム）

| 項目 | 内容 |
|---|---|
| エッジ源泉 | 金利・為替・日銀短観・米国株等の外生的な状態変数によるレジーム判定 |
| 価格由来か | 否（ただし為替ベータ等の横断設計に逃げると価格由来に退化する。EXP-OBS000003既述） |
| データ取得可能性 | FRED API・日銀時系列統計データ検索サイトで無償取得可（実測済み） |
| 既存の判定 | **既に独立スリーブとして却下済み**（EXP-OBS000003 §6.3・2026-09-13）。理由: ①検証期間約2年では有効n不足（日銀短観8観測、金利・為替の独立エピソード5〜15回）②在庫ゼロでゲート設計が成立しない③OBS000018型（固定閾値レジームゲート＝蜃気楼）の再演④横断設計に逃げると価格由来に退化⑤OBS000027の罠への最短経路 |
| 本メモでの再評価（方向要素としての用途） | **②（在庫ゼロ）は本メモの文脈では該当しなくなる**（掛け合わせ対象を探す文脈そのものであるため）。しかし①・③・④・⑤は依然として有効。加えて**新たな構造的不適合**を指摘する: レジーム変数は連続的でイベント境界を持たないため、PEAD/ギャップのようなdiscreteイベント単位のG1検定枠組みに素直に乗らない。「レジーム条件下でのPEAD/ギャップの方向一致率」という条件付き分析に頼ると、それは実質的に**イベント発生後の事後的サブグループ分析**であり、確認期間のリターンを見てからフィルタ条件（どのレジーム変数・どの閾値）を選ぶことと外形的に区別できず、**K-4（HARKing）に極めて近い設計になる** |
| 判定 | **却下（本用途にも不適）**。既存の却下理由に加え、「方向要素はまず単独で検証すべき」という本メモの設計原則（§3）に構造的に乗らないことが決定打 |

## 3. 掛け合わせ設計の原則（OBS000027型の罠を避けるため）

複合戦略（マグニチュード/タイミング検出器 × 方向要素）を将来spec化する際に、**回す前に**必ず適用すべき設計原則を以下に固定する。

### 原則1: 方向要素は、掛け合わせる前に単独でG1相当を検証する

方向要素の候補（信用取引残高・大量保有報告書等）は、まず**それ自身のイベント定義**（例: 信用倍率が閾値を超えた日、大量保有報告書の提出日）で、方向一致率・IC・permutation p値を独立に測定する。マグニチュード/タイミング検出器（PEAD/ギャップ型）と組み合わせた後の成績だけを見て採否を判断してはならない。理由: 単独での予測力を経ずに合成すると、**合成重みの自由度によって無エッジの方向要素でも選定期の成績が改善しうる**（EXP-OBS000003 §2.1 が束ね設計を禁じた理由そのもの）。

### 原則2: 合成は固定ルールのみ。最適化しない

方向要素とマグニチュード/タイミング検出器を組み合わせる規則（例: 「イベント発生日に方向要素の符号が正なら買い、負なら売り、方向要素が閾値内で中立ならスキップ」）は、**両方の単独検証が完了する前に、数値を伴う形で固定する**。選定期間のリターンを見てから重み・閾値・組み合わせ方（AND/OR、加重平均等）を選ぶことは禁止する。本PJの既存4戦略の配分ルール（`research/config/parameter-set.json`でバージョン管理・逆ボラティリティ加重を選定期間で凍結）と同じ規律を適用する。

### 原則3: マグニチュード/タイミング検出器側も「死んでいない」ことを別途確認する

PEAD・ギャップはいずれもG1（予測単位＝符号込みの方向予測）でKillされた。**しかしこれは「イベント発生自体が将来の値動きの大きさ・タイミングを予知する」という、より弱い主張までは否定していない**（両EXPともG1は方向一致・IC等を測る設計であり、「イベント発生の有無が将来ボラティリティ・出来高を予知するか」は一度も検定されていない）。複合戦略でPEAD/ギャップ型のイベント検出をマグニチュード/タイミング要素として再利用する場合、**「イベント発生が方向を予知する」という主張（Kill済み）と、「イベント発生が値動きの大きさ・タイミングを予知する」という主張（未検定）を明確に区別し、後者について改めてそれ自体のG1相当検証を行う**必要がある。この区別を曖昧にしたまま「PEAD/ギャップは死んだが検出器としては使える」と前提するのは危険である。

### 原則4: 条件付きサブグループ分析によるHARKingの回避

方向要素×マグニチュード/タイミング検出器の組み合わせは、本質的に「マグニチュード/タイミング検出器のイベント集合を、方向要素でサブグループ分割する」設計になりやすい。**確認期間のリターンを見てから、どの方向要素・どの閾値がそのサブグループ分割に「効く」かを探すことは、候補5（マクロレジーム）で指摘したとおりK-4（HARKing）と外形的に区別できない**。サブグループ分割の規則（どの方向要素を使うか、閾値はいくつか）は、確認期間のリターンは元より選定期間のリターンさえ見る前に、方向要素単独の検証（原則1）の結果だけをもとに固定すること。

### 原則5: 選定/確認データの分離を、方向要素とマグニチュード/タイミング要素それぞれに独立して適用する

一方の要素の選定作業に、他方の要素の確認期間データを混入させない。特に、PEAD（確認窓 2021-09-16〜2026-08-21）・ギャップ（同型の10年版）は**このSUE定義・このギャップ定義について確認期間のリターンが既に既知になっている**（N-9）。複合戦略で同一の定義・同一の確認窓を再利用する場合、それは新規の事前登録として扱い、「未見」と主張してはならない。
