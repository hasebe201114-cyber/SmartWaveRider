## 1. HTTP 200 の可否

`/markets/margin-interest` に対し、`JQuantsClient`（`scripts/lib/jquants_client.py`）経由で `code=72030`（トヨタ自動車）を指定してGETした結果、**HTTP 200 が返った**。STEP0時点（`scripts/step0_api_probe.py`記載）ではHTTP 403だったが、Standardプラン契約下（0-23）で解禁されている。

代替パスの探索は行っていない（主エンドポイントが最初からHTTP 200のため）。

## 2. レスポンスのフィールド構成・粒度

- トップレベルキー: `data`（リスト）
- 1レコードのフィールド: `Date`, `Code`, `ShrtVol`, `LongVol`, `ShrtNegVol`, `LongNegVol`, `ShrtStdVol`, `LongStdVol`, `IssType`
- 銘柄別粒度: `code` パラメータ指定で銘柄単位のデータが返る（トヨタ72030で508件）
- `date` のみ指定（`code`省略）でも200が返り、その日の**市場横断データ**が返る（`date=2026-09-11`でn=4259件）
- **頻度は週次**（日次ではない）。508件のレコード間隔を実測すると、7日間隔が460件で最多。6・8・9・14・15日間隔も混在（祝日・年末年始等によるずれと推定されるが、原因の特定は本タスクの範囲外）
- 加算関係を実測で確認: `ShrtNegVol + ShrtStdVol == ShrtVol`、`LongNegVol + LongStdVol == LongVol`（サンプル1件・トヨタ2016-09-16分で厳密一致）
- 信用倍率（買い残/売り残の比率）そのものを表す単一フィールドは存在しない。`LongVol`・`ShrtVol`から算出する必要がある（本タスクでは未算出）
- `IssType` はサンプル3銘柄（72030・13320・99890）すべてで値`"2"`のみ観測。値の意味（公式定義）は本タスクでは確認していない

## 3. 取得可能な履歴期間（ローリング窓の境界を実測）

`research/EXP-OBS000001/11-data-refetch-standard-plan.md`「訂正: 実体はローリング窓である」節と同じ手法（境界日を明示`date`指定してHTTP 400になる日を探る）で実測した。

| 指定日 | 結果 |
|---|---|
| `2016-09-09` | HTTP 400（`Your subscription covers the following dates: 2016-09-16 ~`） |
| `2016-09-15` | HTTP 400（同上メッセージ） |
| `2016-09-16` | HTTP 200（n=1） |

**下限境界: 2016-09-16（2026-09-16実行時点）。** `code`指定なしの全期間取得（トヨタ）の最古レコードも`2016-09-16`と一致する。この境界は`/equities/bars/daily`等と同型のローリング窓（クエリ実行日から遡る約10年）と整合する挙動であり、翌日以降に再実行すると1日前進すると見込まれる（実測はしていない）。

最新側（上限）は明示的な400探索を行っていない。`code`指定の全期間取得での最終レコードは`2026-09-11`（週次データの直近公表分）。
