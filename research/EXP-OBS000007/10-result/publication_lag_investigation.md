## 2. 実測（ローカルデータ）による補助的確認

`data/raw/margin_interest/`（0-25で取得済み・554銘柄・270,081レコード全件）の`Date`フィールドの曜日分布を集計した。

| 曜日 | 件数 | 割合 |
|---|---|---|
| 金曜日 | 260,998 | 96.6369% |
| 木曜日 | 7,467 | 2.7647% |
| 水曜日 | 1,616 | 0.5983% |

再現コマンド:
```bash
cd /home/user/SmartWaveRider
python3 -c "
import json, glob, datetime, collections
files = [f for f in sorted(glob.glob('data/raw/margin_interest/*.json')) if 'state' not in f]
weekday_counter = collections.Counter()
total = 0
for fp in files:
    with open(fp) as f:
        d = json.load(f)
    for rec in d:
        dt = datetime.date.fromisoformat(rec['Date'])
        weekday_counter[dt.strftime('%A')] += 1
        total += 1
for k, v in sorted(weekday_counter.items(), key=lambda x: -x[1]):
    print(k, v, f'{v/total*100:.4f}%')
"
```

金曜日が96.6%を占め、木曜・水曜が残りを占める分布は、§1.2で確認した公式フィールド定義「通常は金曜日付」（祝日等でその週の最終営業日が金曜日以外になる場合がある）と整合する。**ただし、この曜日分布だけからは公表ラグそのものは特定できない**（依頼メモの注記どおり、あくまで補助情報として記録する）。

また、`2026-09-11`（金曜日）が0-24・0-25で確認したJ-Quants側データの最新申込日であり、これはJPX公式ページ（§1.3）に掲載されている最新の公表ファイル「2026年9月11日申込分」と一致する。JPX公式通知PDF（§1.5）の日程表では、この「9/11分」は暦日`2026-09-15`（火曜日）に公表されると記載されている。`2026-09-11`→`2026-09-15`の営業日差を計算すると、`2026-09-12`（土）・`2026-09-13`（日）は非営業日、`2026-09-14`（月）が1営業日後、`2026-09-15`（火）が2営業日後であり、**§1.1・§1.3で確認した「基準日から通常2営業日後（翌週火曜日）」という記述と数値的に一致する**。

## 3. 確定できた事実（まとめ）

1. **`/markets/margin-interest`（信用取引週末残高）のレスポンスに公表日フィールドは存在しない**（J-Quants公式ドキュメントのフィールド定義でも確認。0-24実機確認の再確認として一致）。
2. **公表タイミングはJ-Quants公式ドキュメントに明記されている**: 「週次(第2営業日)　16:30頃　通常は火曜日、祝日等非営業日がある場合はその分後ろ倒し」（`https://jpx-jquants.com/ja/spec/data-update`）。
3. **基準日（`Date`）の定義**: 「信用取引残高基準となる時点」＝「通常は金曜日付」（同ページの`mkt-margin-int`フィールド定義）。
4. **上記2点を組み合わせると、調査時点（2026-09-16）で有効な仕様下での公表ラグは「基準日から通常2営業日後（金曜基準日→翌週火曜16:30頃公表）」と確定できる**。この数値はJ-Quants公式ドキュメント（2ページ）・JPX公式ページ・JPX公式通知PDF（2件）の計4情報源で相互に整合しており、B実装チームによる一般知識・記憶からの推測ではない。
5. **祝日等で基準日または公表日側の営業日がずれる場合、上記「通常2営業日」からさらに後ろ倒しになる**（公式ドキュメントに明記）。後ろ倒しの具体的な日数分布（例: 年間で何回・何営業日ずれるか）は、公式ドキュメントの一般的な記述として確認したのみであり、**全期間にわたる網羅的な実測は本タスクでは行っていない**（4.項参照）。
6. **重要な留保（未来の仕様変更）**: JPX公式通知（2026年7月6日付）により、**本エンドポイントは2026年9月28日（月）に新仕様へ移行予定**。新仕様では公表頻度が週次から毎営業日に変わり、申込日（基準日）は前営業日となる（実質的なラグは1営業日程度に短縮される見込み）。J-Quants公式APIリファレンスにも「本APIは2026年9月28日に新仕様での提供を開始予定」と明記されている。**ただし移行は2026-09-27のシステム移行可否を踏まえて実施されるため、2026-09-16時点では未確定の予定であり、本調査では移行後のJ-Quants API側の実際のレスポンス仕様（フィールド名・粒度）を実機確認していない**（移行前のため実機確認不可能）。
7. **0-25で取得済みの10年分生データ（`data/raw/margin_interest/`）は、上記の「現行仕様（週次・2営業日ラグ）」下でのスナップショットである**。2026-09-28以降に同エンドポイントを再取得すると、異なる公表頻度・ラグ構造のデータになる可能性がある。

## 4. 未確定・未実施の事項（正直な申し送り）

- **祝日を挟んだ場合の公表ラグの正確な営業日数の網羅的実測**: 公式ドキュメントは「通常は火曜日、祝日等非営業日がある場合はその分後ろ倒し」という定性的な規則のみを記載しており、「具体的に何営業日ずれるか」を年間全パターンで数え上げる実測は行っていない。祝日が基準日側（週の最終営業日が金曜以外になる）・公表日側（火曜が祝日）のどちらで発生するかにより後ろ倒しの日数が変わりうる。§2のローカルデータ曜日分布（木曜2.76%・水曜0.60%）は基準日側のずれの実例であり、公表日側のずれについては実測していない。
- **2026年9月28日以降の新仕様でのJ-Quants API実機確認**: 移行前のため実施不可能。移行後に改めて実機確認が必要（B実装チームへの将来タスクとなる可能性がある）。
- **J-Quants API側でのデータ反映が、JPX公式サイトでの公表と完全同時か、追加のシステム的ラグ（数分〜数時間程度）があるかの厳密な実機比較**: §1.2でJ-Quants公式ドキュメントが「配信データは下記のページで公表している内容と同一」と述べていることから、追加ラグは想定しにくいと文書上は読み取れるが、**J-Quants APIのレスポンスが実際に火曜16:30ちょうどに更新されるかどうかを秒単位で実測する検証は本タスクでは行っていない**（更新タイミングページの「16:30頃」という表現自体が目安であることも公式記載どおり）。
