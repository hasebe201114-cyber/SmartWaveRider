## A-0. なぜ新規EXPなのか、そして**なぜ今回は再挑戦する価値があるのか**

EXP-OBS000003 は §6.0 のデータ十分性ゲートで停止した（DS-2a / DS-5 / DS-6 / DS-7 の4つが不合格・K-5 保留）。S は第3版 §6.0.1(g) で「**本 spec の枠内で §6.0 を充足させる再設計は存在しない**」と結論している。その決定的根拠は §6.0.1(a):

> DS-6 の計数対象はイベント集合 `E` ではなく**プール `P`**（`z ≤ −1.5`）であり、`z*` は `P` の定義に一切入らない。**したがって `z*` の較正をどう引き直しても実測 62日は動かない。**

**この論証は「契約データ期間を固定したまま」という条件下でのみ成立する。** DS-6 は「プールの日次ブロックのうち5件以上を持つ日数」であり、**期間の長さに概ね比例して増える量**である。10年データ（約2,440営業日）は2年データ（487営業日）の約5倍であり、**`z*` を一切動かさずとも DS-6 の母数が5倍になる。** これが本EXPを再挑戦に値するものにしている唯一かつ十分な理由である。

> **重要**: 本EXPは「基準を緩めて通す」のではない。**閾値は1つも動かさず、母数だけを増やす。** 旧EXPが停止した4ゲート（DS-2a / DS-5 / DS-6 / DS-7）のうち、DS-5・DS-6・DS-7 は期間の長さで直接改善しうる量であり、DS-2a は較正グリッドの範囲不足という**選定期間のみの情報から診断済みの設計不備**である（旧 spec §6.0.1(b)）。

```

```

| 区分 | ユニバース確定日 `D_u` | U-4 窓（`D_u` を含まない直前60営業日） | イベント日 `D` の範囲 |

| **確認（未見）** | `D_conf = T[m + 1]` | `T[m − 59]` 〜 `T[m]`（**ちょうど60本・`Va` は銘柄あたり60個**） | **`T[m + 1]` 〜 `T[N − 11]`** |

### A-2.1 なぜ `floor(N/2)`（時系列50/50）なのか（**実測を一切見ずに言える理由のみ**）

| # | 理由 |
|---|---|
| 1 | **自由度がゼロである。** 分割点は `N` のみから機械的に決まる従属変数であり、こちらが選んだ値ではない |
| 2 | **確認期間を最大化する方向に働く。** 本EXPが座礁した DS-5（相異なるイベント日数）・DS-6（プール日次ブロック数）は**いずれも確認期間の長さに概ね比例する量**であり、確認期間を短くする分割は死因を温存する |
| 3 | **選定期間の自由度は `z*` の1個だけ**（旧 spec §2.3）であり、それも**カウントのみを入力とする決定的手続き**（§3.6）である。選定期間に5年あれば較正には十分すぎる |
| 4 | **時系列順（古い側を選定・新しい側を確認）にする。** 確認期間は本番運用に時間的に最も近い区間であるべき |
| 5 | **PEAD（EXP-OBS000005）と同一の分割規則を使う。** 2本のEXPで異なる分割を使うと、どちらかが「都合の良い分割を選んだ」という疑いを構造的に免れない。同一規則にすることでその疑いを消す |

### A-2.2 イベント日の開始添字が `68` である算術的根拠（**T-8・trading-app-v2 EXP-OBS000037 の教訓**）

旧 spec §2.1 の論証をそのまま引き継ぐ。

- `σ_gap(j, D)`（`D = T[i]`）は、**`T[i−66]` 〜 `T[i−1]` の範囲にある有効ギャップのうち新しい順にちょうど60本**を採る（旧 spec §3.2）。
- その範囲で最も古いギャップ `g(j, T[i−66]) = ln( O(j,T[i−66]) / C(j,T[i−67]) )` は**終値 `C(j, T[i−67])` を要する**。
- ゆえに `i − 67 ≥ 1`、すなわち **`i ≥ 68`**。
- 同時に `D` はユニバース確定日 `T[61]` より後でなければならない（`68 > 61` で充足）。
- **⇒ 両条件を同時に満たす最小の添字が 68。**

### A-2.3 前方窓の算術的整合性（**本数と対象範囲の対応を明記する**）

イベント日を `D = T[i]` とする。

| 用語 | 営業日の本数 | 対象となる `T` の添字 | 必要な価格の個数 |
|---|---|---|---|
| ギャップ `g(j,D)` | 1本のオーバーナイト窓 | `T[i−1]` の終値 と `T[i]` の始値 | **価格2個**（`C(T[i−1])` と `O(T[i])`） |
| `σ_gap` の窓 | **有効ギャップちょうど60本** | `T[i−66]` 〜 `T[i−1]` の範囲（**遡り上限66営業日**） | ギャップ60本 ⇒ 参照する終値/始値は最大で `T[i−67]` まで |
| エントリー日 `t_1` | 1本 | `T[i+1]` | 始値 `O(T[i+1])` 1個 |
| 予測単位 `R_5`（H=5営業日） | **5本のホライズン** | `t_1 = T[i+1]` 〜 `t_5 = T[i+5]` | **`R_5 = C(T[i+5]) / O(T[i+1]) − 1`。始値1個＋終値1個＝価格2個**（隣接差分の連鎖ではないため「H+1個」ではない） |
| 最大保有（5営業日）＋時間切れ決済 | 5本の保有＋決済1本 | `t_1 = T[i+1]` 〜 `t_5 = T[i+5]`、決済は `t_6 = T[i+6]` の**始値** | 添字は `i+6` まで |
| `SELL_BLOCKED` による持ち越し上限 | **＋5本** | 最悪で `T[i+11]` | 添字は `i+11` まで |
| **⇒ イベントに必要な添字の範囲** | — | **`i − 67` 〜 `i + 11`** | — |

- したがってイベント日の添字 `i` は **`68 ≤ i ≤ N − 11`**（確認期間は `m+1 ≤ i ≤ N − 11`、選定期間は `68 ≤ i ≤ m − 11`）を満たす。
- **選定期間側にも `−11` の余白を置く理由**: 余白が無いと選定期間末尾のイベントの前方窓が確認期間の先頭に食い込み、「選定期間の測定」が確認期間の価格を観測してしまう。旧 spec（選定末 2025-06-30／確認始 2025-07-01）はこの重なりを持っていた。**本EXPは構造的に排除する。基準の緩和ではなく分離の強化である。**
- **イベント集合は G1・G2 で共通に定義する。** 上記の添字範囲は G1（`i+5` まで）と G2（`i+11` まで）の**両方**を満たすよう `i ≤ N−11` で統一しており、「測定ごとに異なるイベント集合を使う」ことを構造的に排除する。
- `m`・`N`・各実日付は `T` から機械的に求め、`params.json` に出力する。**推定日付をハードコードしてはならない。**

## A-4. `z*` 較正グリッドの範囲拡張（**閾値の緩和ではない**）

| 項目 | 旧 EXP-OBS000003 | 本EXP | 性質 |
|---|---|---|---|
| グリッド | `{−1.50, −1.75, …, −4.00}`（0.25刻み・**11点**） | **`{−1.50, −1.75, …, −8.00}`（0.25刻み・27点）** | **範囲の拡張のみ。刻み幅 0.25 は不変** |
| 目標年換算件数 | 215件/年 | **215件/年（不変）** | — |
| 選択規則 | `|N_ann(z*) − 215|` 最小、同値はより極端側 | **不変** | — |
| 年換算定数 | 245営業日/年 | **不変** | — |
| DS-2a の帯 | `[150, 300]` | **不変** | — |
| DS-2b の帯 | `[100, 400]` | **不変** | — |

**拡張の根拠（確認期間を見ずに言える）**: 旧 spec §6.0.1(b) が**選定期間のみの実測**として記録したとおり、`z` の p01 は **−6.235**（選定期間）であり、標準正規を下半分に切断した理論分位点（p01 ≈ −2.58）から大きく外れている。**グリッド上限を `−4.00` に置いた設計は、テールが概ね正規に近いという暗黙の前提に立っており、その前提は選定期間の測定だけで既に否定されている。** 本EXPは新しい選定期間を持つが、日本株のギャップ分布がファットテールであるという性質は期間に依らない。**したがって範囲の拡張は、確認期間の情報を用いずに正当化できる。**

> **なぜこれが HARKing でないか**: (i) 拡張の根拠は**確認期間の件数分布ではなく、frozen 済みの旧 spec に記録された選定期間の分位点**である。(ii) 選択規則が `|N_ann − 215|` の最小化である以上、グリッドを細かく/広くすることは**目標 215 により近づける方向にしか働かず、「良い結果が出る点を選ぶ」余地を作らない**（`N_ann` は `z*` について単調）。(iii) **DS-2a / DS-2b の帯そのものは1ミリも動かしていない。**

### A-4.1 `N_ann` の分母の一意な定義（**旧 spec §3.6 の曖昧さを修復する**）

旧 spec は `N_ann = 件数 × 245 ÷ (選定期間のイベント日数)` と書いたが、「選定期間のイベント日数」が3通りに読めた（旧 spec §3.6 第3版注記）。**本EXPでは `T` の添字から一意に再計算できる式として定義する。**

```
n_sel_eff := #{ i | 68 ≤ i ≤ m − 11 かつ T[i] が E-2B の一括除外日でない }
N_ann(z*) := (選定期間の候補イベント件数) × 245 ÷ n_sel_eff
```

- **E-2B** = 各暦月の最終営業日の1営業日前 `X(m)` を全銘柄共通で除外する規則（旧 spec §3.1.1）。`X(m)` は `T` と暦のみから決まり、価格を参照しない。
- 確認期間側の `N_ann` も同様に `n_conf_eff := #{ i | m+1 ≤ i ≤ N − 11 かつ T[i] が E-2B の除外日でない }` を分母とする。
- **B実装チームは `n_sel_eff` / `n_conf_eff` を必ず `params.json` に出力すること。**

### A-5.1 重大論点 C-7 の3点チェック
