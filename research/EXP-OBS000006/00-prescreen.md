## 4. 【D-10 の適用】イベント発生日分布の事前スクリーニング（**リターンを見ずに件数のみで測る**）

> **旧EXPは、まさにこのスクリーニングを prescreen 段階で行っていなかったために、spec を3版重ねて B が9タスクを完走した末に DS ゲートで座礁した**（`STRATEGY-BRIEF.md` 重大論点 C-7・司令塔判断 D-10）。**本書はその教訓を最初に適用する。**

入力は旧EXPが実測したカウントのみ（`research/EXP-OBS000003/10-result/feasibility.json`）。**リターンは一切使わない。**

| # | 測る量 | 旧 spec の実測（確認期間 2025-07-01〜2026-06-12・**220イベント日**） | 10年化後の期待値（期間比例の外挿・確認期間は約1,635営業日） | 旧 spec の閾値 | 判定 |
|---|---|---|---|---|---|
| **(i-a)** | プール観測数（`z ≤ −1.5`） | **1,586件** | 約 **11,200件** | ≥1,500件（合格） | 良好 |
| **(i-b)** | プールが分布する相異なる日数 | **167日** | 約 **1,180日** | — | 良好 |
| **(i-c)** | `IC_bar` の算出対象日数 `K`（プール5件以上の日） | **62日** | 約 **440日** | ≥100日（**不合格**） | **旧EXPの決定的な死因が構造的に解消する** |
| **(i-d)** | 相異なるイベント日数 `K_event` | **25日** | 約 **176日** | ≥80日（**不合格**） | **解消する** |
| **(ii)** | 最大単日イベントシェア | **52.83%**（`2026-03-09` に 56/106件） | 期間が7.4倍になるため、同じ規模の単日が占めるシェアは **約7%** | ≤25%（**不合格**） | **解消する** |
| **(iii)** | 選定期間と確認期間のテール発生率の比 | **3.2倍**（`z ≤ −4.00` の候補比率 選定2.28% / 確認0.71%） | **改善するが解消しない**（§4.1） | — | **残存リスク** |

### 4.1 (iii) が残存リスクであることの明示（**GO を出すが、隠さない**）

- 旧EXPが実測した最も重要な構造は、**「日本株の極端下方ギャップは市場共通因子に支配される群発過程であり、選定期間で較正した閾値が確認期間へ転送されない」**ことであった。原因は、旧分割では**選定期間が実質9ヶ月・確認期間が実質11ヶ月**しかなく、**それぞれが1〜2回のストレス・エピソードで代表されてしまった**ことにある。
- 新しい分割では**選定期間が約3.0年（737イベント日）・確認期間が約6.7年（1,635営業日）**となり、**両期間がそれぞれ複数のストレス・エピソードを含む**。したがってテール発生率の期間間ばらつきは平均化され、転送性は改善する。
- **しかし解消は保証されない。** 特に、確認期間はコロナ・ショックを含むため、**選定期間（2016-12〜2019-12）より確認期間のテールが厚くなる方向の乖離**が起こりうる。その場合、選定期間で較正した `z*` は確認期間で**過剰にイベントを生成**する。
- **⇒ spec §6.0 の DS-2b（確認期間の年換算イベント件数 `N_ann` ∈ [100, 400]）が、この失敗様式を回す前に検知するゲートとして機能する。** 400 を超えればイベント駆動から常時フル投資へ退化し、EXP-OBS000002 と同じコスト構造で死ぬため、**G1 へ進まず S へ差し戻す**。
- **この残存リスクを理由に DS-2b の上限を緩めることを禁止する。**

## 5. 過去の不採用パターンとの重複チェック

### 5.1 `portfolio-ledger.md` の不採用一覧との重複

- **EXP-OBS000002（クロスセクショナル価格ファクター）との差**: 却下の決定打だったコスト算術の適用結果が異なる。OBS000002 は**常時フル投資の横断ランキング**でコストが建玉全体の回転に比例し「年率0.5%のスプレッドから年24.5%を捻出せよ」＝40〜50倍不足だった。本EXPは**イベント駆動**でコストがイベント件数に比例し「選別した年215件の極端イベント1件あたりグロス0.45%」＝必要倍率は**およそ2倍以内**である。**ただしイベント件数が想定を大きく超えれば常時フル投資に退化して同じ理由で死ぬため、DS-2b で件数の上限をゲート化している**（§4.1）。
- その他（業種区分単体・マクロ・板情報・決算発表予定日・TDnet インデックス単体）とは**いずれも重複しない**（シグナルの入力が異なる）。

### 5.2 trading-app-v2 から輸入した負の資産との重複

- **OBS000022 は台帳に行が存在せず未チェックである**（ACTIVE 0-17・未解消）。**本 prescreen は「全件実施した」と主張しない**（旧 prescreen と同じ留保を引き継ぐ）。
- チェックできた9件（018/019/025/027/028/029/030/031/038）について:
  - **OBS000018（固定閾値＝蜃気楼）**: 主指標を連続値 `z` の Spearman IC とし、デシル単調性 G1-5 を合否ゲート化することで構造的に対処。
  - **OBS000027（足し算）**: 在庫ゼロで単独検定。N-2 で合成を禁止。
  - **OBS000029（実質1本張り）**: DS-7（最大単日シェア ≤25%）・**DS-7b（上位5日の合計シェア ≤50%・新設）**・G1-7（最大イベント日を除いた再計算）・§5.3-8（同一イベント日2銘柄上限）の**4重**で対処。
  - **OBS000030（ブレッド拡張は救わない）**: ユニバースを TOPIX500 相当の外へ広げない。**10年化は銘柄数ではなく期間を増やすものであり、OBS000030 が否定した方向ではない。**
  - **OBS000025（予測単位◎・パイプラインで死亡）**: **本EXP最有力の死因として名指しされている**（旧 prescreen §5.2）。G1・G2 の両方を測り、G2-7（往復0.60%でも損益分岐を割らないこと）を合否ゲート化して対処。

## 6. コスト前提（回す前に置く。旧 spec から一切変更しない）

| 項目 | 片道 | 往復 |
|---|---|---|
| スプレッド（呼値の半値） | 0.05% | **0.10%** |
| **スリッページ（寄付の板寄せ）** | **0.100%** | **0.20%** |
| 委託手数料 | 0.05% | **0.10%** |
| 信用買方金利（5営業日 ≒ 7暦日） | — | **0.05%** |
| **往復コスト合計** | — | **0.45%** |

- **損益分岐グロス = 0.45%/トレード**（G1-3 のゲート値）。**Sharpe 1.0 到達に必要なグロス = 0.85%/トレード**（報告基準・ゲートではない）。
- **必要勝率 = 59.4%**（初期損切 −4.0%・利益側名目 +4.0%・往復0.45%・翌営業日始値約定ギャップ0.30% を織り込んだ再計算）。
- **年間コスト** = 215件 × 25万円 × 0.45% = **24.2万円 ＝ 資本比 24.2%/年**。
- **10年化にともなう注意（新規）**: 2019年以前の実効コストは上記より高い（消費税率・手数料自由化）。**偏りは選定期間に限局し、合否を担う確認期間（2020-01〜）には及ばない。**

## 7. GO の理由（回す前に言えること）

1. **旧EXPを停止させた4つの不合格（DS-2a / DS-5 / DS-6 / DS-7）のうち、DS-5 / DS-6 / DS-7 の3つは期間の7.4倍化によって構造的に解消する見込みである**（§4）。残る DS-2a（事前登録グリッドが実測テールを覆っていなかった設計欠陥）は、**グリッドを −8.00 まで広げることで修復する**——これは**目的関数・目標件数215・タイ規則を一切変えない、設計欠陥の修復**である（spec §3.6）。
2. **本EXPの検出力は本プロジェクトで最も高い。** 確認期間の期待 `K ≈ 440日`・`n_d ≳ 10` から **MDE(`IC_bar`) ≈ 0.026** となる一方、**G1-3 が要求する経済的な IC 水準は約 0.062〜0.070** である（spec §6.1.5）。**⇒ 統計的検出下限が経済的必要水準の半分以下であり、「エッジが無い」と「エッジはあるが小さすぎて取れない」を分離して判定できる。**
3. **⇒ 本EXPが G1 未達となった場合、それは「検出力不足」ではなく「エッジ不在」の証拠として `portfolio-ledger.md` に不採用記録できる。** これは本PJにとって**初の、十分な検出力下での負の結果**となる。本PJはこれまで2件連続で「リターンを一度も見ないまま判定不能」に終わっており、**この状態を脱すること自体に大きな戦略的価値がある**（価格由来の方向予測族が日本株でも枯れているのかを、初めて自前の測定で確かめられる）。
4. **測定範囲の空白 B-1（確認期間の独立ストレス・エピソードが実質1回）が解消する。** 本EXPの賭けは「市場ストレス時の売り需給の偏りの解消」であり、**ストレス・エピソードの数こそが本EXPの実効サンプル数**である。ここが1回から複数回になることは、期間延長の効果として最も本質的である。
5. **追加のデータ費用は発生しない**（Standard 契約は決裁済み。本EXPが使う `/equities/bars/daily`・`/equities/master`・`/fins/summary`・`/fins/earnings-date` はすべて Standard の範囲内）。
6. **配当落ちの識別手続き（旧 spec §3.1.1・E-2A/E-2B）は B の独立再実行で V-1〜V-5 全合格しており、確立済みの再利用可能資産である**（傾き `b̂ = −0.9424`・プラセボ4点すべて `|b̂| ≤ 0.075`）。**T+3 期（2019-07-16 以前）への拡張のみが新規作業であり、その分岐は回す前に固定した**（10Y-COMMON §6.1）。

## 9. 優先度（EXP-OBS000005 との関係）

**S は EXP-OBS000005（PEAD）を先に実行することを推奨する。** 理由:

1. **PEAD は本PJの賭けを検証できる唯一の現役候補**であり、戦略的価値が高い（`STRATEGY-BRIEF.md` の主軸候補）。
2. 本EXPは**価格由来の低事前確率族**であり、勝ったときのポートフォリオ上の位置づけが PEAD より弱い。
3. **ただし両 spec は同時に凍結されているため、実行順序は事前登録性に影響しない**（10Y-COMMON §9 CX-1）。かつ**データ取得層は完全に共通**であるため、順序を変えても総コストは変わらない。
4. **契約は1ヶ月で解約する運用であるが、生データは `data/raw/jq10y/` に永続化されるため、本EXPの実行が翌月以降にずれ込んでも再課金は不要である**（10Y-COMMON §10 D-18）。
