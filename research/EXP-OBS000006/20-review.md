## 独立検算で発見した事実

### 1. V-3・V-6 不合格は、B の報告どおり独立に再現できた

`feasibility.json` の `9-2b_e2a_e2b_and_validation.V_gates` を精査し、`scripts/lib/gap10y_engine.py`・`scripts/lib/gap_common.py` の実装を確認した。

- **V-1（全体傾き）**: `b̂=-1.0823`（se=0.339, n=6758）。区間 `[-1.15,-0.70]` 内 → 合格。理論値（配当全額 `b=-1`）に極めて近く、E-2A/E-2B による配当落ち日の識別が**プール全体では**おおむね機能していることを示す。
- **V-2（プラセボ、±1/±2営業日ずらし）**: 4点すべて `|b̂|≤0.35`（実測は最大でも `0.073`）→ 合格。**日付の精度（オフバイワン等のずれ）は無いことを強く示唆する。**
- **V-3（日別再現性）**: `11.86%`（59日評価）。閾値80%に対し**桁違いの不合格**。プール全体の回帰は通る（V-1合格）のに、個々の落ち日ごとの回帰では8割どころか1割強しか理論区間に収まらない。V-2が示す「日付特定そのものは正確」という結果と合わせると、**原因は日付特定の誤りよりも、個々の落ち日あたりの配当支払銘柄数が少なく回帰が不安定になっている（統計力不足）可能性が高い**が、これは推測であり、B・私（C）のいずれも実際の原因を特定できていない。
- **V-4（カバレッジ）**: `99.49%`（閾値99%以上）→ 合格。
- **V-6（T+3期独立検証）**: `b̂_T3=-1.9214`（se=0.931, n=2049）。区間外（理論値からほぼ2倍乖離）。プラセボ4点は全て合格しており、**T+3期でも日付特定は正確だが、落ち幅の水準が理論（配当全額相当）から大きく外れている**。T+3期はn=2049と相応の標本数があるため、V-3のような小標本ノイズでは説明しにくい。T+3期特有の要因（決済サイクル分岐の実装・当時の税制クライアンテレ効果の違い・データ品質の年代差）を疑う余地がある。

**spec §3.1.2 の規則**: 「V-1〜V-6のいずれかが未達なら、実験を回さずSに差し戻す（K-6）」。かつ「T+2期（V-1〜V-5）は合格したがT+3期（V-6）が未達の場合…本EXPをKillする」という**より狭い例外規定**が別途存在する。**しかし本件は V-3（T+2/T+3を問わない全体の日別再現性テスト）も同時に不合格であるため、この狭い例外（Kill）には該当しない。** デフォルトの規則（差し戻し）が適用される。B の `run.log` の結論（「V-1〜V-6のうちV-3・V-6が未達…K-6に該当するため、G1測定を実行していない」）は spec の文言に照らして**正しい**。

### 2. 【重大な未実施】V-5（期末日の算術検算）が一度も計算されていない

spec §3.1.2 は V-1〜**V-6の6ゲートすべて**を要求しているが、`gap10y_engine.py::run_v1_v6()` の docstring には「V-5（期末日算術検算は9-2bで別途）」と書かれている一方、`feasibility.json` の `9-2b_e2a_e2b_and_validation` の実際のキーは `e2a_pairs`・`e2b_distinct_dates`・`transition_band_count`・`cycle_counter`・`V_gates`（V1/V2/V3/V4/V6のみ）であり、**V-5に相当する出力は feasibility.json 全体を検索しても一件も存在しない**（`grep`で確認済み）。`run.log` の V-gate要約にも V-5 への言及が一切ない。

- V-5 は「`CurFYSt`/`CurFYEn` から暦月加算で構成した四半期末日が、`CurPerEn` が存在する行についてそれと一致する比率 ≥99%」を検証するゲートであり、**まさに §3.1.1 step 2 の暦月加算実装が正しいかどうかを直接検証するもの**である。V-3 が示す「日別ではバラバラ」という結果の原因診断に最も直結する検証がまさに**実施されていない**。
- 結果として、B の V-gate 判定（「V-1〜V-6のうちV-3・V-6が未達」）は**厳密には不正確**——正しくは「V-1・V-2・V-4・V-6は評価済み（うちV-6不合格）、V-3は不合格、**V-5は未評価**」であり、**V-5を除いても既に差し戻し（K-6）に該当するため最終結論は変わらない**が、B の自己申告（「V-1〜V-6全てを評価した」という含意）は正確ではない。

### 3. K_look>66（§3.2・§9-5）の停止規則が実装されておらず、違反が実在する

spec §3.2「遡り上限66の根拠」は「1件でもK_look>66が出ればSに差し戻す（上限を延ばす独自判断を禁止する。N-8）」と明記する。B自身が run.log で申告した通り、実測で**908,523銘柄日中 883,932件でK_look収集に成功し、うち K_look<=66 の被覆率=99.983%**（＝約150銘柄日でK_look>66）。

コードを検証した結果:
- `sigma_gap()`（実際の候補評価で使われる関数）は `lo=i-66` として探索範囲を66日に**正しく制限**しており、この66日以内に60本の有効ギャップが見つからない場合は `None` を返して当該候補を除外する（C-2条件で不合格）。**したがって実際のプール `P` や `z*` 較正の結果自体が、この66日制限を超えて不正に広い窓を使ってしまっているわけではない**（この点はB自身の申告と一致し、独立に確認できた）。
- 一方 `compute_k_distribution()`（診断用の別関数）は、66日の制限を**課さずに**「60本の有効ギャップを集めるのに実際に何日遡る必要があったか」を無制限に計算しており、これが「最大1,308日」という値の正体である。
- **問題は、spec の意図（66日という設計前提が10年データでも100%成立するかを検証し、1件でも破れたら実験全体を止める）に対して、この停止条件がコード上のどこにも実装されていない**ことである。`gap10y_feasibility.py` は K_look の分布を計算して出力するだけで、`k_le_66_all` のようなブール値を持たず、DS/V ゲート判定にもこの結果を組み込んでいない。**結果として、本来「1件でも出れば実験を回さず差し戻す」はずの条件が実在するにもかかわらず、feasibility.json の生成・DS/V ゲート評価が最後まで実行されてしまった。**
- 実務上の影響は小さい（0.017%・約150銘柄日が、正しく「候補として不採用」扱いされているだけで、誤って採用されているわけではない）が、**spec が要求する「66日という設計前提そのものの妥当性検証」という趣旨には応えられておらず、pre-registeredな停止規則が守られなかったという事実は残る**。

### 4. D-4・D-6（共通先行タスク、PEAD側と共有）も本EXPに波及する

EXP-OBS000005側のレビュー（`research/EXP-OBS000005/20-review.md`）で詳述した通り、10Y-COMMON §8 の D-4（`/fins/summary` 10年カバレッジ、文字通りの判定は不成立）・D-6（`AdjFactor`/`ExRT` の意味が一意に決まらない、777行が未解決）は、**PEADとGapが共有するデータ層（`data/raw/jq10y/`）の構築段階で発生しており、Gap側にも同一の影響が及ぶ**。

特にD-6は Gap にとって PEAD 以上に重要である: `gap_common.is_split_merger_row()`（E-1除外ロジック）は `ExRT=="1"` のみを分割・併合とみなしており、**E-1除外はσ_gap窓・プールP・z*較正のすべてに適用される最重要の除外規則**である（spec §3.4「E-1/E-2A/E-2Bの3規則のみ、σ_gapの窓にも適用される」）。`ExRT="2"/"3"` の777行が実際に権利落ち関連だった場合、**未除外の分割・併合起因の価格ギャップが `σ_gap` の分母・候補プール双方に混入している可能性がある**——これは spec が最も警戒する「配当落ち・分割の混入によるバイアス」（§3.1「バイアスの向きが安全側ではない」）と同種の懸念であり、Gap側でこそ検証を急ぐべき項目である。

### 5. 9-7排反性チェックの設計不備は、B の自己申告どおり実害なしと確認できた

B が自己申告した「9-7の排反性チェックが日付集合ベースの弱い比較になっており、spec §3.5が要求する銘柄・日単位の排反性を検証できていない」という点について、`scripts/lib/gap_engine.py::evaluate_candidate_row()` を直接読み、E-3の実装（`disc_positions_by_code` を銘柄別に保持し `(i+off) in disc_positions for off in (-2,-1,0,1,2)` で判定）が**spec §3.4 E-3の定義通り、銘柄単位・添字単位で正しく実装されている**ことを確認した。したがって:
- **実際の候補プール構築（E-3除外）は正しく、PEAD/Gapのイベント集合は行レベルで排反に保たれている**（B の申告通り）。
- 問題は**診断用の9-7チェック自体の設計**（Gapイベント日288日とPEAD開示日2,334日の日付集合としての積集合281日、非空）に限られ、**選定/確認データの独立性そのものは汚染されていない**と判断する。
- ただし、この診断チェック自体は spec §3.5 が要求する「実データ上での確認」の役割を果たせておらず、正しい銘柄・日単位の排反性検証を診断出力として別途追加することを推奨する。

## 判定理由

**総合判定は「差し戻し」。理由は3点の複合。**

1. **spec自身の事前登録規則どおり、V-3・V-6の不合格は「実験を回さずSに差し戻す」場面である。** B は正しくこの規則に従いG1を実行しなかった。これは trading-app-v2 由来の鉄則（「選定期間のリターンを一度でも見たら、その窓は永久に未見ではなくなる」）を守り、確認期間のリターンを一切参照せずに停止した**模範的な対応**であり、本EXPは「エッジ不在の負の結果」としてまだ確定していない（G1もG2も一度も測定されていない）。
2. **V-3不合格の原因診断に必要なV-5が一度も計算されていない。** これはspecが要求する検証セットの不完全な実施であり、V-3が「本質的にダメな設計」なのか「日別の標本サイズが小さいだけの統計力不足」なのか「暦月加算の実装バグ」なのかを、現状のデータからは判断できない。この診断なしに「Kill」を宣告することはできず、**差し戻して原因を特定すべき**である。
3. **K_look>66の停止規則が実装されておらず、実際に違反が存在する**（150/908,523銘柄日・0.017%）。実害（不正に広い窓を使った候補の混入）は無いことを確認できたが、spec が要求する「66日という設計前提の妥当性を10年データで検証する」という趣旨のチェックが機能しないまま先へ進んでおり、**プロセス上の瑕疵として是正が必要**。

**「不採用」としなかった理由**: 本EXPはG1・G2いずれも一度も実行されておらず、確認期間の前方リターンは完全に未見のまま温存されている。spec §6.8 K-5（DSゲート未達）・K-6（V-gate未達等）はいずれも「Killではなく差し戻し」と明記しており、**この結果を不採用として台帳に記録することはspec自身の規則に反する**（trading-app-v2 EXP-OBS000003（旧）が「保留・不採用に移してはならない」と扱われた前例と同型）。

**「保留」としなかった理由**: 保留は「specの基準は満たすが本番投入に見合わない別要因がある場合」に使う区分であり、本件はspec自身の基準（V-gate）を満たしていない状態であるため該当しない。

## 差し戻し（該当時）

- **差し戻し先**: B実装チーム（V-3原因診断・K_look停止条件の実装・D-6解消）。V-3が構造的に解消不能（例: 日本株の配当落ち日の性質上、個別日の標本サイズが恒常的に小さく統計力が出ない）と判明した場合はS戦略チームによる設計判断（§3.1.1の配当落ち識別手法の再設計、またはV-3の閾値・評価単位の再事前登録）が必要。
- **内容**:
  1. **V-5を実装し出力する**。暦月加算で構成した四半期末日と `CurPerEn` の一致率を計算し、V-3の原因が暦月加算のロジックエラーにあるのか、単純な標本サイズ不足によるノイズなのかを切り分ける。
  2. **V-3の評価単位（59日評価）の内訳を精査する**。日ごとの配当支払銘柄数（回帰のn）の分布を出力し、n が極端に小さい日（例えばn<10）を除いた場合にV-3の再現率がどう変化するかを記述統計として出力する（合否判定基準は変えない。診断目的のみ）。
  3. **K_look>66の停止条件を `gap10y_feasibility.py` に実装する**（`k_le_66_all` をDS/Vゲート評価前のブール条件として追加し、不成立なら即座に停止・Sへ差し戻すフローに組み込む）。今回発見された約150銘柄日の扱い（66日を超えて候補から除外し続けるか、上限自体の再設計を新規EXPとして起票するか）はSの判断を仰ぐ。
  4. **D-6（ExRT="2"/"3" の777行）の意味を確定する**（PEAD側レビューの差し戻し内容と共通）。Gapでは特にE-1除外への影響（分割・併合起因のギャップが誤ってプールに混入していないか）を優先的に検証する。
  5. **D-4の扱いをS戦略チームと合意する**（PEAD側レビューと共通）。
  6. 上記1〜5の対応後、V-1〜V-6を再評価し、全合格した場合のみG1測定へ進む。V-3が依然として構造的に解消しない場合は、S戦略チームが「配当落ち識別手法の再設計が必要」と判断し新規EXPとして再起票するか、「本EXPをKillする」（spec §3.1.2の趣旨を拡張解釈する）かを決定する必要がある。

## 次フェーズへの申し送り

- V-1（プール全体）・V-2（プラセボ）・V-4（カバレッジ）は合格しており、**配当落ち日識別の「大まかな」精度は確立している**。問題は個別日単位の粒度（V-3）とT+3期の水準（V-6）に限定されるため、**識別手法そのものを放棄する必要はなく、診断を深める価値がある**とC品質チームは考える。
- D-4・D-6はPEAD側と共有する問題であり、**データ層を1箇所で修正し両EXPが参照し直す**運用を推奨する（EXP-OBS000005側レビューと同じ申し送り）。
- K_look>66の実態（最大1,308日・p50=63・p90=64・p99=65）を見ると、**99パーセンタイルまでは66日以内に収まっており、外れ値はごく少数の銘柄・特殊な取引停止パターンに起因する可能性が高い**。66日という設計前提自体を疑う必要はないと見立てるが、これも推測であり、Sの判断を仰ぐべき事項として明記する。
