## 1. 仮説（1文）

**東京証券取引所の寄付の板寄せにおいて前日終値から大きく下方に乖離して始まった銘柄のうち、決算開示に起因しないものは、その乖離の一部を続く5営業日で回復し、往復コスト0.45%控除後も正の期待値を残す。**

### 1.1 エッジ族の宣言（**正直に記す**）

- **`g = ln(O_t / C_{t−1})` は価格由来であり、PJ000001 §4 C-3 が低事前確率とした「価格由来の特徴量から方向を予測する」族に属する。**
- 非価格なのは特徴量ではなく**条件分岐（決算開示の有無）のみ**である。**本EXPは本PJの賭け（非価格情報に直交エッジがあるか）を検証しない。**
- **日本株固有なのは情報の種類ではなく市場構造**である（17.5時間の取引停止・寄付の板寄せ単一オークション・値幅制限・昼休み。いずれも24/7連続取引の暗号資産には概念として存在しない）。

### 1.2 事前確率の見立て

**低〜中（低寄り）。旧 spec から変更しない。期間が7.4倍になったことは事前確率を上げない**（検出力が上がるだけである）。

### 1.3 本EXPが賭けているものの正体（**忘れないこと**）

- 文献が報告する反転は**日中で完結する**とされ、その1日保有版は「必要グロス0.45%に対し効果量0.07%＝**6.4倍不足**」として旧 prescreen §7.5 で**回す前に却下済み**である。
- **本EXPは「反転の一部が数営業日残存している」という文献の外挿に賭けている。文献の存在は根拠を補強しない。**
- 賭けの中心は「**市場ストレス時の売り需給の偏りが数営業日かけて解消する**」ことである。**したがってストレス・エピソードの数こそが本EXPの実効サンプル数であり、10年化の最大の効果はそこにある。**

## 3. シグナル定義（**旧 spec §3 を流用。決済サイクル分岐と `N_ann` の分母のみ訂正**）

### 3.1 使用する価格（調整の規約）と権利落ち・配当落ちの除外

- ギャップ・`σ_gap`・前方リターン・損益のすべてにおいて、**同一の調整規約で揃えた価格系列を使う。生値と調整値を混在させてはならない。** 単元数計算・株価帯フィルタ・値幅制限判定は**同一日の生値**で行う（10Y-COMMON §6 H10-5）。
- **E-1（権利落ちの除外）**: `AdjFactor(D) ≠ 1`、または `ExRT` が `D` における権利落ち（分割・併合等）を示す場合、**その銘柄日 `D` をイベント候補・プール `P`・`σ_gap` の窓のすべてから除外する。**
  - 既知の実測（旧 spec §9-2a）: `AdjFactor` 非1.0 の91件はすべて整数分の1（1/2〜1/15）のクリーンな分割比率であり、`ExRT='1'` と完全一致。**`AdjFactor` は配当を調整しない。** **10年分では新しいパターンが出現しうるため、B は 10Y-COMMON §8 D-6 で再確認する。**
- **E-2（配当落ちの除外）**: `AdjFactor` が配当を調整しない以上、**配当落ち日の下方段差は本EXPのシグナルに直接混入する。** 日本株の配当落ちは3月末・9月末に極端に集中するため、混入は **OBS000029（実質1本張り）の時間方向再発**を直接引き起こす。§3.1.1 の決定的手続きにより **E-2A（銘柄別・厳密）と E-2B（暦ベース・一括）の和集合**を除外する。

> **「記録して先へ進む」にしなかった理由（旧 spec から継承）**: 配当落ちは (a) 方向が常に下向き、(b) 反転しない（理論価格の段差）、(c) 暦上2日に極端に集中する、の3条件をすべて満たす。混入した場合の影響は「効果の希釈」ではなく「特定2日への集中と、そこでの確実な負け」であり、**バイアスの向きが安全側ではない。**

> **「配当分だけ価格を補正して使う」を採らなかった理由**: 実際の落ち幅は配当額の100%ではない（源泉徴収20.315%を含む税制クライアンテレ効果により実証的な落ち率は0.7〜1.0倍）。補正は「どの落ち率を使うか」という**新しい自由パラメータ**を生み、残差（≈0.21%）は**配当利回りと横断的に相関して残る**（`σ_gap` の典型値 約1.2% の 0.17σ）。**除外は規約であり自由度を持たないが、補正は自由度を持つ。**

#### 3.1.1 配当落ち日の決定的な構成手続き

| step | 手続き（**すべて決定的。推定・近似・当てはめを含まない**） |
|---|---|
| **1** | `/fins/summary` の各行について `CurFYSt`（会計年度開始日）と `CurFYEn`（会計年度末日）を読む。いずれかが空の行は使わない（件数を記録） |
| **2** | 会計四半期末日を**暦月加算**で構成する: `Q1末 = CurFYSt + 3ヶ月 − 1日`、`Q2末 = CurFYSt + 6ヶ月 − 1日`、`Q3末 = CurFYSt + 9ヶ月 − 1日`、`FY末 = CurFYEn`。**暦月加算は日を保存し、月末超過のみクランプする。** 基準日 `R` は**暦日**であって営業日ではない |
| **3** | **基準日 `R` を権利落ち日 `X` へ写す。`k := idx(b(R))`（`b(R)` は `R` 以下である `T` 上の最大の営業日）として、決済サイクルに応じて分岐する（10Y-COMMON §6.1 が正本）**:<br>`date(b(R)) ≥ 2019-07-22` → `X = { T[k−1] }`（**T+2**。権利付最終日 = `T[k−2]`）<br>`date(b(R)) ≤ 2019-07-12` → `X = { T[k−2] }`（**T+3**。権利付最終日 = `T[k−3]`）<br>それ以外（移行帯 2019-07-16〜2019-07-19） → `X = { T[k−1], T[k−2] }`（**両方を除外**。件数を記録）<br>`T` に `R` 以下の営業日が無い場合、または添字が1未満になる場合は構成しない（件数を記録） |
| **4** | 各四半期の実績配当 `Div1Q` / `Div2Q` / `Div3Q` / `DivFY` を step 2 の対応する期末日に**フィールド名の四半期番号で**結びつける（開示回の四半期ではなく、会計年度内の四半期に対応する） |
| **5** | **`DPS > 0` のもののみ**を配当落ちとする。`0.0` の明示申告は対象にしない（件数を記録）。同一 `(銘柄, 基準日)` に複数の申告値が現れた場合は**最大値**を採り、発生件数を記録する |

- **E-2A（銘柄別・厳密）**: step 1〜5 で構成された銘柄日 `(j, X)` を、**イベント候補・プール `P`・`σ_gap` の窓のすべてから除外する。**
- **E-2B（暦ベース・一括）**: 各暦月 `m` の `T` 内での最終営業日を `L(m)`、`k_m := idx(L(m))` として、
  ```
  X(m) = { T[k_m − 1] }                    if date(L(m)) >= 2019-07-22
       = { T[k_m − 2] }                    if date(L(m)) <= 2019-07-12
       = { T[k_m − 1], T[k_m − 2] }        otherwise
  ```
  を**全銘柄共通で、イベント候補・プール `P`・`σ_gap` の窓のすべてから除外する。**

> **E-2B を E-2A に加えて置く理由**: (a) 株主優待・新株予約権無償割当等、配当以外の権利落ちが同一基準日に同居するが `Div*` には現れない、(b) 配当落ち日には**銘柄横断の需給歪み**（配当再投資に伴う先物・現物のフロー）が生じ、配当を出さない銘柄にも及ぶ、(c) `/fins/summary` のカバレッジが欠ける銘柄を E-2A は救えない。**E-2B は「配当落ち日という日そのものを測定対象から外す」規約であり、E-2A は非月末決算の銘柄を救う補完である。**

#### 3.1.2 §9-2b の検証ゲート V-1〜V-5（**配当落ちの識別が本物であることの証明**）

`d(j,X) := DPS(j,X) / C(j, X−1)` を理論落ち幅（比率）、`g(j,X)` を §3.2 のギャップとする。回帰は `g = a + b·d` の単純OLS。**E-1 に該当する銘柄日は全ゲートから除く。前方リターンを一切参照してはならない**（使ってよいのは `g` と `Div*` のみ）。

### 3.2 ギャップと正規化（**単一の事前登録定義。旧 spec と一字一句同一**）

`D = T[i]` をイベント日（ギャップが観測される日）とする。

| 記号 | 定義 |
|---|---|
| `g(j,D)` | `ln( O(j, T[i]) / C(j, T[i−1]) )` — 銘柄 `j` の `D` におけるオーバーナイト・ギャップ（対数） |
| `σ_gap(j,D)` | **有効ギャップちょうど60本**の**標本標準偏差（ddof=1）** |
| **`z(j,D)`** | **`g(j,D) / σ_gap(j,D)`** — 下方ギャップでは負値 |
| **`S(j,D)`** | **`−z(j,D)`** — 下方ギャップの深さ。**大きいほど深い。予測単位の説明変数はこの `S` である** |

**`σ_gap` の窓**

- **有効ギャップ**とは、`g(j, T[m])` が算出可能（`O(j,T[m])` と `C(j,T[m−1])` がともに存在し正）であり、**かつ `T[m]` が `j` にとって E-1 / E-2A / E-2B の除外日でない**ギャップをいう。
- `σ_gap(j, D)`（`D = T[i]`）は、**`T[i−66]` 〜 `T[i−1]` の範囲にある有効ギャップのうち、新しい順にちょうど60本**を採り、その標本標準偏差（ddof=1）とする。
- **60本に満たない場合はイベント候補から除外する**（§3.4 C-2）。**窓長の延長・短縮・「取得できた分での代用」を禁止する**（N-8）。
- **遡り上限 66 の根拠（旧 spec の実測）**: 候補511銘柄・全銘柄日について、60本の有効ギャップを集めるのに必要な遡り営業日数 `K_look` の分布は**最大 65、`K_look ≤ 66` でカバー率 100.0000%**（取りこぼし0件）であった。
  - **【10年化での必須確認】この実測は2年分のデータに基づく。10年分では E-2B の除外が T+3 期に1日ずれること等により `K_look` の分布が変わりうる。B は §9-5 で全期間の `K_look` 分布を再出力し、`K_look ≤ 66` が全銘柄日で成立することを確認する。1件でも `K_look > 66` が出れば S に差し戻す**（上限を延ばす独自判断を禁止する。N-8）。

**仮説の符号**: `S` が大きいほど前方リターン `R_5` が大きい ⇒ **IC は正**。

**なぜ生の % ではなく `z` を主定義にするか**（回す前に確定した設計判断）:

1. ユニバースの株価帯は1,000〜3,500円（3.5倍幅）であり、銘柄ごとの日次ボラティリティも大きく異なる。**固定の % 閾値ではイベント集合が系統的に高ボラ銘柄で埋まる。** それは「下方ギャップを取る戦略」ではなく「高ボラ銘柄のロング」であり、**OBS000029・OBS000030 と同型化する。**
2. `z` は「その銘柄の平常のギャップ変動に対して何倍か」という銘柄間で比較可能な尺度を与える。
3. **`σ_gap` による正規化は単一シグナルのスケール変換であって、別のシグナルとの合成ではない**（N-1 に抵触しない）。ATR・ボリンジャーバンド等のテクニカル指標は一切使わない。
4. 生の % 版は §6.3-7 で**記述統計としてのみ出力**する。**合否判定に使うことを禁止**（N-10）。

### 3.5 EXP-OBS000005（PEAD・10年版）との事象排反性の証明

- PEAD のイベントは `(j, DiscDate)` であり、そのエントリー日は `DiscDate` の翌営業日である。
- 本EXPのイベント日 `D` は、E-3 により `DiscDate ∈ [D−2, D+2]` なる銘柄日をすべて除外している。
- 仮に本EXPの `D` が PEAD のエントリー日と一致したとすると `DiscDate = D−1` であり、これは `[D−2, D+2]` に含まれるから E-3 で除外されている。**矛盾。**
- 同様に、PEAD のイベント日そのもの（`D = DiscDate`）も `[D−2, D+2]` に含まれるため除外されている。
- **∴ 本EXPのイベント集合と PEAD のイベント集合・エントリー日集合は排反である。** B実装チームは E-3 による除外件数を**銘柄日ベースと `DiscDate` ベースの両方**で出力し、この排反性を実データ上で確認すること（§9-7）。

### 3.6 イベント閾値 `z*` の較正（**カウントのみを入力とする決定的手続き。分母を式で与える**）

1. **探索グリッドを事前に固定する**: `z* ∈ { −1.50, −1.75, −2.00, …, −7.75, −8.00 }`（**0.25刻み・27点**）。**グリッドの追加・細分化・再拡張を禁止する**（N-9）。
2. **選定期間のみ**について、各グリッド点の**候補イベント件数** `n(z*)` を数える（§3.4 の C-1〜C-4 と E-1〜E-6 をすべて適用した後の件数）。
3. **有効イベント日数 `D_eff` を次の式で一意に定める**:
   ```
   D_eff(選定) := #{ i : 68 ≤ i ≤ s−1  かつ  T[i] ∉ (E-2B による全銘柄一律除外日の集合) }
   D_eff(確認) := #{ i : s  ≤ i ≤ |T|  かつ  T[i] ∉ (E-2B による全銘柄一律除外日の集合) }
   ```
   **`n(z*)` は、まさにこの `D_eff` に数えた日に属するイベントのみを数えたものでなければならない**（分子と分母の母集団が一致すること）。B は `D_eff` の値と、除外された添字の一覧の長さを `params.json` に出力する。
4. **年換算件数** `N_ann(z*) = n(z*) × 245 / D_eff`。**年換算定数は 245 のみを使う**（旧 spec からの継続。B は参考値として `|T| / ((T[|T|] − T[1]) の年数)` も出力する）。
5. **`z*` = `|N_ann(z*) − 215|` を最小にするグリッド点。** 同値の場合は**より極端側（より負）**を採る。
6. `z*` を**凍結**する。確認期間・パイプライン・感度分析のすべてで同じ `z*` を使う。
7. **この手続きに前方リターンは一切入らない。入力は銘柄日の件数のみである。**

#### 3.6.1 グリッドを −4.00 から −8.00 へ拡張したことについて（**閾値の緩和ではなく設計欠陥の修復である**）

- 旧 spec のグリッド上限 `−4.00` は、**テールが概ね正規に近いという暗黙の前提**に立っていた（標準正規を下半分に切断した集合の理論分位点は p01 ≈ −2.58 / p05 ≈ −1.96）。
- 実測ではこの前提が誤っており（旧 spec 実測: `z` の p01 は選定 **−6.235** / 確認 **−3.689**、最小値 −15.87 / −22.50）、**グリッド11点すべてで `N_ann` が目標帯 [150,300] の外側（356.12 以上）となり DS-2a が不合格となった。** すなわち**最適化が境界で打ち切られていた。**
- **拡張の性質**:
  - **目的関数（`|N_ann − 215|` の最小化）・目標件数215・タイ規則・刻み0.25 を一切変更していない。**
  - **グリッドを広げることは `N_ann` を目標215に近づける方向にしか働かない。** 「通りやすくするために動かした」のではなく、**「最適解が探索範囲の外にあった」という欠陥を直している。**
  - **較正は選定期間（2016-12〜2019-12）のみで行う。この期間は S・B・C の誰も一切観測していない**（旧EXPの実測はすべて 2024-06〜2026-06 のものである）。
  - **なお、拡張の必要性を S が知った経路は、旧EXPが 2024-2026 について測ったテール分布である。この期間は新しい分割では確認期間に属する。** 10Y-COMMON §3.3 のとおり**正直に開示する**。ただし (i) 使ったのはカウント（分位点）のみでリターンではない、(ii) 拡張は目的関数を変えず最適解の取りこぼしを直すだけである、(iii) `z*` を実際に決めるのは新しい選定期間のカウントのみである、の3点により、**確認期間の結果に対して設計を有利にする作用を持たない。**
- **最小化点がグリッド境界 `−8.00` に来た場合**、それは「27点のいずれも目標帯に入らない」可能性を示唆する。**その場合も DS-2a（選定期間で `N_ann ∈ [150,300]` を満たす点が存在すること）が不合格となり、S に差し戻される。グリッドを再度広げてはならない**（N-9）。

### 3.7 「非決算」の定義の限界（**安全側だと扱わない**）

- 本EXPが除外できるのは **`/fins/summary` に載る開示（決算短信等）のみ**である。業績予想の修正・自己株式取得・M&A 等の適時開示は、**TDnet アドオン（¥11,000/月）未契約のため識別できない。**
- **混入率の条件付き推定は構造的に不可能である**（無償 TDnet インデックスの保持期間は約38日であり、自前スナップショットは 2026-08-06〜 しか存在しない）。**なお10年化により、TDnet スナップショットの期間と日足の期間は初めて重複する**（日足は直近営業日まで取得できるため）。**B は §9-8 でこの重複期間における条件付き混入率を出力する**（記述統計。合否判定には使わない。**重複期間は確認期間の約2%にすぎず、代表性を主張してはならない**）。
- **バイアスの向きを断定しない。** 未識別ニュース起因のギャップは「反転しないので効果を希釈する（＝安全側）」と考えるのが自然だが、**ニュースへの過剰反応がむしろ強く反転する可能性を排除できない。** trading-app-v2 EXP-OBS000037 の教訓に従い、**本 spec はバイアスの符号を決めない。** C品質チームはこの未確定性を判定文に明記すること。

## 4. 約定モデルの固定（**旧 spec §4 を一字一句そのまま流用する**）

### 4.0 値幅制限フラグ `UL` / `LL` の判定

**`research/EXP-OBS000001/01-spec.md` §4.0 を参照により取り込む**（EXP-OBS000005 §4.0 と同一）。

```
BUY_BLOCKED(t)  :=  (Vo(t) == 0) or (O(t) is null) or ( UL(t)==1 and O(t) == H(t) )
SELL_BLOCKED(t) :=  (Vo(t) == 0) or (O(t) is null) or ( LL(t)==1 and O(t) == L(t) )
```

- `UL` / `LL` は**価格水準ではなく 0/1 の文字列フラグ**。パース規則: `"1"` → 真、`"0"` / `""` / null → 偽。**それ以外の値が1件でも出現したら推測で埋めず S に差し戻す。**
- **JPX 制限値幅表からの自前再構成を禁止する。**
- **方向の非対称性は意図的である**（買いを阻むのは `UL`、売りを阻むのは `LL`）。**反転・変更してはならない。**

> **本EXP固有の追加除外との関係（矛盾ではない）**: 約定可否そのものは上記2式のみで判定する。**その上で、本EXP固有の事前登録された追加除外**として `LL(t_1)=1 かつ O(t_1)=L(t_1)` のイベントを**見送る**（§4.1 E-8）。理由は約定可否ではなく、**(a) 始値が自由な市場清算価格ではない、(b) 特別気配による寄付遅延で「始値で買えた」という前提が検証不能**という測定上の理由である。**両者は別項目として件数を分けて記録する**（P-2 / P-2d）。

### 4.1 エントリー（**先読みを構造的に排除する**）

- **エントリーは `D` の翌営業日 `t_1 = T[i+1]` の始値 `O(t_1)` に固定する。**
- **`O(D)` でのエントリーを禁止する（N-4）。** `g(j,D)` は `O(D)` そのものから計算される量であり、`O(D)` で約定できると仮定することは**「板寄せの清算価格を、その板寄せに注文を出す前に知っている」ことを意味する。これは近似ではなく明確な先読みである。**
- 約定価格 = `O(t_1) × (1 + s)`、`s` = 買い片道スリッページ（中心ケース **0.100%**）。
- 以下は**約定不能として見送る**（翌日以降の再エントリーを行わない）。**件数と内訳を必ず分けて記録する**:
  - **E-7**: `BUY_BLOCKED(t_1)` が真（内訳3分類）
  - **E-8**: `LL(t_1)=1 かつ O(t_1)=L(t_1)`（ストップ安寄り付き）
  - **E-9**: §5.3 のリスク集中上限・単元離散化により建てられなかった（スロット競合。E-7/E-8 とは別カウント）
- 参考値として `UL(t_1)=1 だが O(t_1)<H(t_1)` / `LL(t_1)=1 だが O(t_1)>L(t_1)` で約定したとみなした件数も記録する。

**エントリーを `t_1` に置くことの代償（正直に記す）**: 文献が報告する反転の大部分は `D` の日中セッションで起きるとされる。`t_1` 始値エントリーは**その部分を構造的に捨てる**。すなわち本設計は文献の効果に対して**厳しい側に倒れている**。**この厳しさを理由にエントリー日を `D` に変更することを禁止する**（N-4）。

### 4.2 予測単位（G1）の前方リターン

- **`R_5(j,D) = C(j, t_5) / O(j, t_1) − 1`**（**グロス**。コスト・スリッページを一切引かない）。`t_k = T[i+k]`。
- 前方窓が確保できないイベント（`i+5 > |T|`）は G1 から除外し、件数を記録する。
- `t_1` が取れないイベント（E-7 / E-8）は G1 から除外する。**ただし除外した場合と `O(t_1)` を用いて仮想的に含めた場合の両方の `IC_bar` を出力すること**（主判定は除外版）。
- **市場超過リターン**: `R_5^excess(j,D) = R_5(j,D) − (同一カレンダー窓 t_1〜t_5 におけるユニバース全銘柄の等加重平均 R_5)`。**市場プロキシはユニバース等加重平均に固定する**（指数の採用は新たな自由度になるため、Standard で TOPIX が取得可能になっても定義を変えない）。
- **セクター中立リターン**も出力する（合否判定には使わない）。
- **価格は調整系列を用いる**（10Y-COMMON §6 H10-5）。

> **注（回す前に確定しておく数学的事実）**: 同一イベント日 `D` に属する観測はすべて同一のカレンダー窓 `t_1`〜`t_5` を持つ。したがって市場プロキシの減算は**日内で定数**であり、**日内 Spearman 順位相関を変化させない。** §6.1 の `IC_bar` は `R_5` でも `R_5^excess` でも同値である。B は `R_5^excess` を用い、同値性を数値で確認して出力すること（食い違ったら S に差し戻す）。**ただし10年化により欠損営業日が発生しうるため（旧 spec の欠損率0.0%は2年分の実測）、同一日でも窓が揃わない銘柄が出た場合は件数を記録し、同値性の検証はそれらを除いて行うこと。**

### 4.3 決済ルール（トレーリングストップ）

| # | パラメータ | 固定値 |
|---|---|---|
| 1 | **初期損切幅** | エントリー約定価格の **−4.0%（固定値）**。**ATR連動にしない**（ATR はテクニカル指標であり N-1 に抵触し、かつ新しい乗数パラメータと第2のルックバック窓を導入する） |
| 2 | **トレール発動水準** | 終値ベースの含み益が **+4.0%** 以上に到達した日の**翌営業日から**有効化 |
| 3 | **追随幅** | 発動後、`t_1` 以降の**日次終値**の最高値から **−2.0%** |
| 4 | **更新足と約定価格** | **日足終値のみ**で更新・抵触判定。抵触した日の**翌営業日始値**で約定 |

- 日中高値・日中安値（`H` / `L`）は**トレールの更新にも抵触判定にも使わない。**
- 初期損切も同じ扱い: `C(t) ≤ エントリー約定価格 × 0.96` なら**翌営業日始値**で手仕舞い。
- 決済時の約定価格 = `O(t_exit) × (1 − s)`。
- **最大保有5営業日**: `t_5` の終値時点で未決済なら `t_6` の始値で強制手仕舞い。
- **予想される挙動（回す前の正直な見立て）**: 本EXPが狙う効果量はトレードあたり数十bp〜数%であり、**トレール発動水準 +4.0% に到達するトレードは少数にとどまる可能性が高い。** その場合、実質的な決済は「初期損切 −4.0%」と「5営業日の時間切れ」の2種類に収斂する。**これは設計の欠陥ではなく、5営業日という短い保有期間と司令塔判断3（固定利確幅を置かない）の当然の帰結である。この見立てを理由にパラメータを事後に変更することを禁止する**（N-9）。

### 4.4 決済できない場合（値幅制限の模擬）

- `SELL_BLOCKED(t_exit)` が真なら約定できず持ち越し。その後の各営業日で同じ式を再評価し、偽となった最初の営業日の始値で約定する。その間の下落はすべて損失として計上する。
- **最大5営業日**持ち越しても約定できない場合、5営業日目の終値で強制的に評価損益を確定し「強制評価」として件数を記録する。
- 本ルールは、初期損切・トレール抵触・最大保有超過（`t_6` 始値）・§7 D項の決算跨ぎ回避・§5.3-10 のサーキットブレーカー清算を含む、**すべての売り約定に一律に適用する。**
- **`UL(t_exit)=1`（ストップ高）は売り約定を妨げない。**

### 4.5 窓長・ラグ・オフセットの算術的整合性

**10Y-COMMON §4 が唯一の正本である。本 spec は独自の窓を導入しない。** 特に次の3点を強調する（**T-8 / trading-app-v2 EXP-OBS000037 の教訓**）:

- **`σ_gap` の「60本」は常にギャップの本数を指し、営業日数でも価格点数でもない。** 採用した60本は隣接とは限らないため、**「60本のギャップ ⇔ 終値61個」という対応は成立しない。** 正しい対応は **60本 ⇔ 始値60個 ＋ 終値60個** である。**この対応関係を実装者が独自に読み替えてはならない。**
- **`σ_gap` の探索範囲は66本であり、最も古い採用候補 `T[i−66]` のギャップは終値 `C(T[i−67])` を要する ⇒ `i ≥ 68`。**
- **「N営業日保有」は `t_1` から数えて N本の日足を保有判定に使うことを意味し、決済約定はその翌営業日 `t_{N+1}` の始値である**（＝価格点は N+2 個）。
- `D` の日足は損益計算に一切入らない。`D` の `O` は `g` の計算に、`D` の終値 `C(D)` は §5.3-3 の単元数決定にのみ使う。

### 4.6 寄付の約定モデルの妥当性は日足では検証できない（**必ず明記して申し送る**）

- 本EXPは「板寄せの始値で、目標建玉25万円を、片道0.10%のスリッページで買える」という前提に**全面的に依拠する**。
- しかし **(a) 自分の成行注文は板寄せの清算価格の形成に参加する、(b) 極端ギャップ銘柄は板が薄い、(c) 特別気配により寄付が遅延する**という3点は、**日足データからは原理的に測定できない。**
- **したがって G1・G2 の合格は「日足上では成立する」ことしか意味しない。** 本EXPの採用可否に対し、**STEP3 フォワード較正における寄付約定の実測（想定約定価格と実約定価格の乖離分布）を必須条件とする。** C品質チームは、G1・G2 が合格した場合でも判定文にこの条件を明記すること。

### 6.1 G1 主検定

#### 6.1.1 測定母集団（2段構成）

- **プール `P`**（連続値IC・デシル分析の母集団）: §3.4 の C-1〜C-3・E-1〜E-6 をすべて満たし、**`z ≤ −1.5`** を満たす銘柄日。**`−1.5` は回す前に固定した値であり、結果を見て動かさない**（N-9）。
- **イベント集合 `E`**（水準検定・パイプラインの母集団）: プールのうち **`z ≤ z*`** を満たすもの。`E ⊆ P`。

> **なぜ母集団を2段にするか**: 主指標は「閾値ではなく `z` の連続値に対する Spearman IC」でなければならない（OBS000018 対策）。一方で「実際に建てる集合のグロス平均 ≥ 0.45%」も要求される。前者は**プール全体での単調性**を、後者は**イベント集合での水準**を問うものであり、母集団が異なるのは設計上必然である。**両者を同時に課すことで、「閾値を1点に決め打ちしたら偶然良かった」（蜃気楼）と「単調ではあるが水準が経済的に足りない」の両方を落とす。**

#### 6.1.2 主指標: イベント日内クロスセクション Spearman 順位相関の等加重平均（`IC_bar`）

1. 確認期間の各日 `d` について、その日にプール観測を持つ銘柄群の **`S`（＝`−z`）と `R_5^excess` の Spearman 順位相関 `IC_d`** を算出する。タイは平均順位で処理する。
2. **1日あたりのプール観測数が5件未満の日は `IC_bar` の算出から除外**する。**残った日数が `K`（＝DS-6a の計数対象と同一の量）である。両者が食い違う場合は S に差し戻す。**
3. **`IC_bar` = 対象日の `IC_d` の単純平均**（日を等加重）。
4. **有意性検定 = イベント日ブロック内 permutation**:
   - 帰無仮説: 「同一日の銘柄間で、`S` の順位は前方リターンの順位を説明しない」
   - 手続き: **同一日ブロックの内部でのみ `S` をシャッフル**し、`IC_bar` を再計算する。**10,000回**繰り返す。
   - 乱数シード: **20260915**（固定。変更禁止）
   - 片側 p 値 = ( 1 + #{ `IC_bar_perm` ≥ `IC_bar_obs` } ) / ( 1 + 10,000 )
   - **日内でのみ並べ替えることにより、同日の銘柄が共有するマクロ・市場全体の共通要因が p 値を過小評価させる問題を構造的に排除する**（本EXPは市場急落日にイベントが集中するため、この配慮は PEAD 以上に重要である）。

#### 6.1.3 水準検定（G1-3 の統計量。**p 値は報告するが合否ゲートにはしない**）

1. 確認期間の各イベント日 `d` について、その日のイベント集合 `E` の `R_5^excess` の**等加重平均** `M_d` を算出する。
2. **`M_bar` = 対象日の `M_d` の単純平均**（日を等加重）。対象日数は `K_event`（＝DS-5a）。
3. **ラベル permutation**: 各イベント日 `d` について、その日に `t_1`〜`t_5` が確保できるユニバース銘柄の中から `k_d` 銘柄を**無作為抽出**して仮イベント集合とし、`M_bar` を再計算する。**10,000回**、シード **20260915**。
4. 片側 p 値を報告する。**この p 値は G1 の合否ゲートではない**（§6.1.5(d)）。

#### 6.1.5 検出力の事前開示と、経済的必要水準との関係（**基準を緩める根拠にも、結果を解釈し直す根拠にも使ってはならない**）

**(a) `IC_bar` の統計的検出下限**

- `SD(IC_d) ≈ 1/√(n_d − 1)`、`SE(IC_bar) = SD(IC_d)/√K`、片側5%の MDE = `1.645 × SE`。
- 期待値（旧 spec の実測密度 `K` = 62日/220イベント日・プール1,586件で外挿。確認期間は約1,635営業日）:

| `n_d` の想定 | 期待 `K` | **MDE(`IC_bar`)** |
|---|---|---|
| 10 | 440日 | **0.026** |
| 20 | 440日 | **0.018** |
| （参考）DS-6a の下限 `K`=250・`n_d`=10 | 250日 | **0.035**（＝DS-6b の閾値） |

**(b) 経済的に必要な IC 水準（G1-3 から逆算）**

- G1-3 は「確認期間のイベント集合 `E` の `R_5` グロス平均 ≥ +0.45%」を要求する（損益分岐）。
- イベント集合はプールの上位 `p` 分位である。旧 spec の実測から `p ≈ 215 / 1,586 ≈ 13.6%`。
- 二変量正規近似の下で `E[R | X ∈ 上位 p] = IC × σ_R × φ(z_{1−p}) / p`。`p = 0.136` のとき `φ(1.098)/0.136 = 1.605`。
- したがって **`IC_econ = 0.45% / (1.605 × σ_R)`**:

| `σ_R`（5営業日の個別株リターンの標準偏差） | **`IC_econ`** |
|---|---|
| 4.0% | **0.0701** |
| 4.5% | **0.0623** |
| 5.0% | **0.0561** |

**(c) 2つの水準の関係（本EXPの最大の価値）**

> **統計的検出下限（0.018〜0.035）は、経済的必要水準（0.056〜0.070）の半分以下である。**
>
> **⇒ 本EXPは「エッジが無い」と「エッジはあるが小さすぎて取れない」を分離して判定できる。** これは本プロジェクトで初めての状態である（PEAD は両者がほぼ一致しており、分離できない）。
>
> **⇒ したがって本EXPが G1 未達となった場合、それは「検出力不足」ではなく「エッジ不在」の証拠として `portfolio-ledger.md` に不採用記録できる。これが本EXPを実行する最大の理由である。**

**(d) 水準検定を合否ゲートにしない理由**

- 水準 `M_bar` の MDE は DS-5b の閾値で 0.35%、期待値で 0.24% であり、経済的必要水準 0.45% を下回るが、**余裕は2倍未満**である。
- 水準に**有意性**を要求すると、経済的に必要な水準と統計的に検出可能な水準が近接し、ゲートが二重になって検出力をさらに削る。**必須条件が求めているのは「統計的に有意でも 0.45% 未満なら不採用」であって「0.45% 以上かつ有意」ではない。** したがって G1-3 は**点推定の閾値**として設計する。
- B実装チームは**実測の `K` / `K_event` / `n_d` / `k_d` / `R_5` の標準偏差 / permutation 帰無分布の標準偏差**を出力すること（C品質チームが実測 MDE と `IC_econ` を独立に再計算できるようにするため）。

| **N-14**<br>（**2026-09-15 明確化**） | **ユニバース・`T`・データ層を独自に再構築しない。** EXP-OBS000005 側の成果物（確定日集合・U-1〜U-5 の通過集合・`Va` 順位）を参照する（§9-1・§9-4）。**ただし U-6 の打ち切りは本 spec の `U6_cap` = 175 で行う**——EXP-OBS000005 第2版の `U6_cap` = 271 を本EXPに持ち込んではならない（D-16 はギャップEXPについて決裁されていない）。**適用した `U6_cap` を `params.json` に必ず記録すること** |

### 10.3 許可される価格データの利用範囲（明示）

本EXPは**シグナル自体が価格由来**であるため、PEAD の N-2 に相当する禁止は存在しない。ただし次を明確にする。

- **シグナルに使ってよいのは `O` と `C` から算出される `g` と `σ_gap` のみである。** 高値 `H`・安値 `L`・出来高 `Vo`・売買代金 `Va`・時価総額 `MktCap` を**シグナルの計算に使ってはならない**（`H`/`L` は §4.0 の約定可否判定に、`Va`/`MktCap` はユニバース構築に、それぞれ限定して使う）。
- 値幅制限による約定可否の判定（`UL` / `LL` と同一日の `O` / `H` / `L` / `Vo`）、前方リターン・損益の計算、市場プロキシ・セクター中立リターンの算出は**許可される**。
