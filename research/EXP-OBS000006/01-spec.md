## 1. 仮説（1文）

**寄付の板寄せで前日終値から大きく下方に乖離して始まった銘柄のうち、決算開示に起因しないものは、その乖離の一部を続く数営業日で回復し、往復コスト0.45%控除後も正の期待値を残す。**（イベント駆動・ロングオンリー・日足）

### 1.1 エッジ族の宣言

- **予測変数は価格のみから作られる（`z = g / σ_gap`）。したがって PJ000001 §4 C-3 が低事前確率とした「価格由来の特徴量から方向を予測する」族に属する。**
- **日本株で結論が変わりうる理由**（CLAUDE.md の要求に対する明示。**有望さの主張ではなく「同型でも結論が変わりうる」理由の提示にとどまる**）:
  1. **板寄せ（itayose）による単一清算価格での寄付**は日本株固有の制度であり、価格発見が寄付の一点に集中する。
  2. **値幅制限**が1日の価格移動を制度的に打ち切るため、ストレス時の過剰反応が翌日以降に持ち越される構造がある。
  3. **信用の委託保証金率・追証**が個人投資家の投げ売りを寄付に集中させる。
  - **これら3点はいずれも trading-app-v2 の8連敗（暗号資産・24時間連続取引・値幅制限なし・板寄せなし）には存在しない構造である。**
- **事前確率は低いままである。** 上記は「族の事前確率を中に引き上げる」根拠ではない。

### 1.2 本EXPが賭けているものの正体（**忘れないこと**）

**「市場ストレス時の売り需給の偏りが数営業日かけて解消する」ことに賭けている。** 賭けの対象そのものが市場共通因子であるため、**イベントが市場ストレス日に集中するのは設計の欠陥ではなく賭けの性質そのものである。** ただしそれは「その1日に何が起きたか以上のことを測っていない」危険と表裏であり、**§6.0 DS-7・§6.2 G1-7・§6.3-2 の三重で検査する**。

### 2.0 参照営業日カレンダー `T`（本 spec 全体で唯一の正本）

- **`T` := ユニバース候補全銘柄の `/equities/bars/daily` の観測日付の和集合を、契約範囲 `[2016-09-15, 2026-09-14]` で切り取り、昇順に並べた列。1始まりの添字。**

- **実測値（`00-prescreen.md` §B-1）**: `T[1] = 2016-09-15`、`N = 2,441`、`T[N] = 2026-09-14`、`m = 1,220`、`T[m] = 2021-09-15`。

#### 2.0.1 契約範囲のピン留め（**第2版で追加。訂正であって基準の変更ではない**）

**`research/EXP-OBS000005/01-spec.md` §2.0.1 と<u>完全に同一の措置</u>を適用する。** 要点のみ再掲する（論証の全文は同節を参照）。

**発見された事実**: `/equities/bars/daily`（`code` 指定のみ）は**クエリ実行日から遡る約10年のローリング窓**を返す。前セッション取得の旧511銘柄は `2016-09-15〜2026-09-14`、§9-1 で本日追加した90銘柄は `2016-09-16〜2026-09-15`（1日前進）。**本日 `2016-09-15` を明示指定すると HTTP 400 で恒久的に取得不能。** 切り取りを行わずに統合すると `N = 2,442` / `m = 1,221` / `D_conf = 2021-09-17` となり事前登録値と1日ずれる。

**採る措置**: 範囲 `[2016-09-15, 2026-09-14]` で切り取る。

**HARKing（K-4）に当たらない理由**:

1. **この範囲は新しく選んだ値ではない。** `00-prescreen.md` §A-1 が、件数測定を1回も行っていない時点（コミット `b5080ee`）で既に「範囲: **2016-09-15 〜 2026-09-14**」と宣言していた。第2版はそれを `T` の定義側へ書き写しただけである。
2. **分割規則 `m = floor(N/2)` も `z*` 較正手続き（§3.6）も変更していない。**
3. **ピン留め後の和集合は `N = 2,441` / `T[1] = 2016-09-15` / `T[N] = 2026-09-14` / `m = 1,220` で、事前登録値と1日も違わない**（S が全キャッシュを実測して確認）。**「ゲートを通すために分割を動かした」という外形が成立しない。**
4. `research/ACTIVE.md` 0-20（EXP-OBS000001 §7 D項のエンドポイント誤りの訂正）と同じ類型である。

**却下した代替案**: ①**全件再取得**は、既存キャッシュを上書きして `2016-09-15` を恒久的に失う**破壊的操作**であり、かつ「実行日を変えれば分割が変わる」自由度を持ち込み、定義の時間依存性も解消しない。②**新規90銘柄の除外**は §9-1 のサバイバーシップ・バイアス是正を無効化する。

**残る非対称性と、それが無害である理由**: 新規取得銘柄（89銘柄）は `T[1] = 2016-09-15` の行を持たない（相異なるのは**この1日のみ**）。**`T[1]` は U-4 の助走窓 `T[1]〜T[60]` の内部にあり、本EXPのイベント日の範囲（`T[68]` 以降）より前であるため、イベントは1件も失われない。** `σ_gap` についても、影響を受けうるのは `i = 68`（窓 `T[2]〜T[67]`）の1点のみで、その銘柄が失う有効ギャップは `g(T[2])` の1本だけである（**60本の要件は満たされる**）。影響は U-4 の `Va` 標本が 60個 → 59個 になることに帰着し、**§5 U-4 の既存規則「有効 `Va` が30個未満なら不通過」で決定的に処理される。新しい閾値を導入しない。** §9-9 で銘柄ごとに開示する。

## 3. シグナル定義

**`research/EXP-OBS000003/01-spec.md` §3.1〜§3.5 / §3.7 を一字一句そのまま適用する。** 以下は再掲であり、**原本との差異があれば原本が優先する**（差異を発見した場合は S に報告すること）。

### 3.1 使用する価格（調整の規約）

- ギャップ・`σ_gap`・前方リターン・損益のすべてで**同一の調整規約で揃えた価格系列**を使う。**生値と調整値を混在させてはならない。**
- **株式分割・併合を跨ぐ日の生値ギャップは株価水準の人為的な段差であり、これを「下方ギャップ」と誤認するとシグナルの最極端側が分割イベントで埋まる。本EXPを構造的に破壊する。**
- **B実装チームは §9-2 として `AdjFactor` / `ExRT` / `Adj*` 系フィールドの正式名称・全ユニーク値・件数・調整の累積規約を実測し `params.json` に明記する。意味が一意に決まらなければ推測で埋めず S に差し戻す**（N-8）。

### 3.1.1 権利落ち・配当落ちの識別（E-1 / E-2A / E-2B）

**旧 spec §3.1.1 の5段階手続きをそのまま適用する。** 検証ゲート **V-1〜V-5**（旧 spec §9-2b）を**全合格させるまで G1 に進まない**（K-6）。

- **E-2B（暦ベース一括）**: 各暦月の最終営業日の1営業日前 `X(m)` を**全銘柄共通**で除外する。`X(m)` は `T` と暦のみから決まり、**価格を参照しない**。

#### 3.1.2 E-1（権利落ち日＝分割・併合）の判定条件（**第3版で確定。実装の欠陥の訂正であって基準の変更ではない**）

**発見された事実（B実装チームの §9-2 実測 ＋ S の独立検証）**: 554銘柄・10年分のデータで、**`ExRT = '2'` という値が初めて観測された**（旧 EXP-OBS000003 が使った511銘柄・2年分のデータには**0件**）。既存の共有関数 `gap_common.is_split_merger_row()` は **`ExRT == '1'` のみ**を権利落ちとして扱っており、この値を捕捉しない。

**S が全601キャッシュを独立に実測した結果（推測ではなく識別）**:

| 検証項目 | 実測 |
|---|---|
| `AdjFactor ≠ 1` の行の `ExRT` 分布 | **`'1'` が282件・`'2'` が105件。`ExRT` が null の行は1件も無い**（完全な分割） |
| `ExRT='1'` の `AdjFactor` | **すべて 1未満**（0.5 / 1/3 / 0.2 / 0.25 / 0.1 …）＝ **株式分割** |
| `ExRT='2'` の `AdjFactor` | **すべて 1より大きい整数**（5.0×45件 / 10.0×39件 / 2.0×21件） |
| 生値の価格比 `C(t)/C(t−1)` ÷ `AdjFactor` | **105/105 件で ≒1.0**（中央値 0.988・p10 0.965・p90 1.010） |
| **`MktCap(t) / MktCap(t−1)`** | **105/105 件で ≒1.0**（中央値 0.988）＝ **時価総額が連続** |

> **価格が `AdjFactor` 倍に跳ね、同時に時価総額が連続である ⇒ 発行済株式数が `1/AdjFactor` に減少した ⇒ `ExRT='2'` は<u>株式併合（リバーススプリット）</u>である。** これは3つの相互に独立な内部量が105/105で一致した**識別**であり、公式定義文書を参照せずとも一意に決まる。
> **日本株の市場構造とも完全に整合する**: 発生日は 2016-09-28 / 2017-09-27（65件）/ 2018-03-28 / 2018-09-26 に集中し、**東証の売買単位100株統一（2018年10月完了）に伴う単元株数変更＋株式併合の波**そのものである。`AdjFactor` が 5 と 10 に偏る（84/105件）ことも、1,000株単位から100株単位への移行で投資単位を維持するための併合比率として整合する。

**確定する判定条件（`is_split_merger_row()` の仕様）**:

```
is_split_merger_row(row) := (row.AdjFactor is not None) and (abs(row.AdjFactor − 1.0) > 1e-9)
```

- **`ExRT` の値を列挙する方式（`ExRT=='1'`、あるいは `ExRT in {'1','2'}`）を採らない。** 理由: **本件は未知のフィールド値が後から現れた2度目の事例であり**（1度目は §2.0.1 のローリング窓）、列挙方式は将来 `'3'` 等が現れたときに**エラーを出さず静かに取りこぼす**。上表のとおり `AdjFactor ≠ 1` は `ExRT ∈ {'1','2'}` と実測上**完全に一致**しており、かつ **E-1 が中和しようとしている当の機構（価格系列の人為的な段差）を直接指している**。
- **`AdjFactor` が null かつ `ExRT` も null** → 通常行。**`AdjFactor` が null だが `ExRT` が非null**（またはその逆）→ **実験を回さず S に差し戻す**（K-6。推測で埋めない）。

**なぜこれが HARKing（K-4）に当たらないか**:

1. **§3.4 E-1 が凍結している規則は「権利落ち日を除外する」であって「`ExRT=='1'` の行を除外する」ではない。** `ExRT=='1'` のみを見る実装は、**凍結済みの規則を取りこぼしていた実装上の欠陥**である。第3版はその欠陥を直して規則に適合させるものであり、**規則そのものは1文字も変えていない。**
2. **修正の方向はリターンではなくフィールドの意味だけで決まっている。** 「結果が良くなる方」を選ぶ余地が構造的に存在しない。
3. **本EXPは §9-2 で停止しており、前方リターンを一度も参照していない。**
4. **`00-prescreen.md` §A-7 L-3 が、prescreen の件数は E-1 / E-2A を適用しない代理測定であり、B が正規実装で DS ゲートと `z*` を再評価すると<u>事前に宣言している</u>。** 本件はその宣言どおりの経路であって、想定外の事後変更ではない。

**この欠陥が無害でない理由（なぜ直さなければならないか）**:

- 併合日の対数ギャップは `+ln(AdjFactor)` ＝ **最大 +2.30**（`AdjFactor=10`）。イベント候補としては E-6（`g ≥ 0`）が弾くが、**E-6 は `σ_gap` の窓には適用されない**（§3.4 の注）。
- したがって捕捉漏れの併合日は **`σ_gap` の60本窓に +1.61〜+2.30 の外れ値として混入する**。通常の日次ギャップの `σ` が 0.015 程度であることを踏まえると、**`σ` は一桁以上膨張し、`z` が同率だけ圧縮される**。
- 結果として **当該銘柄は併合後60営業日にわたりイベント集合から事実上排除される。** 旧 spec が配当落ちについて実測した汚染機構（`σ` の p99 で27%膨張）と同型で、**規模はそれよりはるかに大きい。**
- **ギャップは比であるため、調整系列の段差が壊すのは<u>その1観測だけ</u>である。** したがって E-1 で当日を除外すれば（イベント候補側・`σ_gap` 窓側の双方）**完全に解消する**。B が報告した「31/100件で `prev_AdjC == prev_C`（調整が遡及していない）」というデータ品質の問題も、同じ1観測の除外で閉じる。
- **影響は選定期間に偏在する**（S の実測: 選定期間87件 / 確認期間2件 / 範囲外16件）。**すなわち本修正は `z*` の較正値を動かしうる。** これは §9-6 で再較正することが**既に事前登録されている**（`00-prescreen.md` §C-5 条件3）。**再較正の結果 DS ゲートを1つでも外した場合は K-5（保留）であり、それを救うためにいかなる値も動かしてはならない。**

### 3.5 PEAD（EXP-OBS000005）との事象排反性

- EXP-OBS000005 のイベントは `(j, DiscDate)`、エントリー日は `DiscDate` の翌営業日。
- 本EXPは E-3 により `DiscDate ∈ [D−2, D+2]` なる銘柄日をすべて除外している。
- 仮に本EXPの `D` が PEAD のエントリー日と一致すれば `DiscDate = D−1 ∈ [D−2, D+2]` であり E-3 で除外されている。**矛盾。** PEAD のイベント日そのもの（`D = DiscDate`）も同様。
- **∴ 両EXPのイベント集合・エントリー日集合は排反である。** B実装チームは E-3 の除外件数を**銘柄日ベースと `DiscDate` ベースの両方**で出力し、実データ上で確認する（§9-7）。

### 3.6 イベント閾値 `z*` の較正（**カウントのみを入力とする決定的手続き**）

1. 探索グリッドを**事前に固定する**: **`z* ∈ {−1.50, −1.75, …, −8.00}`（0.25刻み・27点）**。**グリッドの追加・細分化・再拡張を禁止する**（N-9）。
2. **選定期間のみ**について、各グリッド点の**候補イベント件数**（C-1〜C-4 と E-1〜E-6 をすべて適用後）を数える。
3. **年換算件数を、`T` の添字から一意に再計算できる式で定義する**（旧 spec §3.6 の曖昧さの修復）:

```
n_sel_eff  := #{ i | 68  ≤ i ≤ m − 11 かつ T[i] が E-2B の一括除外日でない }
n_conf_eff := #{ i | m+1 ≤ i ≤ N − 11 かつ T[i] が E-2B の一括除外日でない }
N_ann(z*)  := (選定期間の候補イベント件数) × 245 ÷ n_sel_eff
```

- **年換算定数は 245 のみを使う。**
- **`n_sel_eff` / `n_conf_eff` を必ず `params.json` に出力すること。**
- prescreen 実測値: `n_sel_eff = 1,085`、`n_conf_eff = 1,150`。

4. **`z*` = `|N_ann(z*) − 215|` を最小にするグリッド点。** 同値の場合は**より極端側（より負）**を採る。
5. `z*` を**凍結**する。確認期間・パイプライン・感度分析のすべてで同じ `z*` を使う。
6. **この手続きに前方リターンは一切入らない。入力は銘柄日の件数のみである。**

#### 3.6.1 グリッド範囲の拡張が作動しなかったことの記録（**HARKing 防御の観点から必ず残す**）

`00-prescreen.md` §B-4 の実測では、**選ばれた `z* = −3.50` も、`[150,300]` に入った4点（−3.00 / −3.25 / −3.50 / −3.75）も、すべて旧 EXP-OBS000003 の11点グリッド（`−1.50`〜`−4.00`）の内側にある。** 拡張された `−4.25` 〜 `−8.00` の16点は**1点も使われなかった**。

> **すなわち、旧EXPの DS-2a 不合格を修復したのはグリッドの拡張ではなく、選定期間が5年に延びたことである。本EXPで登録した唯一の「疑われうる自由度」は、実測において作動しなかった。**

### 3.7 「非決算」の定義の限界（**安全側だと扱わない**）

## 4. 約定モデル

**`research/EXP-OBS000003/01-spec.md` §4.0〜§4.5 をそのまま適用する。** 要点の再掲:

### 4.1 値幅制限フラグの解釈（**唯一の判定式**）

```
BUY_BLOCKED(t)  = (Vo(t)==0) or (O(t) is null) or (UL(t)==1 and O(t)==H(t))
SELL_BLOCKED(t) = (Vo(t)==0) or (O(t) is null) or (LL(t)==1 and O(t)==L(t))
```

- **JPX 制限値幅表からの上限/下限価格の自前再構成は禁止。**

### 4.2 エントリー（**先読みを構造的に排除する**）

- **`t_1 = T[i+1]` の始値 `O(t_1)`** に固定する。**イベント日 `D` の寄付では建てない**（`z` は `D` の始値が確定して初めて計算でき、その時点で `D` の寄付には間に合わないため）。
- `BUY_BLOCKED(t_1)` が真なら見送り（**E-7**）。加えて本EXP固有の追加除外: **`LL(t_1)=1 かつ O(t_1)=L(t_1)` なら見送り（E-8）**。
- 約定価格 = `O(t_1) × (1 + スリッページ片道)`。

### 4.3 予測単位（G1）の前方リターン

- **`R_5 = C(T[i+5]) / O(T[i+1]) − 1`**（グロス）。

### 6.1 G1 主検定

#### 6.1.2 主指標: イベント日内クロスセクション Spearman 順位相関の等加重平均（`IC_bar`）
