## 環境上の重大な発見（次セッションが同じ轍を踏まないために）

**リモート実行コンテナとユーザーのローカルWindows環境は別物であり、`.env.local` は共有されない。** 前セッションのJ-Quants実測がどの環境で行われたにせよ、**このリモートコンテナは毎回クリーンな状態で新規作成される**ため、APIキーを使うには毎回（またはコンテナが生きている間は継続して）環境変数として明示的に注入されている必要がある。

- **J-Quants API**（クラウドAPI）→ **リモート化可能**。ユーザーが `claude.ai/code` の当該Environmentの Settings → Environment Variables に `JQUANTS_API_KEY` を登録すれば、**新しいセッション（コンテナ）から**利用できる。**登録しただけでは稼働中の既存セッションには反映されない**（環境変数はコンテナ起動時にのみ注入されるため）。本セッション終了時点で、ユーザーは登録済みだが未確認（新セッションでの確認待ち）。
- **kabu STATION API**（発注実行系）→ **リモート化不可**。ユーザーのWindows常駐アプリ（`localhost:18081`）にしか疎通しない設計上の制約（H-2）。これは今後も恒久的にローカル操作が必要。

1. J-Quants API の V1 が2026-06-01に廃止 → V2（APIキー方式、`x-api-key`ヘッダー）に全面書き直し済み

3. J-Quants APIのレート制限（429）が厳しい。「間隔5秒・429時は10秒待って最大3回リトライ」に落ち着いた（`scripts/step0_api_probe.py`冒頭の定数群、`scripts/lib/jquants_client.py`が再利用）。フル実行で特定項目だけ429に阻まれ続ける場合は単体スクリプトへの切り出しが有効（`scripts/check_master_schema.py`の前例）
4. kabu STATION疎通も単体スクリプト化: `scripts/check_kabu_station.py`
5. 先読み不具合の予防策（trading-app-v2 EXP-OBS000037の教訓）を`.claude/agents/*.md`と`portfolio-ledger.md`に反映済み。時系列ウィンドウは「本数」と「対象範囲」の算術的対応を必ず明記すること
