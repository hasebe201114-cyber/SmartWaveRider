## 本セッションで発生した技術的トラブルと対応（次セッションが同じ轍を踏まないために）

1. **J-Quants API の V1 が2026-06-01に廃止されていた**ことに気づかず、旧版スクリプトが常に403で失敗していた。→ V2（APIキー方式、`x-api-key`ヘッダー）に全面書き直し済み
2. **HTTP 200でも中身が空リストのことがある**（`has_real_data()`ヘルパーで対処済み）。ステータスコードだけで成功判定してはいけない
3. **J-Quants APIのレート制限（429）が想定より厳しい**。速度優先の設定（間隔短縮・リトライ削減）は結果が虫食いになる失敗を繰り返した。最終的に**「間隔5秒・429時は10秒待って最大3回リトライ・実行時間30分を許容」**という確実性優先の設定に落ち着いた（`scripts/step0_api_probe.py` 冒頭の定数群）。**それでも `/equities/master`（§6）だけはフル実行の中では毎回429に阻まれ続けた**ため、単体で叩く軽量スクリプト `scripts/check_master_schema.py` を新設し、これが功を奏してR-1cを解消できた。**「フル実行で特定の項目だけ通らない」場合は、単体スクリプトに切り出すのが有効な打ち手**
4. **kabu STATION疎通も同様の理由で単体スクリプト化**: `scripts/check_kabu_station.py`（J-Quantsの実測を待たずに数秒で確認可能）
5. **先読み不具合の予防策を横展開済み**: 姉妹プロジェクト trading-app-v2 の EXP-OBS000037（specの窓長定義の算術矛盾がB実装の独自解釈を招いた事例）を調査し、`.claude/agents/chief-strategist.md`・`quant-researcher.md`・`adversarial-reviewer.md` の3体と `portfolio-ledger.md` に恒久ルールとして反映済み。時系列ウィンドウを定義する際は「本数」と「対象範囲」の算術的対応を必ず明記すること
